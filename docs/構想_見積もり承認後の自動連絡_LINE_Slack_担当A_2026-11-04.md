# 構想: 見積もり承認後の自動連絡（LINE または Slack）

2026-11-04 社長の要望。**今すぐは作らない。将来の構想として保管**（連携先がLINE/Slackで未確定。賃金同期・入社通知のLINE返信登録の計画 と同じ土台で作る想定）。

## 目指す流れ
1. 見積もりが届く → 本部タスク（最重要）が自動で立つ【実装済】
2. 本部が会社を決める → **申請者に通知**（「○○に決まりました。工事はいつ頃できそうですか？」）
3. 申請者が**工事日を返信/選択**（LINEならボタン・日付選択、Slackならボタン）→ **タスクの工程「修繕日の確定」が完了し、タスクの期限が工事日に変わる**
4. 工事が終わったら申請者が**完了写真を送る** → 工程「修繕完了」が自動で完了 → **支払い担当（原 美香）へ自動通知**「支払いをお願いします（会社名・金額・見積書）」
5. 支払い担当が「支払い済み」を返す → 工程「支払い完了」が自動で完了 → タスク完了

## 作る時に決めること
- 連絡手段: LINE か Slack か（既存の line-webhook・Slack通知の土台を使う）。従業員とLINE/Slackアカウントの紐づけが前提
- 申請者・支払い担当へ届く「返信の受け口」（Edge Function）と、会話の状態（どの見積もりの何待ちか）の保存
- 期限内に返信がない時の催促（保留と同様に未読を残す）
- 既存の実装: 見積もり表 quote_requests/quote_options、RPC quote_decide、本部タスク4工程（procedure_note = quote:select/date/done/pay）。工程の完了・期限更新はこの目印で特定できる

## 推奨プラン（担当A）
**結論: 第1弾は「申請者への連絡＝LINE」、「支払い担当への連絡＝今ある個人Chatwork通知」。窓口は1か所にまとめ、将来Slackへ差し替え可能にする。**

| 観点 | LINE | Slack |
|---|---|---|
| 現場の人に届くか | 在籍142人中102人がLINE連携済み（約72%）。追加の準備ほぼ不要 | 全員の参加と使い方の定着が先（運用判断が必要） |
| 工事日の返信 | 日付選択ボタン・写真送信がそのまま使える（スマホで1タップ） | ボタン・ファイル送信は可能だが、現場スタッフには不慣れ |
| 実装の土台 | line-webhook・LINE連携コードが稼働中 | notify-slack は設計済みだが未デプロイ（疎通テスト待ち） |
| 将来の統一 | 後でSlackへ移す時は送り先を差し替えるだけにしておく | 全員がSlackに入った時点で本命 |

**段階**
1. 第1弾（LINE）: 会社決定→申請者へ「工事はいつ頃？」＋日付ボタン→選ぶと工程「修繕日の確定」完了・タスク期限が更新。工事後に写真を送ると工程「修繕完了」完了。
2. 支払い通知: 完了と同時に原 美香へ（既存の個人Chatwork通知。無ければアプリ内通知）「支払いをお願いします（会社名・金額・見積書）」。「支払い済み」で最後の工程が完了。
3. 通知の窓口を1つの関数にまとめ、宛先の種類（LINE/Slack/Chatwork）を設定で切り替えられる形にする（賃金同期・入社通知の計画と共通）。
4. 全員のSlack定着後に、送り先をSlackへ切り替える。

**懸念**: LINE未連携の約40人は通知が届かない → 未連携者はアプリ内通知＋本部への通知にフォールバック。LINEの月間無料通数の上限（line-quota-check で監視中）に注意。
