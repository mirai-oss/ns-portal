## 7. 補足の技術メモ（ハマりやすい点）

- **ns-info-systemはNext.js 16**。`middleware.ts`は非推奨になり`proxy.ts`（`export function proxy`）に名称変更されている。公式codemod `npx @next/codemod@canary middleware-to-proxy .` で安全に移行できる。新規のNext.jsコード変更をする前に`node_modules/next/dist/docs/`配下の該当ガイドを確認すること（`AGENTS.md`に明記）
- **`info`スキーマの権限モデル**: `profiles`（本人の役職・法人アクセス）→`roles`（本部/部長/店長/一般スタッフの4種）→`role_permissions`（役職×カテゴリ×none/view/edit）→`categories`（corp_info/store_info/property/bank/loan/supplier/id_pw/ad_media/employee/utility/real_estate/photosの12種＋salaryは設定UI対象外でマスター限定のまま）。個人単位の上書きは`user_permissions`・`user_corporations`。読み取り可否は`info.has_perm(cat)`、編集可否は`info.has_edit_perm(cat)`（今回新設）で判定。クライアント側は独自にロジックを再実装せず、`supabase.rpc("has_edit_perm",{cat})`を直接呼ぶ設計にしてある（`src/lib/permissions.ts`）
- **Vercelの「Use existing Build Cache」チェックに注意**: 環境変数を変更してRedeployしても、このチェックが入っていると古いビルド（＝古い環境変数が埋め込まれたJS）がそのまま配信され続ける。環境変数を変えた直後のRedeployは必ずこのチェックを外すよう案内する
- **Vercelの実際の切替確認は、ログイン情報なしでもできる**: 配信中のJSチャンクをcurlで取得し、埋め込まれたSupabaseプロジェクト参照文字列（`grep -o "[a-z0-9]\{20\}\.supabase\.co"`）やデプロイID（`grep -oE 'dpl_[a-zA-Z0-9]+'`）を見れば、実際にどちらのDB・どのビルドを向いているか外部から確認できる
- **法人マスタ**: `public.corporations`は4件（LiveGate/SK/N-Style/トーホー、corp_code列で識別）。店舗09〜12（じんべぇ川崎・じんべぇ新横浜・エース本厚木・秋葉原肉寿司）はcorporation_id未設定のまま＝経費申請ではN-Style（本社）にフォールバックする設計
- **経費申請の科目マスタ**: 交通費/消耗品費/会議費/通信費/その他/修繕費の6件（ユーザーが管理画面から追加済み）
