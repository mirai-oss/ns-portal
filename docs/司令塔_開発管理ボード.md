# 司令塔 開発管理ボード（開発の「今」はここだけ見れば分かる）

管理: 司令塔（設計スレッド）。各担当は**自分の行だけ**を 1 行で更新する（区切りがついた時・止まった時）。長い説明は書かない（詳しくは WORKLOG・各設計書へ）。秘密の値・氏名つきの金額・Slack の ID は書かない。

## 運用ルール（2026-11-16 社長決定）

1. **役割**: 司令塔＝複雑な設計・技術判断・全体の管理（Fable）。実装担当＝通常の開発・修正・テスト・デプロイ（Sonnet が標準）。司令塔は実装担当とは別枠。
2. **1 件ずつ**: 実装担当は原則 1 エージェントずつ稼働し、1 つの機能を**本番稼働まで**完成させてから次へ。例外は重大なセキュリティ問題・緊急障害だけ。（11/16 時点で進行中の担当B・D は完了まで続けてよい）
3. **質問は各担当から社長へ直接でよい（11/16 午後に変更）**: 司令塔を毎回経由すると費用がかさむため、各担当が社長に直接聞いて答えをもらう。かわりに、担当は社長とやり取りするたびに「回答待ちの質問」と「残タスク」を毎回短く書く。司令塔は、社長と話すたびに担当ごとの回答忘れ・残タスクをまとめて伝える。複雑な設計判断・担当をまたぐ話は司令塔へ。社長の承認が要るもの（重要な仕様変更・本番の実データの変更・外部送信・スマレジへの書き込み・銀行操作・スイッチ ON）は、これまでどおり必ず社長本人の承認を取る。
4. **本人の操作が要るもの**（ツールの許可ダイアログ・GAS への貼り付け・認証メール・銀行にログインするジョブ）は代行しない。司令塔が「どの画面で・何を押すか」を案内する。
5. **放置しない**: 担当は、区切りがついた時・止まった時に、下の表の自分の行を更新し、司令塔へ 1 通送る（止まった理由と、だれの何を待っているかを必ず書く）。司令塔は、社長とやり取りするたびにこの表を見て、止まっている物を動かす。
6. **費用を抑える**: 不要な並列起動をしない／同じ調査をくり返さない／既存のコード・ログ・引継ぎ書を使い回す／長い報告・不要なテストを省く。**安全確認は省かない**（構文チェック・認証と権限・スマレジ誤更新の防止・給与と賃金の削除や上書きの防止・銀行の振込操作の禁止・既存機能を壊さない確認）。
7. **PC の分担**: Mac mini＝Playwright が要るもの（WEB総振など銀行の読み取り）だけ。**勤怠修正申請・固定残業代・採用・入社登録は MacBook 側**（Mac mini では着手しない）。
8. **ぶつからない決まり**: 共有フォルダで pull／stash しない・自分用の worktree・STEP の始め／commit の前／デプロイ直前に git fetch と git log で確認。
9. **数えるもの**: 同時に何件開発しているかではなく、**本番稼働まで完了した機能の数**。
