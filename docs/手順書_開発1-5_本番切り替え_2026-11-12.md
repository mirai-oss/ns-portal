## 0. 先に知っておくこと

- SQL・Edge Function・画面を入れただけでは、**何も変わりません**。変わるのは、下の 2 つのスイッチを入れたときです。スイッチは、それぞれ別に承認をいただいてから入れます。
  - スイッチ A: #本部-人事 に金額を出さない（`slack_policy.hide_amount_channels`）。

- 賃金 2 段階承認のスイッチ①②には触りません（OFF のまま）。
- 既存の従業員・賃金・口座・申請のデータは変えません。
- Edge Function は 3 つ変えます（`notify-slack`・`onboarding-notify`・`smaregi-sync`）。どれも稼働中なので、デプロイの前に、本番のソースを取り出して「今回の変更以外に差が無いこと」を確かめます。

## 2. スイッチ A: #本部-人事 に金額を出さない（★本番の有効化は別途承認）

**テストは済みました（2026-11-11 15:59〜16:00。結果は「6.3」）。** 宛先は社長あての DM にしました（テスト用のチャンネルが無く、チャンネルの作成・変更は別途承認のため。ほかの人には見えません）。

本番で有効にするとき（承認のあと）:

1. `hq.jinji` をスイッチ A に入れる。実行する SQL（実行の前にもう一度提示します）:
   `update app_settings set value = jsonb_set(value, '{hide_amount_channels}', '["hq.jinji"]'::jsonb) where key = 'slack_policy';`
2. テスト従業員の入社登録の親メッセージで「🔄 表示を更新」を押す。賃金の行が「賃金設定済み」になり、金額が消える。
3. 1 日ぶん、#本部-人事 の新しいメッセージと、送信の記録（止めた通知が無いか）を見る。

成功の見分け方: #本部-人事 の新しいメッセージに、¥ や「○○円」が 1 つも出ない。日付・店舗・氏名・状況・ボタンはこれまでどおり出る。

守りは 3 段です。

| 段 | どこで | 何をする |
|---|---|---|
| 1 | 文面を作るところ（入社登録の通知） | 金額の項目そのものを数字にしない（項目の単位）。親メッセージは「賃金設定済み」「交通費確認待ち」など状況だけ |
| 2 | Slack への出口 | 「¥ が前に付く数字」「円 が後ろに付く数字」だけを置き換える。日付・時刻・件数・番号は消さない |
| 3 | Slack への出口（消したあと） | 金額らしいものが残っていたら、その通知は**送らない**。送るはずだった場所に「1 件止めました」とだけ出し、#本部-開発システム に場所の名前つきで知らせる（金額は書かない）。同じ知らせは 1 時間に 1 回まで |

戻し方: スイッチ A の一覧を空に戻す（すぐ戻る）。
`update app_settings set value = jsonb_set(value, '{hide_amount_channels}', '[]'::jsonb) where key = 'slack_policy';`

そのあと（別途）: 過去のテスト従業員のメッセージを消すか決める → チャンネルの公開設定と参加者を確認 → チーム長の参加。

## 3. スイッチ B: スマレジにだけある賃金の行を正式登録しない（★別途承認。今回は入れていない）

**試し読みは済みました（2026-11-11 16:00 ごろ。結果は「6.4」）。** いま入れると、9 人・10 行が保留になります。初期登録として自動で入る行は 0 です。

入れるとき（承認のあと）:

1. **保留になる 10 行をどうするか決める**（本部の確認）。
   - ア: いまのスマレジの内容を出発点として、これまでどおりの取り込みで正式に取り込む（nippo の「スマレジの賃金を管理システムへ取り込む」を 1 回）。
   - イ: 取り込まず、スイッチを入れて保留にし、1 件ずつ確認する。
2. スイッチ B を true にする（SQL は実行の前に提示します）。
3. もう一度、一括取り込みを実行する。アなら「未承認の変更として保留: 0 件」、イなら 10 件。

初期登録として自動で取り込む人（スイッチを入れたあと）: 次の**全部**を満たす人だけ。「スマレジ連携から 14 日以内」だけでは取り込みません。

| 見るもの | 条件 |
|---|---|
| 入社手続きの状態 | 入社登録が進行中、または完了から 14 日以内（取り消し・入社登録なしは不可） |
| 賃金の履歴 | 管理システムに賃金が 1 件も無い（別の法人に賃金がある人＝異動は不可） |
| 承認の状態 | 承認待ちの賃金変更の申請が無い・保留中の控えが無い |
| 連携の履歴 | 終了したスマレジ連携が無い（再連携・異動は不可）・入社登録より 14 日以上前からの連携が無い |

戻し方: スイッチ B を false に戻す。**戻しても、保留中の行は正式な賃金になりません。**

| もの | false に戻したあと |
|---|---|
| 保留中の控えがある人 | 保留のまま。その人の新しい行も保留になる。控えは勝手に閉じない |
| 控えが無い人 | これまでどおり（スマレジにだけある行は取り込まれる） |
| 保留を終わらせる方法 | 同じ内容を管理システムで正式に登録する、またはスマレジ側を戻す → 次の照合で「一致」として閉じる |
| 控えの表ごと外すとき | 未解決の控えが残っていると、外す SQL は止まる（先に解決する） |
