| 困りごと | こうなる |

# v3 追補（2026-11-10）: リマインドの安全対策と「社内期限／法定期限」の分離　★ 本番未適用

SQL: `supabase/2026-11-10_post_join_remind_scope.sql`（切り戻し `..._rollback.sql`）。EF: `onboarding-notify` の op `post_join_remind`。本番への適用・デプロイは承認後。

## 1. なぜ直すのか

v2 のままリマインドを有効にすると、**いま在籍している社員の全員**が「必須なのに未提出」として通知の候補になります（dry-run で 19 人）。入社したばかりの人に送るつもりの通知が、既存の人へ一斉に飛んでしまいます。

## 2. だれに送るか（①）

送る条件は、これまでの条件（必須・リマインド有効・未提出・間隔）に、次のどちらかを足します。

| 区分 | 判定 | 送る？ |
|---|---|---|
| 新規入社者 | 入社登録ワークフローがあり、その作成日が基準日（`onboarding_alerts.post_join_new_hire_from`＝既定 2026-11-09）以降 | 送る |
| 既存従業員・対象リストに入っている | 本部が「対象リスト」に登録し、**マスターか社長が承認**したリストのメンバー | 送る |
| 既存従業員・対象リストに無い | 上のどちらでもない | **送らない**（未提出というだけでは通知しない） |

- 対象リスト: `post_join_remind_batches`（名前・トラック・年度・状態 下書き→承認→取り消し）と `post_join_remind_members`（メンバー）。
- グループ指定（雇用区分・店舗）は**登録した時点のメンバーに展開**します。あとから条件に合うようになった人は自動では増えません。
- 登録は本部（`post_join_remind_batch_create`）、承認はマスター・社長だけ（`post_join_remind_batch_approve`）。取り消し・1 人だけ外すこともできます。すべて履歴（`post_join_policy_history` の `remind_batch_*`）に残ります。
- 任意のアルバイトは、対象リストに入れても候補になりません（必須ではないため）。個別に必須へ変えた人だけ対象になります。社員・アルバイトの必須／任意と個別上書きは今までどおりです。

## 3. 一度に大量に送らない仕組み

- `onboarding_alerts.post_join_max_per_run`（既定 10 人）。1 回の送信対象がこれを超えたら**誰にも送らず**、#本部-人事 に「上限を超えたので止めました」とだけ出します。
- 上限と基準日の変更は `post_join_remind_settings_set`（マスター・社長のみ・理由必須）。**有効化フラグ `post_join_remind_enabled` はこの関数では変えられません**（承認のうえ別途）。
- 安全装置の関数が見つからないときは送らない（fail closed）。

## 4. 有効化の前に確認する画面（dry-run）

`onboarding_post_join_preview_summary()`（本部用 RPC。nippo の確認画面と EF の dry-run が同じものを返す）:

- 自動送信が ON か OFF か／上限／上限を超えているか
- **今回送る人**（氏名・区分・店舗・入社日・理由（新規入社 or 対象リスト名）・送信に使う経路・トラックと期限・**その人に送る文面**）
- **送らない人**と理由（既存従業員（対象リスト未登録）／対象リストが未承認（下書き）／入社 3 日未満／間隔待ち（次回 ○/○）／リマインド無効）と内訳の人数

連絡先（メール・LINE の ID など）そのものは返しません。文面は DB 関数 `post_join_remind_text` の 1 か所だけで作ります。

## 5. 社内期限と法定期限（⑤）

| | 何に使うか | 決め方 |
|---|---|---|
| **社内期限**（`deadline`＝`internal_deadline`） | リマインド・必須の管理・画面の「期限」 | 扶養: 入社後最初の**月末**（給与の締め日。末日締め・翌月 15 日払い）。入社から 2 日未満なら次の月末。年末調整: 対象年度の 11/30。**本部が個別に変更できる**（`post_join_set_override` の deadline・理由必須） |
| **法定期限の目安**（`legal_deadline`） | 参考表示だけ（リマインドや必須判定には使わない） | 扶養: 最初の給与支払日の前日（例: 11 月入社 → 12/14）。年末調整: その年最後の給与支払日の前日（12/14）。祝日の前倒しは計算に入れていません |

- 表示は「必須・社内期限 11/30（法定の目安 12/14）」。法定期限についての注記（`legal_deadline_note`）は「正確な期限は税理士・所轄税務署に確認」と添えています。システムは法的な判断をしません。
- 「任意」の注記（`legal_note`: 任意は社内運用上の扱いで、税法上の義務を免除するものではない）は今までどおりです。
- 個別に期限を変えても、変わるのは社内期限だけです（法定期限の目安は変わりません）。
