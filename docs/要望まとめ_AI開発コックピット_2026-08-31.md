# Claude Code 実装指示書 — N-Style AI開発コックピット

## 目的
複数PC・複数Claude Codeセッション・人間の開発作業を、N-Style統合ポータル上で一元可視化・管理する。
単なるタスク管理ではなく、「誰が・どの端末で・どのリポジトリ/ブランチを・どのタスクで・どこまで進めているか」を確認し、その場から次の指示を出せる開発コックピットにする。

添付HTML `NStyle_AI開発コックピット_UI_v2.html` をUI基準として既存ポータルへ統合する。

## 必須機能
- 今進めている内容
- 残タスク
- これから進める内容
- 今後やる内容
- 優先順位
- AIがやるタスク
- 中山がやるタスク
- 担当別タスク
- 確認待ち / blocked / 完了
- 指示書作成
- 進捗率
- 複数PCでどの担当がどこを動かしているか
- 実行・変更履歴
- 他PCから見ても同じ状態

## 主要エンティティ
### devices
device_id, device_name, hostname, os, last_seen_at, status

### agent_sessions
session_id, device_id, agent_type, agent_name, repository, branch, current_task_id, status, progress_percent, started_at, last_heartbeat_at, current_file, blocker, git_head, changed_files_count

### development_tasks
task_id, title, description, priority, project, category, assignee_type, assignee_id, target_device_id, target_session_id, repository, branch, instruction_id, status, progress_percent, blocker, due_at, created_by, created_at, updated_at, completed_at

### instructions
instruction_id, task_id, title, markdown, target_agent, target_device, repository, branch, created_by, created_at

### execution_events
event_id, session_id, task_id, device_id, event_type, message, metadata_json, created_at

## タスク状態
backlog / ready / in_progress / review / waiting_human / blocked / done / cancelled

## セッション状態
running / waiting / blocked / idle / stopped / stale / disconnected

## Heartbeat
各稼働セッションから15〜30秒ごとにheartbeatを送信。
一定時間途切れたら stale、その後 disconnected に自動遷移。
ローカルPCの状態を正本にせず、Supabase上の共有状態を正本にする。

## Claude Code側の状態更新
CLI / hook / wrapper / MCP のいずれかで共通化する。

例:
```bash
ai-cockpit start --task TK-203
ai-cockpit progress --task TK-203 --percent 45 --message "PDF生成実装中"
ai-cockpit blocked --task TK-203 --message "OAuth権限不足"
ai-cockpit done --task TK-203 --message "実装・テスト完了"
```

## Git連携
表示:
- repository
- branch
- HEAD commit
- changed files
- uncommitted changes

警告:
- 同じbranchを複数端末が同時編集
- 同じファイルを複数sessionが変更
- migrationの同時変更
- mainへの直接編集
- 同一taskを複数agentが実行

## 人間承認
以下は自動実行せず waiting_human:
- DB破壊変更
- migration削除
- 本番データ更新
- API credential変更
- 課金処理
- 外部メール送信
- 本番deploy
- main merge

ダッシュボードから承認 / 却下できるようにする。

## データ保存
Supabase:
- devices
- agent_sessions
- development_tasks
- instructions
- execution_events
- approvals
- comments

BigQueryは大量ログの長期分析が必要になった段階で追加。最初から全ログを入れない。

## 実装Phase
