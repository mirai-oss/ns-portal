# 設計書ドラフト: ①請求書→広告費の自動反映／②精算書への勘定科目・補助科目追加→PL自動連携

作成: 2026-08-31（司令塔） ／ 状態: **設計ドラフト＝§3の質問回答後に確定・着手**
発端: 2026-08-31ユーザー要望（項目8）

## 1. ①請求書（メール）→広告費入力への自動反映

**要望**: MFに入力した請求書のうち食べログ・ぐるなび等の広告費を、広告費入力（広告費用対効果_管理シートの💾広告費DB）へ自動反映したい。請求書処理時に「何の広告か」を推定表示→選択すれば店舗×金額が自動連携。店舗別金額が請求書に無い場合はMF仕訳の部門（店舗）を参考にする。

### 実装案
1. **判定**: 請求書のOCR結果・送信元（例: tabelog.com／gnavi）・過去の処理履歴から「広告費らしさ」と媒体（食べログ/ぐるなび/ホットペッパー等）を推定し、`invoices.html`の処理画面に**「📢 広告費として反映」パネル**を表示（媒体・対象年月・店舗×金額の割り振り案を提示→人が確認・修正して確定。AI=下書き・人=承認の原則どおり）
2. **店舗×金額の割り振り**: 優先順= a)請求書明細に店舗別金額があればそれ b)無ければ同じ請求書で作ったMF仕訳の部門別金額 c)どちらも無ければ前月の同媒体の割り振り比率を提案
3. **書き込み先**: 広告費用対効果_管理シートの`💾広告費DB`（年月×店舗×媒体×金額）。書き込み経路は**経営ダッシュボードGASに書き込み用actionを追加**（GAS変更=担当A縄張り）し、invoices側のEdge Functionからそれを呼ぶ（invoicesから直接シートを触らない）。媒体名は既存の`tpl_media_alias`正規化を通す
4. **重複防止**: `invoices`に`ad_cost_synced_at`等の列を追加し、同じ請求書からの二重反映を防ぐ（MF仕訳の`mf_journal_id`と同型）
5. **担当分担**: invoices側UI・判定=担当C／GAS書き込みaction=担当A（Cから依頼）

## 2. ②精算書に勘定科目・補助科目を追加→店舗PLへ自動連携

**要望**: 精算書に入力している費用（電気料金・通信費等）は実際のPLに反映されるべきなので、精算書側に勘定科目・補助科目を付けて店舗PLへ自動連携したい。固定ロイヤリティ等はPL対象外なので「対象外」も選べるように。支払い（運営委託費）は今まで通りの自動連携を維持。

### 実装案
1. **精算システム（SeisanDashboard.gs）の明細入力に「勘定科目」「補助科目」列を追加**。科目リストはPL管理システムの科目マスタ（勘定科目・補助科目=A-1で整備済みの補助科目機構）と同じものを使う＋**「対象外」**選択肢（固定ロイヤリティ等・PLに送らない）
2. **既定値の自動提案**: 項目名からの推定（「電気」→水道光熱費 等）＋前月の同項目の科目を引き継ぎ（毎月選び直さなくてよい）
3. **PLへの連携**: 既存の`syncSeisanFeeToPl`（運営委託費の自動計上・毎朝）と同じパターンで、科目付きの明細を**店舗×年月×勘定科目×補助科目**でDB_PL（＋PL管理システム・stg_plミラー）へ`自動｜精算書`として計上する新関数を追加。**運営委託費の既存連携はそのまま**（二重計上にならないよう、新連携は「対象外」「運営委託費」以外の科目のみを送る）
4. **精算書UI刷新（A-7・別タスク）との関係**: UIの見た目刷新はモック（`docs/mockups/NStyle_統合ポータル_精算ダッシュボード_UI_v3_プレビューPDFメール対応.html`）準拠で先行。科目列の追加は本設計の確定後に「明細を入力」画面へ組み込む（同じ担当Aが順にやるのが安全）
5. **担当**: 精算GAS・PL連携とも**担当A**（GASデプロイ独占・PL連携の全実績あり）
