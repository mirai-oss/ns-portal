# 設計書: PL補助科目・スポット人件費・マネーフォワード試算表CSV取込

作成: 2026-08-23 ／ ユーザーヒアリング済み（4論点確定）／ 実装は未着手
対象読者: 実装スレッド。現行構造は `docs/売上ダッシュボード_データ設計仕様書_2026-08-23.md` §2 を先に読むこと。

**確定した前提（2026-08-23 ユーザー回答）**:
①スポット人件費は**日付単位**で入力（日別の人件費率・FL率に反映）
②マネーフォワード会計は**部門=店舗**で試算表を出せる（店舗別取込が可能）
③CSV取込で金額不一致の場合は**プレビューで1件ずつ「残す/上書き」を選ばせる**
④補助科目は**マスタ管理＋入力時のその場追加**

## 0. 現行データモデル（変更対象）

- `DB_PL`シート: 年月／店舗名／勘定科目／区分(S,F,L,R,A,O,X)／金額／メモ。店舗名空欄=全社共通
- 書込経路: ダッシュボードPLタブ（`savePlEntries`/`savePlBulk`）＋PL管理システム`✍販管費入力`（毎日8:00と10分おきの自動同期）＋自動行（`自動｜媒体販促費`・`自動｜法定福利費`・`自動｜通勤手当`・運営委託費）
- BQミラー: `sales.stg_pl`（PL書込時に`bqSyncPL`が自動追随・speed-v6で修正済み）
- 人件費: L01社員/L02PA は`分析_日別店舗`由来の自動値（DB_PLには入れない）

## 1. 補助科目（勘定科目の下の階層）

### データモデル（すべて追加のみ・既存を壊さない）

| 変更 | 内容 |
|---|---|
| `DB_PL`に7列目「補助科目」追加 | 既存行は空欄=補助科目なし。一意キーは**年月×店舗×勘定科目×補助科目** |
| 新シート`DB_補助科目`（マスタ） | 列: 勘定科目／補助科目／表示順／有効。GASが雛形自動生成（既存DB_系と同方式）。`getData`で配信 |
| `stg_pl`に`sub_item`列追加 | `bqSyncPL`・`bqGetPL`のSQLに列追加 |
| PL管理システム`✍販管費入力`にG列「補助科目」追加 | 自動同期（pl_dbpl_autosync）の転記範囲をG列まで拡張 |

※科目マスタ（60科目・行番号固定）には触らない。補助科目は独立マスタ。

### UI

- **入力**: 勘定科目を選ぶと補助科目プルダウンが出る（マスタ由来＋「＋新しい補助科目を追加」でその場登録→マスタへ保存）。空欄（補助科目なし）も可
- **PL表示**: 勘定科目行は**合計値**を表示し、行頭の▶/▼で補助科目内訳を開閉（既定=閉じた状態・インデント表示）。「すべて展開/すべて折りたたむ」ボタンをタブ上部に
- **集計は勘定科目合計ベースのまま**（FL率・営業利益等の既存計算ロジックは不変。補助科目は表示上の内訳のみ）→ 数値のリグレッションリスクを構造的にゼロにする

## 2. スポット人件費（タイミー等の単発人件費）

### データモデル

- 新シート`DB_スポット人件費`: 日付／店舗名／区分（タイミー/その他 ※プルダウン・マスタは初期2種で開始）／金額／人数(任意)／メモ／入力者／入力日時
- BQミラー: `bqSyncSales`の対象に`stg_spot`を追加（毎朝08:45/11:00の既存同期に乗る）

### 反映（2系統）

| 反映先 | 方式 |
|---|---|
| **日別の人件費率・FL率**（ダッシュボード） | `getData`/`bqDailyStore`にspotを配信し、**フロント（app.jsのstat()）で日別加算**。人件費合計=PA＋社員＋スポット。内訳表示に「スポット」行を追加。※`分析_日別店舗`・`fact_daily_store`の生成ロジックには一切触らない（安全第一） |
| **月次PL** | 既存の「自動｜」行パターンを踏襲: 月次集計を`自動｜スポット人件費`（L区分）としてDB_PLへ日次upsert（morning-refreshに1ステップ追加）。手入力と混ざらず、二重計上しない |
| Lark日報（reportDataBQ） | 人件費集計に`stg_spot`を加算（1クエリ追加） |

### UI・権限

- 入力導線: PLタブと日別ダッシュボードの人件費カードに「＋スポット人件費」ボタン → 日付・店舗・区分・金額・メモ（3タップ級）
- 一覧・修正・削除: 同月内は編集可。一覧に入力者と入力日時を表示
- 権限: 既存の「使える機能」方式に`spot`キーを追加（既定: 本部・社長=全店／店長=自店舗）

## 3. マネーフォワード試算表CSV取込

### フロー

```
MF会計で部門別試算表CSVを出力（法人ごと・月次）
 → ダッシュボード「📥 MF取込」画面にアップロード
 → パース＆照合 → プレビュー（登録/除外/要選択/未対応の4分類）
 → ユーザーが確定 → DB_PLへ書込（bqSyncPL自動追随）
```

### 照合ロジック

1. **部門名→店舗名**: Supabase`store_aliases`に部門名を別名として登録して解決。未解決部門はプレビューで店舗を選択→aliasに保存（次回から自動）
2. **科目名の対応**: 新シート`DB_科目対応`（MF勘定科目／MF補助科目 → 内部勘定科目／補助科目／区分／**取込対象外フラグ**）。未対応科目はプレビューで対応付け→保存で学習
3. **判定**（キー=年月×店舗×勘定科目×補助科目）:
   - DB_PLに無い → 「**登録**」
   - あり・金額一致 → 「**除外**（取込済み）」
   - あり・金額不一致 → 「**⚠️要選択**」: プレビューで1件ずつ「残す/上書き」（一括ボタン「すべて残す」「すべて上書き」も用意）
4. **二重計上ガード（最重要）**: 以下は既に自動連携済みのため**既定で取込対象外**（`DB_科目対応`のフラグで管理・画面から変更可）:
   - 人件費系（給与手当・雑給・法定福利費・通勤手当）→ 分析_日別店舗/自動行由来
   - 運営委託費 → 精算書から毎週自動連携済み
   - 売上・仕入系 → 日次取込由来
   - 経費申請と重複しうる科目は除外はしないが、同月×同店舗×同科目に経費申請由来の登録がある場合プレビューに「⚠️経費申請と重複の可能性」を表示
5. 取込で登録した行はメモ欄に`[MF取込 2026-08-23]`を自動記載（手入力との区別・次回判定の材料）

### プレビュー画面

サマリ（登録N件／除外M件／要選択K件／未対応科目J件）＋明細テーブル。**要選択と未対応が0になるまで確定ボタンは押せない**。確定後に結果（登録件数・BQ同期結果）を表示。

## 4. 実装順と目安

| 順 | 内容 | 目安 | 依存 |
|---|---|---|---|
| 1 | 補助科目（列追加・マスタ・開閉UI・BQ列） | 1日 | なし（他2つの土台） |

## 5. 実装時にユーザーへ確認・依頼すること

1. **MF試算表CSVのサンプルを法人ごとに1枚ずつ**（列構成の実物確認。部門別出力の設定状態も）
2. 補助科目の初期マスタの種（例: 水道光熱費=電気/ガス/水道、通信費=電話/ネット 等。最初に入れておく分）
3. MF部門名と店舗名の対応の初期確認（初回取込プレビューで一緒に確定すればよい）
4. スポット区分の初期値（タイミー/その他 で開始してよいか）

## 6. 壊さないための検証項目

- [ ] 既存PL表示の数値が変わらない（補助科目導入後、勘定科目合計=導入前の値）
- [ ] `✍販管費入力`→自動同期がG列込みで動く（既存行・補助科目空欄行も従来どおり）
- [ ] スポット追加後の日別人件費率が「PA＋社員＋スポット」で再計算され、Lark日報とも一致
- [ ] MF取込を同じCSVで2回実行すると、2回目は全件「除外」になる（冪等性）
- [ ] `bqReconcileSales`の突合が引き続き完全一致（スポットは別テーブルのため影響しない設計だが確認）
