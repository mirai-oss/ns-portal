# 調査結果: インフォマート「支払管理」の請求書データの取り方（Mac mini実機・2026-10-13）

指示書: `指示書_MacMini_infomart-invoice実機調査と実装_2026-10-13.md`。実施: Mac miniセッション（読み取り・ダウンロードのみ。「集計する」「再集計」「承認依頼」は一切押していない）。
実装: `ns-daily-import/tasks/infomart-invoice.js`。9月分で対象10社すべて検算が通ることを確認済み。

## 1. 結論（検算4段に使うデータの取り方）
| 用途 | 取り方 | 備考 |
|---|---|---|
| **金額の正本（CSV）** | **「会計データ出力」**（MFフォーマット・`acc_request_download.pagex`）の CSV。1回で**全取引先分**が取れる | 列・性質は§3。取引先×店舗(部門)×税区分の行。借方金額=税込、借方税額=うち消費税 |
| 店舗別の画面金額（検算①） | 「支払金額の承認依頼」→「店舗別明細」（`invoice_breakdown.pagex`）の表 | 取引先ごとに開く。直接URLは前回画面を返す事故があるため**一覧(表示数100)のリンクをクリック**して開く |
| 請求書PDF（証憑・検算①②） | 店舗別明細の「請求書を印刷する」→別ウィンドウのPDFプレビュー（`task_preview.page?…pdfNm=invoice_bill….rpx`）→`application/pdf` | **PDFは文字情報が取れる**（`pdf-parse`で合計・消費税・御請求額・請求No・店舗別金額・税率別を抽出可）。ファイル名は全社`InvoiceBill.pdf`→`<年月>_<取引先>_<請求No>.pdf`で保存 |
| 承認依頼一覧の金額（検算③） | 「支払金額の承認依頼」一覧（表示数を100に）の 金額/消費税/請求金額・承認日時 | 取引先名は`(株)アールエスエス`形式。行の「店舗別明細」リンクの`DetailLoad('年','月','日','parent','seller',…)`に取引先コード |
| 月次集計（検算④） | 「支払金額の集計」（`index.pagex?st=1&yyyy=年`）の月行（税抜・消費税・税込・取引社数） | 読み取りのみ |

## 2. 各画面の確認結果
### 請求書データ出力（`invoice_list.pagex`）
- 期間（年月〜年月）・**処理選択**（請求一覧／請求一覧(店舗・部門別)／請求一覧(取引先別)／請求書／請求明細(伝票単位)／請求明細(商品単位)）・金額範囲・取引先・承認状況・保存方式・店舗/部門で絞り込み。
- 出力方法は「帳票表示する」（画面表示）と「データ作成依頼」（非同期でCSV作成→一覧から受信）。作成依頼の一覧は処理日時から62日分。
- **今回は実行していない**（会計データ出力で必要な金額が全て取れたため）。商品単位の明細が要る場合（インボイスの明細部分）は「請求明細(商品単位)」の「データ作成依頼」を使う想定。

### 会計データ出力（`acc_request_download.pagex`）← 採用
- 事前設定のレイアウト「マネーフォワード【IM作成中】」（設定基準=請求データ基準）。出力条件: 請求月・締め日（全て/末日）・個別請求の含む/含めない・事業者区分・取引先 等。
- 「データ作成依頼」→（約2分）→依頼一覧で「完了」→「受信」でCSV（Shift_JIS）。依頼一覧は過去分も残り、**完了済みの依頼は「受信」だけで再取得できる**。
- 列（27列）: 取引No・取引日・借方勘定科目(仕入高)・借方補助科目・借方部門(`01本店`〜`08匠味新横浜`)・借方取引先・借方税区分(`課税仕入 10`/`課税仕入 軽8`)・借方金額(税込)・借方税額・貸方勘定科目(買掛金)・貸方補助科目・貸方金額(円)・摘要(`9月分_取引先名`) 他（MFインポート形式）。
- **性質（9月分で検証）**: 取引先ごとに Σ借方金額(税込)＝請求金額、Σ借方税額＝消費税が全社で一致。**全取引先の合計は「支払金額の集計」の月次集計（税抜／税込）に一致**。
- ⚠️注意: 「貸方金額」は取引先ごとの合計だが、取引先が増えると同じ`取引No`に複数取引先が載る行があり貸方側の集計はずれる→**取引先は`借方取引先`（列F）で集計し、金額は借方金額・借方税額から出す**。
- 部門コードはInfomart側のコード（`06黒霧`＝黒霧屋 新横浜、`08匠味新横浜`＝鶏武者 新横浜）。ハブの`store_no`と06/08が逆なので、取込口へ送る際は`resolve_store('infomart', code)`を通すこと。

### 納品書一括出力（`receipt_all_search.page`）
- 対象日付（伝票日付/納品日・日付指定）・取引金額・取引先・保存方式・店舗/部門・並び順で絞り込み、「帳票表示する」または「データ作成依頼」。受領済み取引伝票の納品書をPDF出力（プレコフーズの納品書=インボイスの証憑に使える）。**今回は未実行**。

### 取引先別のsiire見込（Q1=b用）
- 仕入日次推移（`daily_transition_b_store.page`）に表示モード「**取引先ごと／店舗ごと／店舗別取引先ごと**」がある。**「店舗別取引先ごと」で 店舗×取引先 の月次見込が取れる見込み**（画面の存在のみ確認。列構成・CSV出力は次の調査）。

## 3. 検算の実装（`infomart-invoice.js`）と9月分の結果
- ① 取引先×店舗: CSVの税抜（借方金額−借方税額）＝店舗別明細（画面）＝PDFの店舗別金額
- ② 取引先: CSVの 税抜・消費税・税込 ＝ PDFの 合計・消費税・御請求額
- ③ 取引先: CSVの合計 ＝ 承認依頼一覧の 金額・消費税・請求金額（および店舗別明細の合計）
- ④ 対象取引先の合計 ≦ 月次集計（税抜／税込）
- 1つでも不一致なら「要確認」（理由を記録）。CSVとPDFが両方取れ検算が通った取引先だけ「取得OK」。
- **9月分: 対象10社すべて取得OK・月次完了**。seedの金額（アールエスエス¥105,923・伊勢五本店¥447,272・シモヤマ¥608,364）と一致。10社合計は月次集計以下。
- 10社の承認日はばらつき（9月分は10/1〜10/5）。全社「承認済み」になっていた。表記ゆれは`vendors`/`vendor_aliases`の正規化一致（法人格・空白を除いて部分一致）で突合できた（`有限会社森和`は2文字のため最小キー長を2にしている）。

## 4. 運用
- `config.js` DAILY_INDEPENDENT に `['infomart-invoice','10:30']`（毎日）。月次完了後は何もせず成功で終了。
- 結果: `import_runs.items`（取引先ごとの状態）・`detail`。**要確認があれば`partial`＋Lark通知**。未着（承認待ち）だけの間は成功扱い（詳細に記載）、**翌月10日を過ぎても揃わなければ一部失敗で通知**（毎日の通知ノイズを避けるため指示書から微調整）。
- 保存先: `ns-daily-import/logs/infomart-invoice/<年月>/`（PDF・CSV・result.json。gitignore済み）。
- 取込口（`invoice-auto-ingest`）への送信は未実装（担当C待ち）。送信時はCSV＋PDFが両方あり検算が通った取引先のみ。
- 再実行ボタン: ジョブは`import_schedule`でdaily。システム利用状況の再実行（2026-10-08のSQLで全有効ジョブに拡張済み）から依頼できる。
