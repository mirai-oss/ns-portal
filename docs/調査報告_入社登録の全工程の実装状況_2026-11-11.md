# 調査報告: 入社登録は最初から最後まで動くか（本番コード・Mac mini・DB・実行ログから）

作成 2026-11-11 夜。**読み取りだけの調査。本番の変更・スマレジへの書き込み・実在従業員のデータの変更はしていない。**
調べたもの: 本番で動いているコード（管理システム nippo・Edge Function・DB の関数）／Mac mini の自動操作（Playwright）／スマレジ API の使い方／DB の実データ／実行ログ。設計書の記述ではなく、実物で確認した。

## 0. 結論

**いまは「人の確認・承認が終われば、あとは自動で最後まで登録される」状態ではない。**

- 自動で最後まで進むのは **スマレジ従業員登録** と **賃金（入力 → スマレジへ反映 → 読み直して照合）** まで。
- 交通費・源泉所得税は、自動操作のプログラムは出来ているが、**スイッチが 2 つとも無効**。いまは「管理画面で手入力して、本部タスクに ✓」の運用。
- Web 明細・メール登録は、自動操作のプログラムはあるが、**それを動かす入口（待ち行列に入れる処理）が無い**。
- Slack 連携と本人アカウント登録は、あとから自動で「完了」になる経路が無い。
- そのため、全項目の完了は、いまは本部タスクの ✓（人）か「スマレジ照合」ボタン（人）に頼っている。
- 実際の入社でこの流れを通した実績は **0 件**（DB にあるのはテスト従業員の 1 件だけ）。

見つかった問題点

1. **照合の前に、いったん「完了」になる**: 自動操作が終わった時点で項目を完了にし、そのあとの照合で不一致なら失敗に戻す作り。照合の呼び出しが失敗すると、**照合していないのに完了のまま残る**。
2. **交通費の設定は、承認していなくても押せる**（承認済みかを確認していない）。
3. 経路の検索は、人がボタンを押さないと始まらない。承認と設定入力が別々の操作。
4. 停滞の知らせ（止まっている入社登録のアラート）は無効で、定期実行も登録されていない。

## 4. 未承認の賃金が自動で反映される経路（確認結果）

| 対象 | 結果 |
|---|---|
| 入社の賃金 | 権限のある人（本部・社長・マスター）が入力した値だけが正式な賃金になり、スマレジへ送られる。自動処理や権限のない人が入れる経路は無い。**2 段目の承認（社長の最終承認）は、入社の賃金には無い** |
| スマレジ → 管理システム | 取り込み前チェックが有効（本番で確認）。スマレジ側で直接変えられた賃金は、控えに記録するだけで正式な賃金にしない（未承認 12 件の保護はこの仕組み）。例外は入社直後の初期投入だけ |
| スマレジへ送る処理 | 送るのは正式な賃金の表の「未送信・エラー」の行だけ。申請の表から直接送る経路は無い |
| 既存従業員の賃金変更 | 本部の人が従業員ページから直接登録すると、承認なしで正式な賃金になりスマレジへ反映される（賃金の承認必須スイッチが OFF のため。**維持する設定のとおり**）。自動ではなく、人の操作による登録 |

**自動処理が、未承認の賃金を勝手に反映する経路は見つからなかった。** 今回の完成作業でも、この部分には触らない。

# 追記（2026-11-11 夜）: 方針の決定を受けた作業の記録

## 7. 決定（ユーザー）

- 入社登録を最終完了まで自動化することを最優先にする。人が行うのは、採用の判断・本人のフォーム入力・必要事項の確認・賃金の確定と承認。確定した内容をスマレジへ入れる作業は API か自動操作（Playwright）で行う。AI が税区分や賃金を推測して決めない。情報が足りなければ人の確認待ちにする。
- 入社時の賃金: アルバイト・パート＝社長の承認なし（権限のある担当者が確定したら自動で反映）／社員＝社長の最終承認が必須（承認まではスマレジに反映しない）。判定は正式な雇用区分で行い、不明・矛盾は確認待ち。スイッチ B と既存の賃金 2 段階承認①②は OFF のまま、別のものとして作る。未承認 12 件は一括承認しない。
- 完了判定は「登録 → 読み直し → 照合 → 一致したときだけ完了」。照合できていないものを完了にしない。
- 源泉所得税・Web 明細は、テスト従業員での実機テストを承認（テスト前の値を記録・テスト後に復旧・自動操作の本番スイッチは ON のままにしない）。

## 8. API で設定できるかの再確認

スマレジ・タイムカード API の従業員の更新で書けるのは、氏名・生年月日・住所・入社日などだけ。**交通費・源泉所得税・個別 Web 給与明細・メールアドレスは、API では書けない**（読むことはできる）。公開の仕様（従業員の更新の項目一覧）と、実際のコードの両方で確認した。この 4 つは自動操作（Playwright）で入れるしかない。

源泉所得税を止めている理由

- 源泉の自動操作は「適用開始月つきの行を追加する」方式で、**行を削除する処理が無い**。API でも消せない。テストで足した行を元に戻すには、**人がスマレジの管理画面でその行を削除する**必要がある（削除ボタンの有無は、画面では未確認）。「テスト後は元の設定に復旧」という条件を、自動では満たせない。
- 区分は人が指定した値を入れる方針のため、テストで入れる値（区分・扶養の数・適用開始月）の指定が要る。
- 提案: 適用開始月を先の月（例: 2027/01）にして 1 行足し、照合まで確認する。そのあと、管理画面でその 1 行を削除する（手順を案内）か、交通費のテストと同じく残す（テスト従業員は勤務・給与が無いため影響なし）。
