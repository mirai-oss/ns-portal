# 手順書: 精算ダッシュボード（GAS）へのセッション共通化パッチ貼り付け

作成: 2026-09-19／担当A（ダッシュボード）。A-11b（実装指示書_ラウンド6_2026-09-18.md §5.2-②・§5.7）対応。

## これは何をする作業？

精算ダッシュボードにログインすると**作業中でも6時間でいきなりログアウトされる**不具合があります（原因はGAS側のセッション保存方式）。経営ダッシュボード（tori-dashboard）で既に直してある方式に合わせて、精算ダッシュボードのGASコードだけを修正しました。**ここから先はGoogle側の制約で、Apps Scriptの編集画面に人間が直接貼り付ける必要があります**（自動化ツールからはデプロイできません）。

このリポジトリ（`~/NStyle-AI/seisan-dashboard`。GitHub: [mirai-oss/seisan-dashboard](https://github.com/mirai-oss/seisan-dashboard)）の`gas/SeisanDashboard.gs`は既に修正済みです。**画面側（index.html）は既にGitHub Pagesへpush済みで自動反映されています**（こちらは何もしなくて大丈夫です）。

## 準備

1. 精算ダッシュボードのスプレッドシート → 拡張機能 → Apps Script を開く（プロジェクト名「清算書」）
   - 直接リンク: https://script.google.com/d/1DlXuQhs3e7WgRhcxvt1cABrW66Md0TlKkHBtcF8uvWOgwKK_xNR7CU9H/edit
2. 左側のファイル一覧で `SeisanDashboard`（または `SeisanDashboard.gs`）を開く
3. 編集はブラウザの**Cmd+F（検索）**で該当箇所を探して、そこだけを書き換えてください。**「全部選択して丸ごと貼り替え」は絶対にしないでください**（同じような文字列が複数箇所にあり、事故ると他の変更が消えます）。

## STEP 2: セッション保存のしくみを差し替え

Cmd+Fで検索: `/* ---------- ログイン／セッション ---------- */`

このコメントの行から、その少し下にある `function sd_login(id, pw) {` で始まる関数の**閉じカッコ`}`まで**（下記の「変更前」とまったく同じ範囲）を、丸ごと「変更後」に置き換えてください。

**変更前**（この範囲をまるごと選択して削除）:
```
/* ---------- ログイン／セッション ---------- */

function sd_login(id, pw) {
  var acc = sd_findAccount_(id);
  if (!acc || !acc.enabled || String(acc.pw) !== String(pw)) {
    Utilities.sleep(500);
    throw new Error('IDまたはパスワードが違います');
  }
  var token = Utilities.getUuid();
  var user = { id: acc.id, name: acc.name, role: acc.role, storesRaw: acc.storesRaw };
  CacheService.getScriptCache().put('sdtk_' + token, JSON.stringify(user), 21600); // 6時間
  return { token: token, name: acc.name, role: acc.role };
}
```

**変更後**（ここに貼り付け）:
```javascript
/* ---------- ログイン／セッション ---------- */

// === セッション保存（A-11b・2026-09-19: 経営D（tori-dashboard/gas/Code.gs:535〜）と同じ
// ds_sessions（Supabase・A-11でレーンPが用意・両GAS共通）を正本へ移行。新旧併用フラグ
// SESSION_BACKEND（スクリプトプロパティ）で段階切替する:
//   'supabase' = 読み取りはds_sessions優先（無ければPropertiesへフォールバック）
//   未設定/それ以外 = 従来どおりPropertiesServiceのみで読み取り（既定・安全側）
// 書き込みは常に両方へ行う（ベストエフォート。Supabase書き込み失敗でもログイン自体は失敗させない）。
// 背景: 従来のCacheService（1キー最大21600秒=6時間固定・使うたびの延長ロジックが無い）が
// 原因で、作業中でも6時間経過すると強制ログアウトされていた。ds_sessions移行後は
// PropertiesServiceと同じsliding TTL（読むたびに+SD_TOKEN_HOURS延長）になる。
// sessには経営D側との突き合わせ・監査のためemailを必須で含める（ID/PW欄ログインでも
// 権限シートG列に登録があればsd_findAccount_が拾う。未登録なら空文字）。===
var SD_TOKEN_HOURS = 336;
function sd_sessionBackend_(){ return PropertiesService.getScriptProperties().getProperty('SESSION_BACKEND') || 'properties'; }
function sd_sessionStore_(){ return PropertiesService.getScriptProperties(); }
function sd_sessionSupaHeaders_(){
  var url = PropertiesService.getScriptProperties().getProperty('SUPABASE_URL');
  var key = PropertiesService.getScriptProperties().getProperty('SUPABASE_SERVICE_KEY');
  if (!url || !key) return null;
  return { url: url, headers: { apikey: key, Authorization: 'Bearer ' + key, 'Content-Type': 'application/json', Prefer: 'resolution=merge-duplicates' } };
}
function sd_sessionSupaPut_(token, sess, exp){
  var h = sd_sessionSupaHeaders_(); if (!h) return false;
  try {
    UrlFetchApp.fetch(h.url + '/rest/v1/ds_sessions', {
      method: 'post', headers: h.headers, muteHttpExceptions: true,
      payload: JSON.stringify({ token: token, sess: sess, expires_at: new Date(exp).toISOString(), last_seen_at: new Date().toISOString() })
    });
    return true;
  } catch (e) { return false; }
}
function sd_sessionSupaGet_(token){
  var h = sd_sessionSupaHeaders_(); if (!h) return null;
  try {
    var res = UrlFetchApp.fetch(h.url + '/rest/v1/ds_sessions?token=eq.' + encodeURIComponent(token) + '&select=sess,expires_at', { headers: h.headers, muteHttpExceptions: true });
    if (res.getResponseCode() !== 200) return null;
    var rows = JSON.parse(res.getContentText() || '[]');
    if (!rows.length) return null;
    var exp = new Date(rows[0].expires_at).getTime();
    if (!exp || new Date().getTime() > exp) { sd_sessionSupaDel_(token); return null; }
    return { sess: rows[0].sess, exp: exp };
  } catch (e) { return null; }
}
function sd_sessionSupaDel_(token){
  var h = sd_sessionSupaHeaders_(); if (!h) return;
  try { UrlFetchApp.fetch(h.url + '/rest/v1/ds_sessions?token=eq.' + encodeURIComponent(token), { method: 'delete', headers: h.headers, muteHttpExceptions: true }); } catch (e) {}
}
function sd_sessionPut_(token, sess){
  var exp = new Date().getTime() + SD_TOKEN_HOURS * 3600 * 1000;
  sd_sessionStore_().setProperty('sdtok_' + token, JSON.stringify({ sess: sess, exp: exp }));  // 常に書く（フォールバック・安全網として維持）
  sd_sessionSupaPut_(token, sess, exp);   // ベストエフォートで複製
}
function sd_sessionGet_(token){
  if (sd_sessionBackend_() === 'supabase') {
    var hit = sd_sessionSupaGet_(token);
    if (hit) {
      var expS = new Date().getTime() + SD_TOKEN_HOURS * 3600 * 1000;   // 使うたびに期限を延長（Propertiesと同じsliding TTL）
      sd_sessionSupaPut_(token, hit.sess, expS);
      sd_sessionStore_().setProperty('sdtok_' + token, JSON.stringify({ sess: hit.sess, exp: expS }));   // Propertiesにも同期
      return hit.sess;
    }
    // ds_sessionsに無い＝移行前の古いセッション、またはSupabase側の一時不調。Propertiesへフォールバック
  }
  var store = sd_sessionStore_();
  var raw = store.getProperty('sdtok_' + token);
  if (!raw) return null;
  var obj; try { obj = JSON.parse(raw); } catch (e) { return null; }
  if (!obj.exp || new Date().getTime() > obj.exp) { store.deleteProperty('sdtok_' + token); return null; }
  obj.exp = new Date().getTime() + SD_TOKEN_HOURS * 3600 * 1000; // 使うたびに期限を延長
  store.setProperty('sdtok_' + token, JSON.stringify(obj));
  sd_sessionSupaPut_(token, obj.sess, obj.exp);   // Propertiesにしかなかった旧セッションもここでSupabaseへ複製
  return obj.sess;
}
function sd_sessionDel_(token){ sd_sessionStore_().deleteProperty('sdtok_' + token); sd_sessionSupaDel_(token); }

function sd_login(id, pw) {
  var acc = sd_findAccount_(id);
  if (!acc || !acc.enabled || String(acc.pw) !== String(pw)) {
    Utilities.sleep(500);
    throw new Error('IDまたはパスワードが違います');
  }
  var token = Utilities.getUuid();
  var user = { id: acc.id, name: acc.name, role: acc.role, storesRaw: acc.storesRaw, email: acc.email || '' };
  sd_sessionPut_(token, user);
  return { token: token, name: acc.name, role: acc.role };
}
```

## STEP 3: `sd_supaLogin`（統合アカウントログイン）と `sd_auth_`（認証チェック）を差し替え

STEP2の直後に続く部分です。Cmd+Fで検索: `CacheService.getScriptCache().put('sdtk_' + token, JSON.stringify(user), 21600); // 6時間`

**STEP2を先に終えていれば、この文字列は残り1箇所しかヒットしません**（`sd_supaLogin`の中）。そこから`sd_auth_`関数の閉じカッコまでを置き換えてください。

**変更前**:
```
  var token = Utilities.getUuid();
  var user = { id: acc.id, name: acc.name, role: acc.role, storesRaw: acc.storesRaw };
  CacheService.getScriptCache().put('sdtk_' + token, JSON.stringify(user), 21600); // 6時間
  return { token: token, name: acc.name, role: acc.role };
}

function sd_auth_(token, needHonbu) {
  var raw = token ? CacheService.getScriptCache().get('sdtk_' + token) : null;
  if (!raw) throw new Error('AUTH'); // クライアント側で再ログイン誘導
  var user = JSON.parse(raw);
  if (needHonbu && user.role !== '本部' && user.role !== 'マスター') throw new Error('この操作は本部アカウントのみ実行できます');
  return user;
}
```

**変更後**:
```javascript
  var token = Utilities.getUuid();
  var user = { id: acc.id, name: acc.name, role: acc.role, storesRaw: acc.storesRaw, email: acc.email || email };
  sd_sessionPut_(token, user);
  return { token: token, name: acc.name, role: acc.role };
}

function sd_auth_(token, needHonbu) {
  var user = token ? sd_sessionGet_(token) : null;
  if (!user) throw new Error('AUTH'); // クライアント側で再ログイン誘導
  if (needHonbu && user.role !== '本部' && user.role !== 'マスター') throw new Error('この操作は本部アカウントのみ実行できます');
  return user;
}
```

## STEP 5【確認をお願いしたい点・§5.7②】: `sd_apiUploadAttachment` がライブに存在するか

2026-09-10のコミット（請求書のPL反映添付ファイルをns-portalから自動アップロードするための`sd_apiUploadAttachment`関数の追加）は、**バージョン表記（v5.20）を上げていない**ため、「v5.20と表示されている＝この関数も入っている」とは断定できません。

**お手数ですが、Apps Scriptエディタで以下を確認して結果を教えてください**:

Cmd+Fで `sd_apiUploadAttachment` と検索してください。

- **①ヒットしない（0件）場合**: 9/10のコミットがまだライブに入っていません。教えていただければ、該当の関数一式（コメント込みで約35行）をこちらで用意してお渡しします。
- **②ヒットする場合**: 関数自体は存在します。ただし**別の不具合を発見しました**——この関数は`SD_API_WHITELIST`という「呼び出しを許可する関数の一覧」と`sd_apiFnMap_()`という対応表の**どちらにも登録されておらず、たとえ存在していても実際には呼び出せない状態でした**（見つかったので今回のパッチに修正を含めています）。この場合は下記STEP 5-Bだけ追加で貼ってください。

## STEP 6【任意・急ぎません】: 経営ダッシュボードとログインを共有したい場合

ここまでで不具合修正は完了です。**さらに経営ダッシュボード（tori-dashboard）と精算ダッシュボードでログインを共有したい**場合だけ、追加で以下を行ってください（今すぐでなくて大丈夫です）:

1. 精算ダッシュボードのApps Script → 左メニューの歯車アイコン（プロジェクトの設定）→ 「スクリプト プロパティ」
2. 経営ダッシュボード（tori-dashboard）側のApps Scriptに既に登録されている`SUPABASE_URL`・`SUPABASE_SERVICE_KEY`と**同じ値**を、精算ダッシュボード側にも追加登録（値はこちらでは扱えません＝ご本人による設定が必要です）
3. 値の登録が完了し、正しく動くことを確認できたら、`SESSION_BACKEND`というプロパティに`supabase`という値を追加すると、両ダッシュボードでセッション共有が始まります（教えていただければこちらで実機確認します）
