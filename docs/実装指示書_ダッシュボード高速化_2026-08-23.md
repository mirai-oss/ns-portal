## 進め方の原則

- 実装順は タスク0→1→2→3。各タスク完了ごとにデプロイ・実測・WORKLOG記録
- GASデプロイは2段階（versions.create→deployments.update）＋`?action=ping`でver確認。appsscript.jsonは触らない（BigQuery設定消失の過去事故）
- 本番へ影響する切替（タスク3の既定化）は必ずユーザー確認を挟む

## タスク0: 現状計測のベースライン取得（30分）

fix-v71の計測診断アクションで、シートモード/BQモードそれぞれの主要アクション所要時間を記録（改善の前後比較用）。既に他スレッドが計測済みならその数値を流用し、再計測しない。

## タスク1: 最終更新ステータスの表示（Codex優先度1）

**目的**: 「数字が古い/処理中/失敗」をユーザーが画面で判別できるようにする。

- GASに軽量アクション `dataFreshness`（ログイン必須）を追加し、次を返す:
  - `fact_daily_store`のMAX(date)（=BQ側の最新営業日）
  - `分析_日別店舗`の最新日付（=シート側の最新営業日）
  - 直近の`bqSyncSales`実行時刻（同期時に`sales`データセット内の小さなメタテーブル or Script Propertiesへ記録する処理を`bqSyncSales`に追記。既存動作は変えない）
- app.jsのヘッダー付近に表示: 「データ最新日: 8/22 ／ BigQuery同期: 8/23 08:50 ✅ ／ 状態: 最新」。BQ最新日がシート最新日より古い場合は「⏳ 同期待ち」、取得失敗は「⚠️」
- 実装は既存の`S.lastSync`表示の隣に追加。5分キャッシュで十分（毎render時に叩かない）

## タスク2: 朝の反映前倒し（Codex優先度2＝鮮度問題の本命）

**目標の時間割**: 06:30-08:30取込 → **08:45 分析再生成 → 08:50 BQ同期** → 09:00にはダッシュボードに昨日分が出る。10時台/11:00の既存処理は保険としてそのまま残す（変更しない）。

1. 【サーバー】ダッシュボードGASの「分析テーブル再生成」トリガー関数の名前と現行トリガー時刻を確認（`NStyle-AI/gas-backup/dashboard-server/`参照。実物はclasp cloneで再取得して確認）
2. その再生成処理を外部から起動できるトークン認証アクション（例: `rebuildAnalysis`、`BQ_LOAD_TOKEN`認証・`setupIfNeeded`より前で分岐）をCode.gsに追加
3. `ns-daily-import`に朝タスク `morning-refresh` を追加（`DAILY_INDEPENDENT`に`['morning-refresh','08:45',{}]`）: `rebuildAnalysis`→`bqSyncSales`→`bqReconcileSales`の順に呼ぶだけ（`bq-sales-reconcile.js`の流用でほぼコピペ。失敗時は既存のnotify()で通知）
4. 検証: 翌朝09:05にBQモードで昨日分が表示されること／11:00の既存タスクが二重実行されても問題ないこと（bqSyncSalesは全置換・冪等なので設計上安全。突合の重複通知だけ確認）
- **注意**: Mac miniの取込が08:30までに終わらない日（リトライ時）は08:45時点のデータが不完全になる。`morning-refresh`の冒頭で当日の`.done-*`マーカー（8本）を確認し、未完了があれば15分待って再試行→3回でスキップ（10時台の保険に任せる）

## タスク3: BQモードの標準化（Codex優先度3・条件付き）

**前提条件（すべて満たしてから着手）**: ①fix-v70/72/73の数値突合診断で「シートとBQの表示数値が一致」の結論が出ている ②タスク0の計測でBQモードの方が速いことを確認済み ③タスク2完了（前倒ししないと「朝はBQに昨日分が無い」体験が悪化する）

1. **キャッシュ追加（必須の前提）**: `bqDailyStore`/`bqGetPL`/`bqGetDeposit`/`bqGetMedia`に`bqDetail`と同方式のCacheService 10分キャッシュを実装（全ユーザー既定化でBQクエリ数とGAS実行数が跳ねるため。キーはaction+months+店舗権限のMD5）
2. **フォールバック実装**: BQ取得が失敗した場合（エラー/タイムアウト）に自動でシート経路へ切替えて再取得し、画面に「⚠️ 予備経路（シート）で表示中」と小さく出す（`fetchStoreDirectory_`のフォールバックと同じ思想）
3. **既定値の反転**: `S.useBqDaily`の既定をtrueへ（localStorage未設定ユーザーが対象）。🧪トグルは残す（切戻し手段）
4. **段階展開**: まずマスター/社長のみ既定ON→2営業日問題なければ全役職ON（**それぞれユーザー確認を得てから**）
5. 検証: 各タブの数値がシートモードと一致・初回表示時間の前後比較・フォールバック動作（BQ側を一時的に不正テーブル名にする等はしない。ネットワーク遮断など非破壊の方法で）
