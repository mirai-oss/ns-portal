# 実装指示書：給与仕訳タブに「給料確定」ボタン＋本部タスク連携（担当C）

**依頼元**: 担当Bスレッド（2026-09-08）。ユーザー要望をそのまま転記：

> 給料仕分のタブで、その月の給料が確定したら給料確定を押す。
> 本部タスクに振り込み、現金手渡しのタスクが必要で自動発行され、完了も自動連携される。
> 振り込みの場合: タイトルは○月分 給料振込 会社名／期日は15日（土日祝日を挟む前はその前）／
> 担当は青山純・原美香・中山俊士／チェック項目に対象者の氏名が入る／
> 振り込み完了したら、その完了した人のチェックをつけていく／
> 全員完了したらそのタスクが完了になってLarkで報告。
> 現金手渡しの場合も同様（担当は青山純・原美香・中山俊士・坂本龍太郎・佐藤俊一・鍋倉巧、期日25日）。
> 現金支払いの人は現金手渡し・サイン（nippo）に連携される。

## 前提：バックエンドは担当Bが実装・本番適用済み

`ns-portal`コミット[771605d](https://github.com/mirai-oss/ns-portal/commit/771605d)（`supabase/2026-09-08_payroll_tasks_auto.sql`）で以下を新設・本番へ適用済みです。担当Cが直接触るのは**invoices.htmlのJSだけ**で、DB側の変更は不要です。

- `jp_prev_business_day(date) returns date` — 指定日が土日・祝日ならさかのぼって直前の営業日を返す（祝日判定は`jp_is_holiday`）
- `hq_create_payroll_tasks(p_year_month text, p_corp text default 'N-Style') returns jsonb`
  - 振込タスク（対象=`payroll_bank_accounts.payment_method<>'cash'`の在籍者、期日=15日を祝日調整）と
    現金手渡しタスク（対象=`cash_handoff_targets()`をそのまま再利用、期日=25日を祝日調整）を
    それぞれ1件ずつ自動発行（本部タスク1件＋工程1件＋チェックリスト＝対象者の氏名）
  - 担当（assignee_ids）は氏名の完全一致で自動解決（振込=青山純/原美香/中山俊士、
    現金手渡しはさらに坂本龍太郎/佐藤俊一/鍋倉巧を追加）
  - 同じ年月・種別で既に発行済みなら重複作成しない（べき等。ボタンを2回押しても増えない）
  - 権限: マスター・CEO・HQのみ呼び出し可
- `hq_check_payroll_task_item(p_year_month text, p_kind text /* 'transfer' or 'cash' */, p_person_name text) returns jsonb`
  - 個人の振込 or 現金手渡しが完了した瞬間に呼ぶと、該当のチェック項目にチェックを入れる
  - 工程内の全員分チェックが揃うと、本部タスクの工程を自動で完了扱いにする
    （既存トリガー`hq_task_recalc_status`により本部タスク本体も自動で`status='done'`になる）
  - そのタイミングで**初めて**完了になった場合のみ、Larkへ完了報告を送る（`notify_lark`関数。
    Webhook URLは`app_secrets.lark_webhook`＝いつも使っている共通のLark連携先）
  - 権限: マスター・CEO・HQ・TENCHO・TEAMが呼び出し可
  - **現金手渡し側はすでに自動で呼ばれます**（`cash_handoff_complete`から。担当Cが何もしなくても、
    nippoの「現金手渡し・サイン」で本人が完了した瞬間に本部タスクのチェックが連携されます）
  - **振込側だけ、担当Cの実装が必要です**（下記②）

## 担当Cにお願いしたい実装

### ① 「給料確定」ボタンの追加

給与仕訳タブ（`TAB==='payroll'`のUI、`payrollLoad()`/`payrollRender()`まわり。invoices.html 5792〜6300行あたり）の
上部（月選択のそば）に、次のようなボタンを追加してください。

```js
// 給料確定ボタン（PAYROLL_STATE.yearMonthはこのタブが既に持っている選択中の年月）
document.querySelectorAll("[data-payroll-finalize]").forEach(el=>el.onclick=async()=>{
  if(!confirm(`${PAYROLL_STATE.yearMonth}分の給与を確定し、本部タスク（給料振込・現金手渡し）を自動発行しますか？\n※既に発行済みの場合は重複作成されません。`)) return;
  el.disabled=true;
  const r=await authed("/rest/v1/rpc/hq_create_payroll_tasks",{
    method:"POST",
    body:JSON.stringify({p_year_month:PAYROLL_STATE.yearMonth,p_corp:"N-Style"})
  });
  el.disabled=false;
  if(!r.ok){ alert("本部タスクの自動発行に失敗しました: "+(r.body&&r.body.message||JSON.stringify(r.body))); return; }
  const d=r.body;
  alert(`本部タスクを発行しました。\n・給料振込：対象${d.transfer_count}名／期日${d.transfer_due}\n・現金手渡し：対象${d.cash_count}名／期日${d.cash_due}\n\n本部タスク（tasks.html）で内容を確認してください。`);
});
```

ボタン自体のHTML（配置場所の例。既存の月セレクトの近く）:
```html
<button data-payroll-finalize class="hq-btn primary">✅ 給料確定（本部タスクを自動発行）</button>
```

`p_corp`は固定で`"N-Style"`にしています（`users`テーブルに会社区分の列が無く、給与仕訳の対象者を
会社ごとに分ける仕組みが現状無いため。もし将来複数法人の給与を分けて発行したくなった場合はご相談ください）。

### ② 個人の振込完了時に、本部タスクのチェックを連携

`[data-payroll-pay]`のクリックハンドラ（invoices.html **6636〜6646行目**）が、まさに「個人の振込を
完了にする」箇所です。ここに1行、成功時の連携呼び出しを追加してください。

現状（6636〜6646行目）:
```js
document.querySelectorAll("[data-payroll-pay]").forEach(el=>el.onclick=async()=>{
  const userId=el.dataset.payrollPay;
  el.disabled=true;
  const r=await authed(`/rest/v1/payroll_journal_records?user_id=eq.${userId}&year_month=eq.${PAYROLL_STATE.yearMonth}`,{
    method:"PATCH",headers:{Prefer:"return=minimal"},
    body:JSON.stringify({paid_at:new Date().toISOString(),paid_by:ME.id}),
  });
  if(!r.ok){ alert("振込完了の記録に失敗しました"); el.disabled=false; return; }
  const rec=payrollRecordFor(userId); if(rec){ rec.paid_at=new Date().toISOString(); rec.paid_by=ME.id; }
  payrollRender(); updateMailSummaryBar();
});
```

追加後（`if(!r.ok)`の下、成功パスに1呼び出しを追加。氏名は`PAYROLL_STATE.rows`から引ける想定です。
`payrollRecordFor`の直前あたりに氏名取得を挟む形で問題ありません）:
```js
document.querySelectorAll("[data-payroll-pay]").forEach(el=>el.onclick=async()=>{
  const userId=el.dataset.payrollPay;
  el.disabled=true;
  const r=await authed(`/rest/v1/payroll_journal_records?user_id=eq.${userId}&year_month=eq.${PAYROLL_STATE.yearMonth}`,{
    method:"PATCH",headers:{Prefer:"return=minimal"},
    body:JSON.stringify({paid_at:new Date().toISOString(),paid_by:ME.id}),
  });
  if(!r.ok){ alert("振込完了の記録に失敗しました"); el.disabled=false; return; }
  const rec=payrollRecordFor(userId); if(rec){ rec.paid_at=new Date().toISOString(); rec.paid_by=ME.id; }
  // 2026-09-08追加: 本部タスク（給料振込）のチェックリストへ連携（担当B依頼）
  const row=(PAYROLL_STATE.rows||[]).find(r2=>r2.user_id===userId);
  const uname=row&&row.user&&row.user.name;
  if(uname){
    authed("/rest/v1/rpc/hq_check_payroll_task_item",{
      method:"POST",
      body:JSON.stringify({p_year_month:PAYROLL_STATE.yearMonth,p_kind:"transfer",p_person_name:uname})
    }).catch(()=>{}); // 本部タスク未発行の月でも振込完了自体は止めない（失敗を握りつぶす）
  }
  payrollRender(); updateMailSummaryBar();
});
```

`payrollRecordFor`のすぐ上で使っている`row`変数名が既存コードと衝突しないよう`row`/`r2`にしてあります。
既存の変数名に合わせて適宜リネームしてください。氏名の突き合わせは前後の空白（全角スペース含む）を
自動で無視するので、`users.name`の表記ゆれ（「中山　俊士」のような全角スペース区切りなど）は
気にせずそのまま渡して大丈夫です。

`hq_check_payroll_task_item`は「対応する本部タスクが見つからない／対象者名が見つからない」場合は
エラーを投げずに`{ok:false, reason:"..."}`を返すだけなので、この月に「給料確定」を押していなくても
振込完了操作自体は落ちません。

## 備考

- 「対象者」は`payroll_bank_accounts`の支払方法（`cash`かどうか）で振込／現金手渡しを振り分けています。
  現金手渡しの対象者一覧は、既存の`cash_handoff_targets`（nippo「現金手渡し・サイン」で使っているRPC）を
  そのまま再利用しているので、**「現金支払いの人は現金手渡し・サインに連携される」は元から成立しています**
  （追加対応不要）。
- 祝日判定（`jp_is_holiday`）は土日・国民の祝日（固定日＋ハッピーマンデー＋春分秋分の近似計算＋
  日曜と重なった祝日の振替休日）に対応。「国民の休日」（祝日に挟まれた平日）は非対応です
  （現行の祝日体系では発生頻度が極めて低いため）。
