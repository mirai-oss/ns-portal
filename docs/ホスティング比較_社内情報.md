# ホスティング比較: 社内情報管理システム（ns-info-system）

作成: 2026-08-18 ／ 実装指示書_第3期実装フェーズ §C-1 に基づく比較提案。**決定はユーザーが行う。**

## 0. 前提: 現在のアプリの技術的な特徴（改修量の判断材料）

`ns-info-system` の実コードを確認した結果、以下の2点が移行のしやすさに直結する:

1. **`src/middleware.ts` が全ページアクセス時に走る**（静的ファイルを除く）。ログインチェック＋**2段階認証(MFA)のゲート**をここで行っている。機密情報システムの認証の要なので、ここが壊れると即・事故になる
2. **PDFからの日付抽出API（`/api/extract-dates`）が `runtime = "nodejs"` を明示**し、`pdf-parse`（Node.js専用ライブラリ）を使っている。Edge実行環境では動かない設計

→ どのホスティングを選んでも、この2点（Middleware・Node.jsランタイムのAPI Route）が**そのまま動くこと**が必須条件。

## 1. 比較案

### ① Vercel Pro（$20/月〜・1シート）

- **改修量: ゼロ**。今と同じNext.js公式ホスティングなので、Middleware・Node.js Runtime API・環境変数まわりの挙動は完全に同一。プラン変更だけで完了
- 運用性: 現状の延長。GitHub連携・プレビューデプロイ・独自ドメインすべて既存のまま
- リスク: 最小（Vercel自身がNext.jsの開発元。組み込み機能への追従が最速・最も枯れている）
- 費用: $20/月/シート（約3,000円/月）。チームメンバーが増えるとシート課金が増える点は留意

### ② Cloudflare Workers（`@opennextjs/cloudflare` 経由）

- **改修量: 中〜大**。ビルド構成の追加（`wrangler.toml`・OpenNextアダプタ導入）、`nodejs_compat`フラグの有効化、デプロイ経路の作り直しが必要
- **技術的リスク（要調査・2026-08時点で未解決）**: OpenNextのCloudflareアダプタは、本アプリが使っている**Next.js 16の新しいProxyアーキテクチャとの間で既知の非互換課題が公開Issueとして存在**する（`cloudflare/workers-sdk` issue #13755「Version Trap」）。`nodejs_compat`はNode.js APIの**ポリフィル**であって完全なNode.js環境ではないため、`pdf-parse`（PDFパース処理）が実際に動くかは**移行してみないと確証が持てない**
- 運用性: Cloudflareの独自ドメイン・DNS機能は成熟しており問題なし
- 費用: Workers Paid $5/月（月1,000万リクエスト・3,000万CPU-ms込み。本システムの利用規模なら通常はこの範囲内に収まる想定）。**最安**
- リスク: 中〜高（機密情報を扱うシステムで、認証Middlewareと書類PDF機能が新しい構成できちんと動くか実地検証が必須。検証中に一時的に機能が壊れる可能性がある）

### ③ Netlify（$20/月・チーム人数無制限）

- **改修量: 中**。②と同じくOpenNextベースのアダプタでNext.jsを動かす方式（Vercelのようなフレームワーク開発元によるネイティブ対応ではない）。Next.js 16への追従は「アップデート済みだがVercelには一歩劣る」という評価
- 運用性: GitHub連携・独自ドメインは対応。2026年4月にシート課金を廃止し「$20/月・人数無制限」の定額制に変更されたばかりで、コスト予測はしやすい
- 費用: $20/月（クレジット制。処理量が想定を超えると追加費用が発生し得るため、初月は使用量を要ウォッチ）
- リスク: 中（②ほどではないが、①の「変更なし」と比べれば移行検証は必要）

## 2. 比較表

| 軸 | ①Vercel Pro | ②Cloudflare Workers | ③Netlify |
|---|---|---|---|
| 月額費用 | $20/月/シート | $5/月〜（従量） | $20/月（人数無制限） |
| 改修量 | なし | 中〜大 | 中 |
| Middleware対応 | ◎（公式） | ○（対応するが新しい経路） | ○ |
| Node.js Runtime API対応 | ◎（公式） | △（ポリフィル。pdf-parseの動作は要実地検証） | ○ |
| Next.js 16との相性 | ◎ | **△（既知の非互換Issueあり・2026-08時点未解決）** | ○（対応済みだがVercelに劣ると評価） |
| 独自ドメイン | ◎ | ◎ | ◎ |
| 移行時の事故リスク | 最小 | 中〜高（機密情報システムで検証必須） | 中 |

## 3. 推奨: **①Vercel Pro**

理由:
- このシステムは契約書・口座情報・ID/PWなど**機密情報を扱う**。要件定義書の「壊さない移行」原則からいって、**認証Middlewareや書類PDF機能を新しい実行環境で作り直すリスクを、月々1,500円程度の差額のために取る必要はない**と判断
- ②Cloudflareは月額では最安だが、**Next.js 16との既知の非互換Issueが現時点で未解決**であり、今この機密情報システムで検証台にするのは時期尚早。将来的にOpenNextのCloudflare対応が安定してから、コスト最適化の一環として再検討する価値はある
- ③Netlifyは②ほどのリスクではないが、①に対して費用面のメリットがない（同額かそれ以上になり得る従量制）ため、あえて選ぶ理由が薄い
