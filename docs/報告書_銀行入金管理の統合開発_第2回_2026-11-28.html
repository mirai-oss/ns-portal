2. GMOあおぞら：公式API／Playwright／規約・認証の調査

優先方法調べて分かったこと判定
①公式API公開仕様は個人向け（2021 年版）。法人向けは、会計ソフト等の仲介事業者（マネーフォワード・弥生など）経由で提供される形。直接利用できる法人向けAPIは、公開情報では確認できず。開発者向けのパートナー制度はある。要問い合わせ（下の文面）
②Playwright（Mac mini）取引規定（2026-07 版）には、自動操作の明示的な禁止も許可も無い。一方で、ID・パスワードの管理義務、誤入力の繰り返しでの利用停止、法人は電子証明書方式を使う旨、複数口座一括認証は法人を除く旨の記載がある。法人向けインターネットバンキングの個別規定の本文は取得できていません。ログイン画面には、パスワード入力とWebAuthn（端末認証）の部品がある。ログイン後の追加認証は、人がログインするまで不明。手動ログイン確認が必要
③マネーフォワード（保険）MFクラウド会計はGMOとPayPayの両方と連携済み。ただしMFから私たちのシステムへデータを渡せるか（API・CSV出力の可否、遅延）はまだ確認していません。別途確認が必要。保険。未確認
認証の回避・規約に反する自動操作はしません。追加認証が出る場合は、毎回人の操作が要る方式に自動化は組み込みません（その場合は手動CSV運用のまま）。本番での自動取得は、あなたの承認まで有効にしません。

ご指示実装

6. 業務委託先の入金管理タブ（精算ダッシュボード）— 安全な認証方式

既存の認証の評価（読み取りのみ・変更なし）

  • 権限シートのパスワードが平文でスプレッドシートにある／セッションは Script Properties 等に保持。銀行入金の情報を出す認証としては、現状のままでは不十分と判断（パスワード管理・総当たり対策・権限シートの閲覧者が見えてしまう点）。
  • 一方、Supabase側に sd_dash_grant（トークンのハッシュ・範囲・有効期限）が既にあり、これを土台にできる。

推奨する構成（実装は承認後）

  1. ブラウザはサービスキーを持たない。入金の取得は、専用の Edge Function（contractor-deposits）だけが行う。
  2. 委託先の特定は、ブラウザから渡される contractor_id ではなく、検証済みのセッション（sd_dash_grant のトークンのハッシュ）から、サーバー側で引く。URL・パラメータを変えても他の委託先・店舗に届かない（パラメータに委託先ID・店舗IDを受け付けない）。
  3. 契約の表（contractors・contractor_contracts）に、対象店舗・開始日・終了日・閲覧可能な期間を持たせ、契約終了後は自動で見えなくなる。
  4. 返す項目は専用のビューに限定：入金日・入金額・入金件数・（整合確認後に）売上・入金予定額・差額/未入金の状態・自店の精算書。口座番号・残高・原本CSV・他店舗/他法人・内部の承認/訂正履歴・他店の差異・委託先に出さない収益情報は含めない。変更・承認・紐付けの操作は無い（閲覧専用）。
  5. 売上・入金予定額は、kd_deposit_daily_v 等との整合を確認してから表示（この整合確認は未実施）。
未確認・要判断：①精算ダッシュボードのログインを、平文パスワードのまま使い続けるのか、見直すのか（見直す場合は別の作業）。②本番公開は別途承認。
