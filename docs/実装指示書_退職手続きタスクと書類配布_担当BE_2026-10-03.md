## 0. 流用する既存の仕組み（新規に作らない）
- **入社登録タスクの自動発行**（担当E・2026-09-01）: RPC `hq_create_onboarding_task`（`supabase/2026-09-01_hq_onboarding_task.sql`）がタスク＋工程（`hq_task_steps`）＋チェックリストをまとめて作る。工程には`action_kind`/`action_payload`で特別ボタンを出せる（例: `onboarding_line_guide`）。nippo側は`hqNotifyOnboarding()`がこのRPCを呼ぶ（失敗しても登録は継続）
- **LINE送信**: `line-webhook` Edge Functionの`push_user`（本人の`line_user_id`宛にtext）
- **本人向けPDF保管**: `payroll-pdfs`バケット（従業員×月の給与明細PDF）と同じ作法。社内情報の`info.tax_documents`（TK-121）は未実装のため**待たない**

## 1. 流れ（確定）
```
退職申請を本部が承認（Sync7の hr_approve_retirement）
 → 直後に本部タスク「退職手続き（○○さん・退職日 YYYY/MM/DD）」を自動発行（工程つき）
 → 本部が工程を順に完了。最後の工程「源泉徴収票」で PDF をアップロード
 → 本人のマイページ「📄 自分の書類」に表示 ＋ LINEに「源泉徴収票が届きました。ポータルの『自分の書類』からご確認ください」
```
- LINEには**PDFそのものや期限付きURLは送らない**（個人情報。ポータルのログイン後ページへ誘導するだけ）
- 工程の内容は雇用区分で分ける（`users.role`: `SHAIN`=社員／`AL`=アルバイト。`TENCHO`/`TEAM`/`HQ`は社員扱い）

| 工程 | 社員 | アルバイト | 期限の目安 |
|---|---|---|---|
| 1 「退職願」／「退職届」の受け取り | ✅ | — | 承認日＋3日 |
| 2 健康保険証の回収 | ✅ | — | 退職日 |
| 3 「健康保険・厚生年金保険被保険者資格喪失届」の提出 | ✅ | — | 退職日＋5日（法定期限） |
| 4 住民税の手続き（異動届・徴収方法の切替） | ✅ | — | 退職日の翌月10日 |
| 5 源泉徴収票をスマレジから出力→アップロード（`action_kind='offboarding_tax_slip'`） | ✅ | ✅ | 最終給与の確定後（退職月の給与支払日＋3日） |

## 2. 担当E（本部タスク側・SQL＋tasks.html）
1. **RPC `hq_create_offboarding_task(p_user_id uuid, p_name text, p_corp text, p_is_employee boolean, p_retirement_date date, p_approved_on date)`**: 入社版と同じ作法でタスク＋上表の工程を作成。担当は入社版と同じ固定担当（見つからなければ未定で作成）。期限は上表。`hq_tasks`に`related_user_id`（既存に相当列があれば流用）を持たせ、同じ従業員の退職タスクが既にopenなら二重発行しない
2. **工程5の特別ボタン**: `action_kind='offboarding_tax_slip'`・`action_payload={user_id,name,year}`。tasks.htmlの工程パネルに「📎 源泉徴収票PDFをアップロード」ボタン→Storageバケット`hr-documents`（非公開・パス`{user_id}/withholding_{year}.pdf`）へ保存→担当Bが用意するRPC `hr_register_document(p_user,p_kind:'withholding_slip',p_year,p_path)`→成功後に`line-webhook` `push_user`で本人へ通知文（§1）→工程を完了にする。失敗時は工程を完了にしない（手動で再試行可）
3. SQLは`supabase/2026-10-xx_hq_offboarding_task.sql`に残し、DB変更の事前報告様式でユーザー確認後に適用。バケット作成も同様
4. 入社登録タスクのLINE案内ボタン（既存）には触らない

## 3. 担当B（nippo側）
1. **承認フック**: `hr_approve_retirement`成功後、`hqNotifyOnboarding()`と同じ形で`hq_create_offboarding_task`を呼ぶ（`p_is_employee = role!=='AL'`・法人は`user_stores→stores.corporation_id`から入社版と同じ対応表で解決。失敗しても承認処理自体は巻き戻さない＝ログに残して「本部タスク作成に失敗。手動で作成してください」トースト）
2. **テーブル`hr_documents`**（`id, user_id, kind text, year int, path text, uploaded_by, uploaded_at, line_notified_at`）＋RPC `hr_register_document`（担当Eの工程5が呼ぶ。本部/社長/マスターのみ）。RLS: 本人は自分の行を読める・本部/社長/マスターは全件。バケット`hr-documents`のポリシーも同じ（本人=自分のフォルダ読み取りのみ）
3. **マイページ「📄 自分の書類」**: `hr_documents`を一覧し、署名付きURL（短時間・本人のみ）で開く。退職後も**本人がログインできる必要がある**→Sync7で「退職日翌日に`is_active=false`」としたため、書類閲覧だけは例外にするか要判断（§5-補足Q）
4. 完了後、担当Eの工程5ボタンと通し（使い捨て従業員・LINEは担当自身のテストアカウント）で動作確認→本番は実データ1件をユーザー立会い

## 4. やらないこと
離職票・雇用保険の電子申請連携／税務署提出用の控え管理／年末調整本体／源泉徴収票のPDF自前生成（調査メモ案B・将来候補）。

## 5. 補足質問（回答が無ければ★で進める）
- **補足Q1 退職後の書類閲覧**: ★a=退職後も「自分の書類」だけは本人がログインして見られる（`is_active=false`でも書類ページだけ通す・ログイン停止の例外を最小に）／b=退職日までに受け取る運用（LINE通知は退職日前に出す）。**a推奨**（源泉徴収票は最終給与後に出るため退職日より後になることが多い）
- **補足Q2 アルバイトの健康保険証回収**: ★a=社保加入者のみ対象なので、アルバイトでも`employee_profiles`に社保加入フラグがあれば工程2・3を出す（無ければ社員のみ）／b=社員のみ
