- **既存行を再利用**: 「本部」（`store_no=99`・`smaregi_store_id=7`・`is_active=false`）＝トーホー本社、「セントラルキッチン」（2026-09-19追加）＝田町セントラルキッチン。**新規行を作らず`location_type`と`display_name`を付ける**。新規はN-Style本社の1行だけ
- 全migrationは冪等（`if not exists`／`on conflict do nothing`）・`supabase/2026-10-xx_store_master_v2_*.sql`として残す・RLSは既存`stores`と同じ（認証済み読み取り・書き込みはRPC/管理画面のみ）
- Phase1では**どのシステムの読み取り先も切り替えない**（比較レポートまで）

## 1. 作るもの（DB）
1. `corporations` 列追加: `legal_name`・`display_name`・`is_group_company boolean default false`。seed: livegate=株式会社LiveGate/LiveGate、sk=株式会社SKコンサルティング/SK、nstyle=株式会社N-Style/N-Style、toho=有限会社トーホーエージェンシー/トーホー（4社`is_group_company=true`。`corp_code`は既存値を確認して合わせる）
2. `corporation_aliases(id, corporation_id, alias, source, created_by, created_at, is_active)`・unique`(alias, source)`。seed: トーホーの表記ゆれ4種（有限会社／（有）／㈲／トーホー）ほか各社の略称
3. `stores` 列追加: `location_type text check in (store,hq,central_kitchen,office,warehouse) default 'store'`・`display_name`。更新: 本部→`hq`/表示名「トーホー 本社」、セントラルキッチン→`central_kitchen`/「田町セントラルキッチン」。新規: 「N-Style 本社」（`hq`・N-Style・`is_active=false`・`store_no`は既存採番規則に合わせる）
4. `brands(id, name, display_name, is_active)`＋`store_brand_relations(store_id, brand_id, is_primary, effective_from, effective_to)`。バックフィル元=`stores.signs`（2枚看板: 鶏武者 新横浜=鶏武者/匠味、黒霧屋 新横浜=黒霧屋/うお蔵/彩 ほか。`signs`の実値を見て作る）。`info.brands`は**作らない・消さない**（Phase1後に`legacy_info_id`で対応付け）
5. `vendor_roles(vendor_id, role_type check in (operator,supplier,sublessee,landlord,advertising_vendor), effective_from, effective_to)` 主キー`(vendor_id, role_type)`。MostFun・FAM Diningが`vendors`に無ければ追加（会計用列は空でよい）し`operator`を付与
6. `store_operation_relations`（原文8の列そのまま。`*_entity_type check in (corporation, vendor)`・`relation_type check in (direct, outsourcing, sublease)`・`effective_from/to`・`contract_term_months`・`auto_renew`）。**同一店舗で期間が重なる行を禁止**（排他制約 or トリガー）。seed=原文9〜11: 直営7店舗（名義・運営・入金=トーホー・direct・`effective_from`は店舗の開業日が不明なら`2026-03-01`で統一し備考）／黒霧屋 新横浜（名義N-Style・運営トーホー・入金N-Style・outsourcing）／じんべぇ 川崎・新横浜・エース 本厚木（名義N-Style・運営=vendor MostFun・入金N-Style・outsourcing）／秋葉原 肉寿司（名義N-Style・運営=vendor FAM Dining・入金N-Style・outsourcing）。非直営5店舗は`effective_from=2026-03-01`・12か月・`auto_renew=true`・`effective_to=null`
7. `store_external_mappings(id, store_id, brand_id null, source_system, external_store_id, external_store_code, external_store_name, corporation_hint, vendor_id null, effective_from, effective_to, created_by, created_at, is_active)`。unique`(source_system, external_store_id) where external_store_id is not null`・unique`(source_system, external_store_name) where external_store_name is not null`。`source_system`の初期値集合: smaregi／smaregi_timecard／invoice／tabelog／hotpepper／gurunavi／gbp／reservation／payroll／settlement／ad／delivery。バックフィル: `store_aliases`（`source`/`kind`→`source_system`。不明は`legacy_alias`）・`stores.smaregi_store_id`→smaregi/smaregi_timecard・`seisan_store_name`→settlement・`mf_department_name`→payroll・`dash_store_name`→dashboard・`delivery_store_map`→delivery。**「本部」は`smaregi_timecard`+`external_store_id='7'`+`external_store_name='本部'`→トーホー本社の行として登録**（グローバル別名にはしない）
8. **RPC `resolve_store(p_source text, p_external_id text default null, p_code text default null, p_name text default null, p_corp_hint text default null)`** → `(store_id, brand_id, corporation_id, confidence, matched_by)`。順序固定: ①`(source, external_id)`②`(source, code)`③`(source, name)`完全一致④`stores.name`完全一致（空白・全角半角・「店」有無を正規化）⑤`store_aliases`⑥正規化後の部分一致（`confidence='low'`）⑦見つからなければ`null`を返し**`kd_unresolved_names`へ1行記録**（既存の隔離表・列構成は担当Dの実装に合わせる。Lark通知は既存の仕組みに乗せる）。security definer・読み取りのみ・`p_corp_hint`で同名の別法人店舗を絞る
9. RPC `register_store_mapping(p_source, p_external_id, p_code, p_name, p_store_id, p_brand_id)`（人・Miraiが確定したときの登録口。本部/社長/マスターのみ。登録後、同じ名前の`kd_unresolved_names`を解決済みに）
10. ビュー `v_store_current_relations`（今日時点の店舗×名義法人・運営主体・入金先・relation_type・契約満了予定）。精算関係はここから導出（専用表はPhase4で判断）
