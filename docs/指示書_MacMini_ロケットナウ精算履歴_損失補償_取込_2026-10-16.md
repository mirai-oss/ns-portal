# 指示書（担当D・Mac mini）: ロケットナウ「精算履歴」（損失補償・支給額）の取込 ＋ 4月分からの取り込み直し

作成: 2026-10-16 担当C／依頼元: ユーザー（中山さん）

## 背景（なぜ必要か）

- 売上入金（ar_receivables）の入金予定額は、今は「月次精算資料」（注文1件ごとの明細）の合計で作っている。
- 実際の入金額（支給額）とは**毎月ずれていた**（4月分から）。原因は、ロケットナウ側の「損失補償」（キャンセル等の補償）が月次精算資料に含まれないこと。
  - 例: 鳥一代 本店 2026年9月分 … 精算資料の合計 ¥849,470 ／ 実際の入金 ¥856,572 ／ 差 ＝ 損失補償 **+¥7,102**。
- 損失補償は、ロケットナウの管理画面の**「精算履歴」**にある別のダウンロード（`settlement-report`）に入っている。

## 画面の操作（ユーザーの動画で確認済み）

ロケットナウ Manager（今の月次精算と同じログイン）:
1. 左メニュー **精算管理** → 上の店舗プルダウン（例: 鳥一代 本店）を選ぶ。
2. 下の **「精算完了履歴」** で、期間（**支払日**）を選んで検索する。
   - 例: **9月分は10月に支払われる**ので、検索期間は「2026-10-01〜2026-10-31」。（期間の選択は「今日 / 1ヶ月 / 3ヶ月 / 6ヶ月 / 1年」のプリセットか、カレンダーで開始日・終了日を指定）
3. 結果の行（支給日／精算期間／…）をクリックすると右に **「精算履歴詳細」** が開く。
4. 詳細の下の **「精算履歴のダウンロード」** を押す → `settlement-report(<店舗ID>)-<支給日>.xlsx` が落ちる（例: `settlement-report(54887)-2026-10-15`）。
   - `54887` は鳥一代 本店の店舗ID。

## ダウンロードされるファイルの形（1店舗×1精算期間＝データは1行）

シート名「Settlement Detail」。行（1始まり）:
- 1行目: 「総手数料には、3％の決済手数料が含まれています。」
- 3行目: 法人名・適格請求書発行事業者番号・事業者名
- **4行目: 見出し**／**5行目: データ1行**

列（A〜O）:
| 列 | 見出し | 保存先の列（delivery_settlement_summary） |
|---|---|---|
| A | 店舗名 | store_name |
| B | 支給日 | pay_date |
| C | 精算期間（例「2026.09.01 ~ 2026.09.30」） | period_start / period_end |
| D | 売上金額 | sales |
| E | 総手数料 | total_fee（マイナス値） |
| F | 店舗負担の割引金額 | store_discount |
| G | 消費税 | tax（マイナス値） |
| H | 広告費 | ad_fee |
| I | 広告支援クレジット | ad_credit |
| J | 広告費調整額（返金） | ad_adjust |
| K | 広告費合計 | ad_total |
| L | **損失補償** | loss_compensation |
| M | RocketNow手数料割引 | rn_fee_discount |
| N | キャンセル注文金額 | cancel_amount（マイナス値） |
| O | **支給額** | payout |

検算式（取込側で計算して `checksum_ok` に入れる。合わなくても保存はし、ログに警告）:
`payout = sales + total_fee + tax + store_discount + ad_total + loss_compensation + rn_fee_discount + cancel_amount`
（例: 9月本店 1,263,868 − 343,741 − 34,295 + 7,102 − 36,362 ＝ 856,572 ✔）
※ 見出しの文字は取込時に必ず確認し、想定と違えば明確なエラーにする（月次精算資料と同じ流儀）。
