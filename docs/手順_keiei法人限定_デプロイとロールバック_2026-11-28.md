## 何を直したか
Edge Function はサービス用の鍵で DB を読むため、DB の RLS（法人の限定）を通らない。`keiei-api-*` は役職（マスター/CEO/HQ/TEAM=全店、TENCHO=担当店）だけを見ていて、法人の限定を見ていなかった。
→ `_shared/corp-scope.ts`（新設）が、検証済みの uid から「見てよい法人・店舗」を求め（`public.dep_unrestricted()` / `dep_allowed_corp_ids()` と同じ意味）、3 つの関数が返す行を絞る。

| 関数 | 変更 | 本番の verify_jwt |
|---|---|---|
| `keiei-api-reservation` | 予約の明細・キャンセル集計・月次サマリを、許可された法人の店舗に限定 | **false** |
| `keiei-api-home` | 店舗一覧を限定（以降の集計はすべてその店舗で読む） | **false** |
| `keiei-api-dashboard-summary` | 全 kind（pl/media/deposit/store/daily/deposit_daily/deposit_carry/ad/target/target_daily/delivery_daily/media_daily/pl_entries/spot/loan）と明細分析（detail*）を限定 | **false** |

- 法人の列（corporation_id）がある表は、その列で絞る（DB の RLS と同じ。法人が空の行＝全社共通経費は、限定された人には出ない）。法人の列が無い表は、店舗（許可された法人に属する店舗）で絞る。
- クライアントから来る store_id / media_name / store_ids は、許可範囲との共通部分だけを使う（範囲外なら空。形は従来の空応答と同じ）。
- 制限なしのユーザー（マスター・許可の設定が無い人）とサービス用の呼び出しは、**完全に従来どおり**（返り値は 528 リクエストで修正前と一致を確認済み）。
- 返り値の `scope` に、法人を限定された人にだけ `corporationIds`（見てよい法人の id）が足される。制限なしの人には足されない。
- 許可の設定を読めないときは 500（全法人を返す側には倒れない）。マスターは info を読まない。

## うまくいかないとき（info の読み取りが失敗する場合の案・未適用）
`info` スキーマが PostgREST の公開対象でない／サービス接続で読めない場合は、`corp-scope.ts` の `info.*` の読み取りを、次の関数の呼び出し（`sb.rpc("corp_scope_for_uid", { p_uid })`）に置き換える。**この SQL は適用していない。承認のうえで適用する**。
```sql
create or replace function public.corp_scope_for_uid(p_uid uuid) returns table(kind text, corporation_id uuid)
language sql stable security definer set search_path to 'public' as $$
  select 'uc', uc.corporation_id from info.user_corporations uc where uc.user_id = p_uid
  union all
  select 'rc', rc.corporation_id from info.profiles p join info.role_corporations rc on rc.role_id = p.role_id
   where p.id = p_uid and p.is_active
$$;
revoke all on function public.corp_scope_for_uid(uuid) from public, anon, authenticated;
grant execute on function public.corp_scope_for_uid(uuid) to service_role;
```
（kind='uc' が 1 件でもあれば uc の法人だけ、無ければ 'rc'、どちらも無ければ制限なし。）
