## 3. ウィジェット設定（今回の設計の中核）

決定3・4を1つの仕組みで実現する。

### 3.1 ウィジェットカタログ（コード内に定義）

`index.html` 内に `WIDGETS` レジストリを定義。1ウィジェット=「key・表示名・対応エリア・データ取得関数・描画関数・必要データ源」。v1で実装するもの:

| key | 名称 | エリア | データ源 |
|---|---|---|---|
| kpi_sales | 今月売上（前年比つき） | kpi | 経営D（キャッシュ） |
| kpi_nippo | 日報提出（昨日） | kpi | reports |
| kpi_tasks | 本部タスク（停滞・超過） | kpi | hq_tasks |
| kpi_check | チェックシート実施率（今日） | kpi | checklist_* |
| kpi_fl | F/L率（今月） | kpi | 経営D（キャッシュ） |
| kpi_mytasks | 自分のタスク | kpi | hq_tasks |
| panel_chart | 売上推移チャート | main | 経営D（キャッシュ） |
| panel_alerts | ⚠️要対応（横断） | side | 集約（下記3.4） |
| panel_posts | 📢お知らせ | main | portal_posts |
| panel_mytasks | ✅今日の自分のタスク | side | hq_tasks |
| panel_stores | 🏪店舗別・今日の状況 | wide | 経営D＋checklist＋reports |
| panel_timeline | 🕐最近の動き | wide | hq_task_activity＋reports＋checklist_checks |

新しいウィジェットを将来足すときは、このレジストリに1エントリ追加すれば設定画面に自動で並ぶ構造にすること。

### 3.2 レイアウト保存（新テーブル）

```sql
create table if not exists portal_layouts (
  role text not null,          -- MASTER/CEO/HQ/TEAM/TENCHO/SHAIN/AL（MASTERは役割と独立の仮想役割として扱う）
  area text not null,          -- kpi / main / side / wide
  widget_key text not null,
  position int not null default 100,
  enabled boolean not null default true,
  updated_at timestamptz not null default now(),
  primary key (role, area, widget_key)
);
-- RLS: 読み=ログイン全員 ／ 書き=portal_is_master()（既存関数を利用。新関数は作らない）
```

- **テーブルが空の役割はコード内のデフォルト構成**（プロトタイプと同じ配置）にフォールバック。
- 表示判定は「役割のレイアウト設定 ∩ その人がデータを取れるか」。例: kpi_sales が設定されていても、経営Dのメール未登録ユーザーには「経営D未接続」カードを出す（数字は絶対に出せない=GAS側で認証されるので安全）。

### 3.3 設定UI（マスター専用・⚙️内に「🎛 画面のカスタマイズ」を新設）

- 役割を選ぶ → エリアごとにウィジェットの ✔表示/非表示 と ↑↓並び順 を編集 → 保存（upsert）
- 「この役割の画面をプレビュー」ボタンで、その役割のホームがどう見えるかをその場で確認できるようにする（既存データで描画。プロトタイプの役割切替と同じ要領）
- 既定に戻すボタン（その役割の行をdeleteするだけ）

### 3.4 「⚠️要対応」の集約ロジック（v1）

上から優先順に最大8件:
1. hq_tasks: 期限超過・3日以上停止（既存の判定関数を流用）
2. reports: 昨日分の未提出者（対象=役職がTENCHO以上、または日報フォーマットを持つ役職。0人なら出さない）
3. checklist_checks: 今日の「異常あり」報告（result=ng）
4. hq_notifications: 未読（上記と重複しないもの）
各行にどのシステム発かのバッジ＋クリックで該当画面へ。

## 4. 売上データの取得（経営D連携）

- 手順: ポータルのSupabaseセッション → tori GASの `action=supalogin`（stoken）でtoriセッション取得 → `action=data&keys=daily&months=13` を取得（前年比計算のため13ヶ月）。実装は `tori-dashboard/app.js` の `doSsoLogin`/`fetchData` を参考に（**toriのリポジトリは読むだけ。変更しない**）
- キャッシュ: `localStorage['portal_tori_cache']` = `{fetchedAt, daily:[...]}`。**再取得条件: キャッシュが無い／キャッシュのfetchedAtが「今日の11:00」より前で現在が11:00以降**。ヘッダーの🔄で強制再取得
- 取得中はKPIカードにスケルトン表示。失敗（メール未登録・GAS落ち）は「経営Dに接続できません／メール登録が必要です」カードで静かに劣化。**画面全体をブロックしない**（売上以外はSupabaseから即描画）
- 集計はクライアントで: 今月売上=当月合計、前年比=前年同月同日まで比、F/L率=daily内の原価・人件費列から（列名はtoriの`分析_日別店舗`準拠。実データで検証すること）
