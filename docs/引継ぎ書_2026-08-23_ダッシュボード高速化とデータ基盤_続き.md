## 4. 主要な学び（このセッションで得た教訓）

- **GAS webappの`?action=ping`のバージョン文字列を常に確認してから作業結果を信じること**。「デプロイした」という申告だけでは信用しない（本セッションでも複数回、申告と実際のバージョンがズレた）
- **CacheServiceは1キーあたり100KB上限**。大きめのBQ結果をキャッシュする時は複数キーに分割する必要がある（`bqCacheGet_`/`bqCachePut_`が既にこの対応済み・今後BQ系アクションを増やす時はこのヘルパーを再利用すること）
- **GAS webappへのPOSTはcurlで直接叩かず、Node.jsの`fetch()`を使うこと**（リダイレクト周りの挙動差でcurlは405になりやすい）
- **BigQueryの日次集計テーブル（`fact_daily_store`等）には月末まで日付だけ入った実績0件のテンプレート行がある**。「最新日」を調べる時は素の`MAX(date)`ではなく、`WHERE net_sales > 0 OR guests_total > 0`等で実績行に限定すること（同じ罠に3回引っかかった: BQ側→シート側→今回の`bqReconcileSales`は元々対策済みだった）
- **1つの機能を直したら、同じ画面の中で他の場所が古い計算方法のまま残っていないか確認すること**（明細分析のページ上部サマリーと店舗別テーブルが別々の計算式を使っていて数字が食い違っていた実例あり）
