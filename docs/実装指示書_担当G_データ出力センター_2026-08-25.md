## ユーザー提供仕様（原文・これが正。以下を満たすこと）

### 1. 基本設計

```text
Supabase / BigQuery
        ↓
出力対象データ取得
        ↓
共通Export Service
        ↓
用途別テンプレート
        ↓
 ┌──────┼──────┐
Excel   CSV   Google Sheets
```

各機能が独自にExcel生成処理を持つのではなく、可能な限り共通Export Serviceを経由する。将来的にHermes AgentなどのAIエージェントからも、このExport Serviceを呼び出せる構造にする。**Googleスプレッドシートをデータベースとして使う機能ではなく、Supabase/BigQuery等を正本として、Sheets・Excel・CSVを「出力先」として扱う。**

### 2. 「データ出力センター」を新設

管理者メニューに「データ出力」を新設。画面: カテゴリー▼／出力データ▼／対象期間▼／対象法人▼／対象店舗▼／出力形式（Excel・CSV・Googleスプレッドシート）／[プレビュー]／[出力する]。
**対象法人・店舗は`public.corporations`と店舗マスタ（stores/store_no）を正本として使用。法人名・店舗名の文字列直書きは禁止。**

### 3. 出力メニュー（初期構成として登録できる構造）

■経営・売上: 月次PL／店舗別PL／売上実績／予算実績比較／店舗比較 ■マーケティング: 広告管理／媒体別広告実績／ROAS分析 ■人事・労務: 従業員一覧／勤怠実績／シフト予定／シフト実績／人件費／給与関連データ ■経理: 経費申請一覧／業務委託精算／支払データ ■管理: アカウント情報 ■その他: 今後追加可能
※データソース未完成の項目を無理に実装しない。**後から出力項目を簡単に追加できる構造を優先。**

### 4. テンプレート管理機能

設定→「出力テンプレート管理」を新設。テンプレートごとに `template_id / template_code / template_name / category / description / file_path / version / is_active / created_by / created_at / updated_by / updated_at` を管理。プレビュー・テンプレート変更・過去バージョン。**テンプレート差し替えでExport Service本体のコード変更が極力発生しない構造。**

### 5. テンプレートのデザインを維持する

Excelはテンプレートのフォント・セル色・罫線・行高・列幅・セル結合・数値書式・%・日付形式・条件付き書式・印刷設定・ヘッダー/フッター・ロゴ・数式を可能な限り維持し、**指定箇所にデータだけ流し込む**。毎回AIがデザインを生成する方式にしない。

### 6. データマッピング

テンプレートとDB項目の対応をコードへ大量ハードコードしない。`template_mapping`（template_id / source / source_field / target_sheet / target_cell・target_column / transform_rule / display_format）のような設定管理を検討。**ただし設定DB化で逆に複雑になる場合は、より保守性の高い方式を提案してから実装。**

### 7. Excel / CSV / Google Sheetsの違い

- Excel: デザイン・数式維持。最も完成度の高い帳票
- CSV: データのみ。UTF-8・ヘッダー有無・文字コード・日付形式を必要に応じ設定可能に（他システム取込用途）
- Google Sheets: テンプレートをコピー→新規Spreadsheet作成→データ流し込み→指定Driveフォルダへ保存→URL返却。**Sheetsを正本DBにしない**

### 8. プレビュー機能

出力前に簡易プレビュー（対象店舗数・対象データ件数・売上合計等）。誤った法人・店舗・期間での大量出力事故を防ぐ。

### 9. 出力履歴（監査ログ）

`export_id / user_id / template_id / export_type / corporation_id / store_id / period_from / period_to / filters / file_path・sheet_url / status / created_at / completed_at` を全出力について記録。誰が・いつ・何を・どの条件で出力したか確認可能に。

### 10. 権限制御（重要）

ログインユーザーが閲覧できない法人・店舗・従業員データは出力でも取得不可。**画面で選択肢を隠すだけでなくサーバー側でも権限チェック**。給与・個人情報・銀行口座・契約情報・ID情報は通常より厳しい制御。

### 11. ID・パスワード関連は別扱い

「ID・パスワード一覧」は通常Exportと同じ権限で出力しない。まず**ログインパスワードが平文保存されていないことを確認**（※監査済みの事実: ハブはSupabase Auth=ハッシュ、経営Dのアカウントシートはsha256+salt、社内情報の外部サービスPWはcredential_secrets分離+RPC経由）。認証パスワードは原則出力不可。外部サービス共用アカウントを出力する場合のみ「管理者権限→再認証→出力理由入力→出力→監査ログ」の追加保護。**Secret/service_role/APIキーはExport対象外。**

### 12. テンプレートデザインの作成フロー

Gemini等がテンプレートデザイン作成→人間が確認→完成版をテンプレート管理に登録→Export Serviceが使う。**AI=テンプレート作成支援、システム=確定テンプレートへのデータ投入**という責任分界。

### 13. 将来のAI/Hermes Agent連携

Export ServiceはUIだけでなく内部API/Toolとしても呼び出せる構造に。AIからDBへ直接自由SQLは投げさせない: `Hermes→AI Gateway→許可されたExport API→権限確認→Supabase/BigQuery→ファイル生成`。AI経由でも依頼ユーザー本人の権限以上のデータは取得不可。

### 14. 「AI自由レポート」は定型出力と分離

「✨AIにレポート作成を依頼」は将来追加できる構造にするが、**Phase 1は定型テンプレート出力を優先**。AI自由出力は別Phase。

### 15. 出力利用状況のログ化

将来の「システム利用・コストダッシュボード」と連携できるよう、出力回数・ユーザー・種類・ファイルサイズ・処理時間・成功/失敗・Sheets API使用量等を可能な範囲でログ化。

### 16. 実装順序

```text
Phase 1: 共通Export Service設計 → テンプレート管理設計 → 権限・監査ログ設計
 → データ出力センターUI → 1種類だけ実装 → 実機テスト → 問題なければ横展開
```

最初のPoCは「月次PL」または現在データ構造が最も整理されている帳票を1つ。既存データ構造を確認した結果、別の帳票の方がPoCに適している場合は理由とともに提案。

### 17. 実装前にClaude Codeから報告すること（コードを書く前に）

1. 現在のSupabase/BigQueryから出力可能なデータ一覧 2. 既存のCSV/Excel出力機能の有無 3. 既存コードで再利用できる部分 4. Excelテンプレートの最適な保管場所 5. Google Sheetsテンプレートの管理方法 6. Export Serviceの推奨アーキテクチャ 7. テンプレートマッピング方式 8. 権限/RLSとの整合性 9. 大量データ出力時の性能対策 10. 既存機能を壊さない移行方法 11. PoCとして最初に実装すべき帳票 12. 想定されるセキュリティリスク

## 補足（当社環境の前提・調査の近道）

- Excel生成は`exceljs`の実績が社内情報管理システムにある（テンプレートのスタイル保持流し込みも同ライブラリで可能=§5の有力候補。調査で適合性を確認）
- 出力対象データの所在は監査済み: BQ`sales.fact_daily_store`/`stg_*`（売上・PL・広告・入金）／ハブSupabase（経費・シフト・勤怠・従業員・精算・API費用）。**正本表（要件定義書§16）に無い新しいデータ経路を作らない**
- Google Sheets/Drive操作はEdge Function（サービスアカウント）方式とGAS方式の両案を調査で比較（GASは既存実績が厚いが担当A専任領域のため、GAS案を採る場合はA経由の依頼になる=アーキテクチャ判断材料に含めること）
- ポータルシェル（担当F）の「⚙️管理」エリアに「データ出力」「出力テンプレート管理」のメニュー枠が用意される予定（F-6）。UIはexport.html単体で完結させ、シェルからはiframeで呼ばれる想定で作る
