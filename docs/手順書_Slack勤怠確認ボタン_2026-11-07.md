# 手順書：勤怠の ○× ボタン（Slack）— 店長が確認・修正申請、中山さんが承認（2026-11-07）

> 毎朝の勤怠取込のあと、打刻がおかしい勤務（1 時間以内／13 時間超え／24 時間超え）が **勤怠確認チャンネル** に届きます。
> 店長が「○ 合っている」か「× 修正する」を押し、修正は中山さんの Slack（DM）に承認依頼が届きます。承認すると管理システムの勤怠実績に反映されます。

---

## できあがりの姿

```
⏰ 勤怠確認
⚠️ 勤怠確認
11/6（金）　鳥一代 本店
Aさん　10:00−翌10:00（24時間0分）
24時間超え（要確認）。打刻は合っていますか？
[ ○ 合っている ]  [ × 修正する ]
```
- **○ 合っている** → メッセージが「✅ 合っている（店長名・日時）」に変わる。
- **× 修正する** → 小さな入力画面が開く（正しい出勤・退勤の日時、理由）→「承認を依頼」。
  - 店長側のメッセージは「📝 修正を申請しました … 承認待ち（マスター）」に変わる。
  - 中山さんの DM に「🙋 勤怠修正の承認依頼 [✅ 承認] [❌ 却下]」が届く。
- **✅ 承認** → 管理システムの勤怠実績（人件費日次・勤怠記録）が修正後の時刻に変わり、両方のメッセージが「✅ 反映済み」に変わる。
- **❌ 却下** → 両方のメッセージが「❌ 却下」に変わる（何も変わらない）。

**押せる人**
- ○ / ×: その店舗の店長（TENCHO は担当店舗のみ）、TEAM・HQ・CEO。それ以外は本人だけに「権限がありません」と出る。
- 承認 / 却下: **マスター（中山さん）だけ**。

**反映の範囲（大事）**
- 直るのは **管理システム（ハブ）の勤怠実績** です。スマレジ・タイムカードの打刻は API で書き換えられない（書き込み権限が未申請）ため、**スマレジ側は今までどおり手で直してください**（給与はスマレジ側が正）。
- 承認で直した行は「手修正ロック」が付き、翌日以降の自動取込で元に戻りません。スマレジ側も直せば、同じ値になります。

- 同じ勤務に 2 回は届かない（1 勤務 1 アラート）。

## 仕組み（読まなくてよい）
- 表 `sf_attendance_alerts`（状態 open → confirmed / fix_requested → approved / rejected）。状態を変えるのは RPC だけ（`sf_attendance_alert_confirm` / `sf_attendance_fix_request` / `sf_attendance_fix_decide`）。
- `labor_cost_daily` に `manual_fixed_at` 等の列と BEFORE UPDATE トリガ `labor_cost_daily_keep_manual_fix`（手修正済みの行は同期の upsert で打刻の値が戻らない。解除は `manual_fixed_at` を NULL にする）。元の値は `orig_*` 列に残る。概算人件費 `smaregi_estimate_cost` は時間に比例して付け替え。
- 送信は `notify-slack`（無変更）。受け取りは `slack-interact`（署名検証 → `user_slack` → RPC → `notify-slack update`）。
