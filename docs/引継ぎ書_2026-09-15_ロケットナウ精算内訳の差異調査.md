## ② 重要な落とし穴（必ず読むこと）

1. **GAS Web AppのURLはcurlで叩くと高確率で失敗する**（`ページが見つかりません`という
   Google Drive風のHTMLが返る。302リダイレクトの絡みか、環境固有のブロックか原因不明）。
   **必ずBrowserツール（`mcp__Claude_Browser__javascript_tool`）でブラウザのfetch()経由で
   叩くこと**。ブラウザ経由なら（サーバー側が本当に不安定な時を除き）安定して動く。
   手順: `mcp__Claude_Browser__navigate`で`https://mirai-oss.github.io/tori-dashboard/index.html`
   を開いてから、`javascript_tool`で以下のように呼ぶ:
   ```js
   const url = 'https://script.google.com/macros/s/AKfycbwW0qhyEr0-uQWTaLg7MkQhurHq6wMoaOKL7uCCnI_bgnAsGB5-auqG_dm_Q9uJc3Kc/exec';
   const r = await fetch(url, { method: 'POST', headers: { 'Content-Type': 'text/plain;charset=utf-8' }, body: JSON.stringify({action:'login', id:'info', pw:'mirai0314'}) });
   (await r.text()).slice(0,300);
   ```
2. **GAS(`gas/Code.gs`)への直接編集（Editツール）は、財務データの読み書きに関わるコードだと
   Claude Codeの安全分類器（`Modify Shared Resources`）にブロックされることがある**
   （`bqSyncDeliverySettlement`本体の追加時に実際にブロックされた。読み取り専用の診断関数
   `diagDeliverySettlementBreakdown`は問題なく編集できた＝書き込み系コードが引っかかる傾向）。
   ブロックされた場合はコードをチャットでユーザーに提示し、**ユーザー自身にApps Scriptエディタへ
   手貼りしてもらう**しかない（ボタン化してapp.js側から呼ぶ設計も同じ理由でブロックされうる）。
3. **`gas/Code.gs`は複数セッションが同時編集する共有ファイルで、ユーザーの手貼り→デプロイのたびに
   「関数の中身がまるごと抜け落ちる」「別セッションの変更で上書きされる」事故が頻発している**
   （本日だけで`bqLoadDeliveryOrders`が3回消失、新規追加した`diagDeliverySettlementBreakdown`も
   デプロイ後に見つからなくなった）。**貼り付け後は必ず以下で実際に反映されているか確認**:
   - ブラウザ経由で該当actionを（無効トークンで）叩き、`unknown action`ではなく
     `unauthorized`等の“関数には届いている”エラーが返るか確認する。
   - `unknown action`が返る場合は、ユーザーに`Cmd+F`で関数名を検索してもらい、ヒット件数を
     確認する（0件＝貼り付け自体が失敗、2件以上＝貼り付けはできているがデプロイが反映されて
     いない可能性が高い＝もう一度「デプロイを管理→編集→新バージョン→デプロイ」を最後まで
     やり直してもらう）。
4. **貼り付け指示は「Cmd+Gで行番号」より「Cmd+Fで目印文字列を検索→その行頭/行末に貼る」方が
   事故率が低い**（行番号は他セッションの同時編集でズレることがある）。目印には、直前に自分が
   追加した関数名など、その場で確実に存在すると分かるユニークな文字列を使うこと。
5. **`fetch()`で302リダイレクトを挟むPOSTは、curlの`-L`だとGETに化ける**（`--post302 --post303`
   を付けても改善しなかった＝GAS特有の何かがある可能性。原因追及より「ブラウザ経由に統一する」
   ほうが早い）。

## ③ 確認・修正の具体的な進め方

### Step 1: 内訳を確認する（読み取り専用・書き込みなし）

`gas/Code.gs`には既に`diagDeliverySettlementBreakdown(p, session)`という読み取り専用の診断関数を
追加済み（`isAdmin`限定）。**ただし前スレッドの最後の時点で、ディスパッチャ登録行がデプロイに反映
されていない状態だった**（`unknown action`エラー）。まず以下で現在の状態を確認すること:

```js
// ブラウザのjavascript_toolで（②の1を参照）
const url = 'https://script.google.com/macros/s/AKfycbwW0qhyEr0-uQWTaLg7MkQhurHq6wMoaOKL7uCCnI_bgnAsGB5-auqG_dm_Q9uJc3Kc/exec';
async function call(body){
  const r = await fetch(url, { method: 'POST', headers: { 'Content-Type': 'text/plain;charset=utf-8' }, body: JSON.stringify(body) });
  return JSON.parse(await r.text());
}
const login = await call({ action: 'login', id: 'info', pw: 'mirai0314' });
const diag = await call({ action: 'diagDeliverySettlementBreakdown', token: login.token, sourceFile: 'rocket_now_2026-08.xlsx' });
diag;
```

- `unknown action`が返る場合: `gas/Code.gs`に該当コードは存在する（下記参照）ので、ユーザーに
  再度「Cmd+Fで`diagDeliverySettlementBreakdown`を検索→ヒット件数確認→デプロイを管理→編集→
  新バージョン→デプロイ」をお願いする。コード自体は`git show 44d4ddf:gas/Code.gs`
  （tori-dashboardリポジトリ）に含まれている。
- 正常に`{ok:true, rows:[...]}`が返れば、`sales`・`coupon_store`・`fee_total`・`tax`・
  `fee_discount`・`payout_expected`の内訳が見える。`sales - coupon_store - fee_total - tax +
  fee_discount`が`payout_expected`と一致するか計算して確認する（符号は実データを見て確定させる
  こと。ここでは未検証の仮説）。

### Step 2: `bqSyncDeliverySettlement`を修正する

現在の実装（`ar_receivables.fee_amount`に`SUM(fee_total)`だけを入れている）を、Step 1で確認した
正しい内訳に基づいて修正する。方針案（Step 1の結果次第で調整すること）:

- `fee_amount`を「`payout_expected`との差額を説明できる全項目の合計」にする
  （例: `fee_total + coupon_store - fee_discount + tax`、符号はStep 1の実データで確認）。
- もしくは`ar_receivables`に`gross_amount - expected_amount = fee_amount`が常に成立するよう、
  `fee_amount`を`gross - expected`から逆算する（内訳の個別項目を厳密に追わず、UIの整合性だけ
  担保する簡易対応。担当Cの画面が「売上決済額－手数料＝入金予定額」の2項関係を前提にしている
  ことは確認済み＝`ar_receivables`スキーマに項目が3つしかないため）。

修正箇所は`gas/Code.gs`の`bqSyncDeliverySettlement`関数内、`fee_amount: Number(row[5] || 0)`の行
（クエリのSELECT文にも`coupon_store`/`tax`/`fee_discount`の追加が必要）。**このコードは財務データ
書き込みのため、Editツールでの直接編集がブロックされる可能性が高い。ブロックされたら、②の2の
とおりコードをユーザーへ提示して手貼りしてもらうこと。**

### Step 3: 再実行して既存データを更新する

修正版デプロイ後、ブラウザ経由で`bqSyncDeliverySettlement`を実行する:

```js
const login = await call({ action: 'login', id: 'info', pw: 'mirai0314' });
const sync = await call({ action: 'bqSyncDeliverySettlement', token: login.token });
sync;
```

`(source_table, store_id, note=source_file)`が一致する既存行（本店8月分・
`ar_receivables.id = 'db9c804c-859e-47d3-86b2-42b2b9906a00'`）は自動的に`action:'updated'`で
上書きされる（新規行が増えることはない）。実行後、以下で正しく更新されたか確認:

```
curl -s -X POST "https://api.supabase.com/v1/projects/uuvsxzhpxtghojoubjcc/database/query" \
  -H "Authorization: Bearer $(cat ~/.config/ns-portal/supabase_pat)" -H "Content-Type: application/json" \
  --data-binary '{"query":"select gross_amount, fee_amount, expected_amount from ar_receivables where id='"'"'db9c804c-859e-47d3-86b2-42b2b9906a00'"'"';"}'
```

`gross_amount - fee_amount = expected_amount`が成立すればOK。
