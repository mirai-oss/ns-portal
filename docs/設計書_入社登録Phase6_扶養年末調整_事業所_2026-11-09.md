# 設計書: 入社登録 Phase 6 — 扶養家族・年末調整の入社後フォーム／源泉所得税の Slack 画面／スマレジ事業所の自動作成

作成 2026-11-09（立会い後）。**本番未適用・未デプロイ**（適用は中山さんの承認後）。ハブ側（ns-portal）の設計と実装。nippo 側・Mac 側は別担当が同じ契約（項目名・値）で作る。

## 0. 何が変わるか（1 分で）

| 困りごと | こうなる |
|---|---|
| 入社フォームが長い。扶養や年末調整まで入れさせると入社登録が遅れる | 入社フォームでは**飛ばす**。入社後に本人がマイページの「扶養・年末調整の登録」フォーム（スマレジの画面と同じ並び）で送る。未提出の人には定期リマインド |
| 扶養・年末調整はスマレジ API で書けない | 本人の提出 → 管理システムに保存 → 本部が Slack の「スマレジに反映」を押す → Mac mini の自動操作がスマレジ管理画面に入力 → API（年末調整）／画面（扶養）で照合 |
| 源泉所得税の Slack 画面がスマレジと違って入れにくい | スマレジの「源泉所得税設定を追加」と**同じ 4 項目・同じ文言**のモーダルに（適用開始月・区分・源泉控除対象配偶者区分・源泉控除対象親族の数）。初期値は入社月・甲・本人提出の内容から |
| 管理システムに店舗を作ってもスマレジに事業所が無く、所属の同期が通らない | 店舗管理の「スマレジにも事業所を作る」→ Mac の自動操作が「事業所 → 新しい事業所を作成」に入力 → 作成された事業所 ID を対応表（store_external_mappings）に自動登録 |

守ること: 入社登録の「完了」は従来の 10 項目のまま（扶養・年末調整は**完了を止めない別トラック**）。氏名・住所・生年月日は DB の中だけで Slack には件数と続柄だけ。マイナンバーは預からない（スマレジの本人画面で入力）。自動書き込みのスイッチ（`commute_rules.smaregi_write_enabled`）が OFF の間は、すべて「manual（管理画面で入力）」として記録される。

## 1. 流れ

```
本人（nippo マイページ）── 年末調整フォーム ──→ RPC onboarding_save_year_end ──→ employee_year_end（status submitted）
                     ── 扶養フォーム ────→ RPC onboarding_save_dependents ─→ employee_dependents（0 人なら「扶養なし」）
                                                                       └→ employee_post_join_status（提出状況・リマインド回数）
本部（Slack 親メッセージ「🔄 表示を更新」で「入社後の提出」が 📝 に）
  └ スレッド「📝 本人が…を提出」（op post_join_submitted）→ 「🧾 年末調整をスマレジに反映」「👪 扶養家族をスマレジに反映」
      → RPC onboarding_enqueue_year_end / _dependents → ui_automation_jobs（smaregi_year_end / smaregi_dependents）
      → Mac mini（Playwright）→ スマレジ管理画面 → 結果 → op ui_job_result → 年末調整は API GET で照合／扶養は画面の行数で照合 → synced
  └ 「🧾 源泉所得税」→ モーダル（4 項目）→ RPC onboarding_set_tax_setting → ジョブ smaregi_tax（既存の Mac 操作）→ 照合
cron（承認後）→ onboarding_post_join_remind_trigger → op post_join_remind → 未提出者に Slack DM → LINE の順で「フォームのお願い」（既定 OFF）
店舗管理（nippo）→ RPC smaregi_store_create_request → ジョブ smaregi_store → Mac が /stores/add に入力 → 新しい事業所 ID → RPC smaregi_store_mapping_upsert → #本部-人事 へ通知
```

## 2. DB（`supabase/2026-11-09_onboarding_phase6.sql`・未適用）

| もの | 内容 |
|---|---|
| 表 `employee_year_end` | スマレジの年末調整と同じ列名（household_header_name / household_header_relationship / spouse_flag / estimate_income / retirement_income / handicapped_division / widow_division2 / widow_division / student_flag / salary_payment_report_collection_division）＋提出・反映の状態 |
| 表 `employee_dependents` | 扶養親族 1 人 1 行（name / kana / relationship / birthday / living_together_division / post_code / address / estimate_income / retirement_income / handicapped_division）。再提出で古い行は is_active=false |
| 表 `employee_post_join_status` | 本人ごとの提出状況（year_end_status / dependents_status: pending / submitted / none / synced / skipped）とリマインド回数 |
| `employee_tax_settings` | 列追加 application_ym（YYYY-MM）・spouse_deduction_division（0/1/2） |
| `ui_automation_jobs.kind` | smaregi_year_end / smaregi_dependents / smaregi_store を追加。`ui_job_enqueue` 新版（店舗ジョブは workflow 無し・smaregi_staff_id='store:<店舗id>'） |
| RPC | `onboarding_save_year_end(p_user, p_data jsonb, p_via, p_actor)`／`onboarding_save_dependents(p_user, p_rows jsonb, p_via, p_actor)`／`onboarding_skip_post_join(p_user, 'year_end'|'dependents', p_actor)`／`onboarding_set_tax_setting(p_workflow, p_application_ym, p_tax_category, p_spouse_division, p_dependents_count, p_actor)`／`onboarding_enqueue_year_end(p_workflow, p_actor)`／`onboarding_enqueue_dependents(p_workflow, p_actor)`／`onboarding_post_join_targets(p_days)`／`onboarding_post_join_reminded(p_user)`（service）／`smaregi_store_create_request(p_store, p_contract, p_actor)`／`smaregi_store_mapping_upsert(p_store, p_contract, p_external_store_id, p_name)`（service） |
| ビュー | `onboarding_post_join_v`（本人ごとの提出状況）。`onboarding_workflow_v` は year_end / dependents 列を追加（drop → create。依存ビューなし） |
| 設定 | `onboarding_alerts` に post_join_remind_enabled=false / post_join_remind_days=3 / post_join_repeat_days=3。cron 用 `onboarding_post_join_remind_trigger()`（schedule は承認後に手で） |

切り戻し: `supabase/2026-11-09_onboarding_phase6_rollback.sql`（RPC・ビュー・設定キー・kind を戻す。表と行は残す。rollback 内で検証済み）。

## 6. 仮定・未確認（実機で確かめる）
- 扶養の照合は画面の行数（API に項目なし）。同姓同名の重複追加を防ぐため Mac 側は「同じ名前＋続柄」の行があれば追加しない前提。
- 年末調整の API 照合は `householdHeaderRelationship` などが GET に出ること（公開リファレンスの要約由来。実機で staff_get の yearEnd を確認）。
- 事業所作成はスマレジの必須項目（事業所名・フリガナ・略称・郵便番号・日付変更時間）を埋める。フリガナは店舗名をそのまま入れる（カナ変換は無し）。郵便番号が無い店舗は Mac 側で not_supported にして手動へ。
- 本人フォームの送信直後に Slack スレッドへ出す経路（op post_join_submitted）は nippo から直接呼べない（合言葉を持たない）ため、本部の「🔄 表示を更新」で親に反映され、スレッド投稿はリマインド cron か本部ボタンのときに行う。必要なら DB トリガー＋pg_net で呼ぶ案を次に検討。
