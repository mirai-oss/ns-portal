# 売上内訳の正本を「営業区分別売上」へ — 調査結果と修正案（担当A・2026-11-11・読み取りのみ／修正案は未適用）

## 1. 営業区分別売上の実装仕様（経営ダッシュボード）
- 元データ: `kd_media_daily`（店舗×営業日×媒体の純売上・客数。分析_媒体別日次 → keiei-kd-refresh media_daily）。**媒体＝来店経路（食べログ・フリー・Ring-style・ランチ・各予約サイト等）**であり、食事時間帯そのものではない。
- 分類（app.js `mediaClassOf`）: ①DB_媒体分類シートの設定（媒体→営業区分）が最優先 ②無ければ既定の正規表現: 媒体名が `デリバリ|ロケットナウ|出前` → デリバリー／`ランチ|昼` → ランチ／**それ以外はすべてディナー**。
- POS確定売上との関係: 直近31日で媒体データのある247店日は **全て kd_media_daily の合計＝POS確定売上（差0）**。従って ランチ＋ディナー＝POS が構造的に成立（按分不要）。税抜・値引き後（POS純売上と同じ）。キャンセル・返金・クーポンはPOS純売上に反映済み。営業日は kd の営業日基準。
- デリバリーは別系統: kd_media_daily にデリバリー系の媒体行は0件。経営Dは kd_delivery_daily を媒体「ロケットナウ」として後から加算して表示する。**POS・kd_media_daily とは二重にならない**（POSはデリバリーを含まない・上の差0が根拠）。

## 2. ユーザーの認識「ランチ区分→ランチ、それ以外→ディナー」との差異（推測で直していません）
1. **「ランチ」は時間帯ではなく媒体名**: 媒体名が「ランチ」の売上だけがランチ。昼にフリーで来た客などは「フリー」媒体＝ディナー側に入る。実際、ランチ媒体を持つのは3店（本店・芝・はなれ）のみで、他の店（恵比寿・新橋・鶏武者2店・黒霧屋）は全額がディナー扱いになる。
2. 本店・芝・はなれで、媒体ベースのランチは明細の時間帯ベースのランチより大きい（芝110%・はなれ107%・本店104%）。旧按分値（明細比率）との差は平均+約5,200円・最大+約2.0万円（ランチがある58日。5,000円超は27日）。
3. テイクアウト・外販・EC は `use`（入店用途）が「外販」になるだけで、営業区分（seg）はディナーのまま。現状の直近31日にはテイクアウト媒体の行は無いが、出た場合は「ディナー」に入る（要確認）。
4. DB_媒体分類シートの上書き設定は**DBに無い**（スプレッドシート）。DB側の日報で同じ分類にするには、設定をDBへ移す必要がある（暫定=既定ルールのみ。上書きが有る媒体は日報と経営Dで食い違い得る）。
