## 0. 先に知っておくこと

- SQL・Edge Function・画面を入れただけでは、**何も変わりません**。変わるのは、下の 2 つのスイッチを入れたときです。スイッチは、それぞれ別に承認をいただいてから入れます。
  - スイッチ A: #本部-人事 に金額を出さない（`slack_policy.hide_amount_channels`）。
  - スイッチ B: スマレジにだけある賃金の行を正式登録しない（`employee_change.wage_import_hold`）。
- 賃金 2 段階承認のスイッチ①②には触りません（OFF のまま）。
- 既存の従業員・賃金・口座・申請のデータは変えません。
- Edge Function は 3 つ変えます（`notify-slack`・`onboarding-notify`・`smaregi-sync`）。どれも稼働中なので、デプロイの前に、本番のソースを取り出して「今回の変更以外に差が無いこと」を確かめます。

## 2. スイッチ A: #本部-人事 に金額を出さない（★別途承認）

1. テスト用のチャンネル（#本部-開発システム）だけをスイッチ A に入れて、金額入りのテスト文を 1 通送る。金額が「（金額は管理画面で確認）」になり、ボタンがそのまま動くことを確かめる。確かめたら、テスト用のチャンネルを外す。
2. `hq.jinji` をスイッチ A に入れる（SQL は実行の前に提示します）。
3. テスト従業員の入社登録の親メッセージで「🔄 表示を更新」を押す。賃金の行が「賃金設定済み」になり、金額が消える。

成功の見分け方: #本部-人事 の新しいメッセージに、¥ や「○○円」が 1 つも出ない。

戻し方: スイッチ A の一覧を空に戻す（すぐ戻る）。

そのあと（別途）: 過去のテスト従業員のメッセージを消すか決める → チャンネルの公開設定と参加者を確認 → チーム長の参加。

## 3. スイッチ B: スマレジにだけある賃金の行を正式登録しない（★別途承認）

1. **試し読み（何も書かない）**: 一括取り込みを `dry_run` で実行し、「スイッチを入れたら保留になる行」が何件あるかを見る。結果を報告します。
2. **出発点をそろえる**: いまスマレジにあって管理システムに無い行を、これまでどおりの取り込みで取り込んでおく（nippo の「スマレジの賃金を管理システムへ取り込む」を 1 回）。取り込む前に、1 の件数を見て、取り込んでよいかを確認していただきます。
3. スイッチ B を true にする（SQL は実行の前に提示します）。
4. もう一度、一括取り込みを実行する。「未承認の変更として保留: 0 件」になる。

成功の見分け方: スイッチのあと、スマレジで賃金の行を足しても、管理システムの賃金カードには出ず、従業員一覧の「同期・承認の状況」に「未承認の賃金変更」として出る（確認は、次に実際の変更があったとき）。

戻し方: スイッチ B を false に戻す（すぐ戻る。控えは残る）。
