# 設計書 契約書の自動読み取り（社内情報「物件・契約」）— 2026-10-14

ユーザー要望: 「物件・契約のところに契約書をアップしたら、その契約書の中を読み込んで、賃料・管理会社の名前・更新日などを自動で拾ってきて反映させてほしい」
→ 結論: **できる。重くない**（既存の請求書AI読み取り `invoice-ocr` と同じ仕組み）。担当Cと担当Fの2担当で分けて進める。

## 1. 流れ

```
物件・契約フォーム（ns-info-system）
  ① 契約書PDF/画像をアップロード（既存: info.documents に保存・properties.document_id に紐付け）
  ② アップロード直後に Edge Function contract-extract を呼ぶ（document_id を渡す）
        └ 契約書をClaudeに読ませ、項目＋根拠の抜粋＋要確認点を返す（担当C）
  ③ フォームに自動入力（空の欄はそのまま入力／既に値がある欄は「現在の値 → 読み取り値」を並べて選ばせる）（担当F）
  ④ 人が内容を確認して「保存」（既存の保存処理。properties へ反映）
  ⑤ 更新日が入ったら 期限（info.deadlines）に自動登録（担当F・既存の期限【C】連携）
```

- **勝手に本番データを書き換えない**: AIの結果は「入力の下書き」までで、保存は人が確認して押す（賃料・日付は誤ると影響が大きいため）。
- 同じ契約書で再度読み取っても、保存済みの結果を返すので二重に課金されない（「再読み取り」ボタンで強制再実行）。

## 2. 読み取る項目（properties の列に合わせる）

| 画面の項目（properties列） | 契約書から | 備考 |
|---|---|---|
| 管理会社 `management_company` | 管理会社（管理業者）名 | 貸主と別に書かれている場合のみ |
| 管理会社 電話／担当 `mgmt_phone`／`mgmt_contact` | 同上の連絡先 | 無ければ空 |
| 賃料 `rent` | 月額賃料（整数・円） | 共益費は含めない。税込/税抜は注記で返す |
| 坪数 `tsubo` | 面積（坪）。㎡のみの場合は ×0.3025 | 面積㎡も返す |
| 契約種別 `contract_type` | 普通借家／定期借家 など | |
| 契約日 `contract_date` | 契約日または契約開始日 | 和暦→西暦に変換 |
| 更新日 `renewal_date` | 更新期日（通常は期間満了日） | 明記が無い場合は満了日を入れ「要確認」を付ける |
| 敷金・保証金 `deposit` / 償却 `amortization` | 記載のまま（文字列） | |
| 貸主 `landlord_name`／`landlord_phone` | 貸主（オーナー）名・電話 | |
| （参考・メモ欄へ） | 共益費・更新料・解約予告期間・自動更新・物件所在地・借主名 | 画面で「メモに追記」できる |

- 各項目に**根拠（契約書の該当箇所の抜粋）**を付け、画面で「なぜこの値か」を確認できるようにする。
- **要確認点**（記載が2か所で違う／手書き修正あり／覚書で上書きされている等）を一覧で返す。
- 値の検証（コード側）: 賃料の範囲、日付の形式（YYYY-MM-DD）、期間の前後関係。外れた値は無視して警告に回す。

## 4. 安全・コスト
- **機密**: 契約書の内容は Anthropic の Claude API に送られる（請求書の自動読み取りと同じ方式）。ログには値そのものでなく件数のみ残す。AI窓口(Hermes)からは契約書へ一切アクセスさせない（既存方針のまま）。
- **権限**: 物件・契約の編集権限（`has_edit_perm('property')`）がある人だけが呼べる。
- **コスト**: 1通あたり数円〜十数円程度の見込み（ページ数による）。結果を保存して再利用する。
- **精度**: 手書き・スキャン画質・特約の多い契約書は誤読があり得る。最初の数通で人がチェックし、必要ならプロンプトを調整する。

## 5. 段階
1. （担当C）SQL適用＋Edge Function デプロイ → テスト用契約書で読み取り結果を確認（精度の確認）。
2. （担当F）画面を実装 → 実際にアップロードして確認。
3. 精度が十分であれば、既存の物件（properties）の契約書も一括で読み取って差分を確認（任意）。
