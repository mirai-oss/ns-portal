# 設計案（下書き）: 社員の固定残業代を賃金設定に足す

- これは下書きです。まだ何も作っていません。本番も変えていません。
- 事実の根拠は、同じフォルダの `調査_固定残業代_2026-11-13.md` にあります。
- 人の名前と金額は書いていません。

## はじめに: 言葉の説明

- **基本賃金**: 月給のうち、固定残業代をのぞいた部分。
- **固定残業代**: あらかじめ毎月決まった額で払う残業代。
- **月額固定給与合計**: 基本賃金＋固定残業代。例: 240,000 円＋60,000 円＝300,000 円。
- **含める労働区分**: 固定残業代の中に、どの種類の割増を入れるかのチェック。6 つあります。
- **同期**: 管理システムの賃金を、スマレジ・タイムカードへ送ること。
- **照合**: 送ったあと、スマレジから読み直して、同じになったか比べること。

## 大事な前提（調査で分かったこと）

1. スマレジが覚えているのは、「適用する」「金額」「含める 6 つ」の 3 種類だけです。
2. 写真の「固定残業時間から算出」は、選ぶ項目ではありません。金額を計算して入れるボタンです。スマレジは、時間数を覚えていません。
3. だから「対象の時間数」と「計算のしかた」は、**管理システムだけが持つ記録**になります。もとは雇用契約書です。
4. ふつうの残業（法定時間外）は、いつも固定残業代に入ります。6 つのチェックは「ほかに入れるもの」です。
5. 今の送る処理は、月給を基本賃金だけで送ります。固定残業代のある行をこの形で直したとき、スマレジ側の固定残業代が消えるかどうかは、まだ分かっていません。

## (a) DB に足す項目の案

### 方針

- 今の表 `employee_wage_settings` に、**列を足すだけ**にします。今ある列・行・決まり（一意の索引）は変えません。
- 足す列は、どれも「空でもよい」にします。今ある行は、そのまま残ります。
- 基本賃金は今の `wage` のまま。固定残業代は別の列。合計は列にせず、表示のたびに足します（ずれないように）。

### 足す列（月給の行だけで使う）

| 列の名前（案） | 型 | 意味 |
|---|---|---|
| `fixed_ot_state` | text | 固定残業代の状態。`unknown`＝まだ確認していない／`none`＝なし／`applied`＝あり。**今ある月給の行は `unknown` から始めます** |
| `fixed_ot_amount` | int | 固定残業代の金額（円）。`applied` のときだけ。1 円以上 |
| `fixed_ot_method` | text | 金額の決め方。`direct`＝金額を直接入れた／`from_hours`＝時間数から計算した。管理システムだけの記録 |
| `fixed_ot_minutes` | int | 対象の時間数（分で持つ。30 時間＝1800）。雇用契約書の数字。管理システムだけの記録 |
| `fixed_ot_calc` | jsonb | 時間数から計算したときの材料の控え（所定労働時間・割増率・計算に入れた手当の額・計算結果・端数の扱い） |
| `fixed_ot_incl_statutory_within` | boolean | 含める: 法定内残業 |
| `fixed_ot_incl_midnight` | boolean | 含める: 深夜労働 |
| `fixed_ot_incl_prescribed_holiday` | boolean | 含める: 所定休日労働 |
| `fixed_ot_incl_statutory_holiday` | boolean | 含める: 法定休日労働 |
| `fixed_ot_incl_over45` | boolean | 含める: 月 45 時間超 時間外労働 |
| `fixed_ot_incl_over60` | boolean | 含める: 月 60 時間超 時間外労働 |
| `fixed_ot_confirmed_by`・`fixed_ot_confirmed_at` | uuid・時刻 | 既存社員の確認をした人と時刻（(d) で使う） |

決まり（CHECK）:
- 時給・日給の行では、固定残業代の列はすべて空。
- `applied` のときは、金額が 1 円以上。
- `none`・`unknown` のときは、金額と 6 つのチェックは空。

### スマレジの今の値の控え（新しい表）

- 名前（案）: `wage_smaregi_snapshots`。
- 中身: 人・契約・スマレジの賃金設定の番号・区分・適用開始日・賃金・「適用する」・固定残業代の金額・含める 6 つ・読んだ時刻。
- 使い道: 差の一覧（(d)）と、送ったあとの照合（(c)）。
- スマレジから読んだ値を入れるだけの表です。賃金の正式な表には触りません。

### 関数の直し方

- `hr_save_wage` は、いろいろな所から 8 個の引数で呼ばれています。形を変えると、全部が一度に動かなくなる心配があります。
- そこで、新しい関数 `hr_save_wage_v2` を作ります。引数に `p_fixed`（固定残業代のまとまり）を足します。
- 今の `hr_save_wage` は残して、中で `hr_save_wage_v2` を「固定残業代は触らない」で呼ぶだけにします。古い入口（Slack・LINE・契約コピー）は、そのまま動きます。
- 古い入口から新しい月給の行ができたときは、`fixed_ot_state` を `unknown` にします。`unknown` の月給は、スマレジへ送りません（(c)）。
- ほかに直す関数:
  - `onboarding_wage_rows_norm`・`onboarding_wage_apply`（入社時の控えに固定残業代を通す）
  - `hr_pay_change_request`・`hr_pay_change_review`・`approval_finalize_wage`（申請の中身に固定残業代を通す）
  - `employee_change_trg_wage`（履歴に固定残業代の前後を残す）
  - 見張り 3 つ（`onboarding_wage_direct_guard`・`employee_change_pay_guard`・`approval_wage_target_guard`）。今は 6 つの列だけで「中身の変更かどうか」を見ています。固定残業代の列を足さないと、固定残業代だけの変更がすり抜けます。
  - `wage_external_changes` の種類に「固定残業代の違い」を足す（`kind` の決まりを広げる）。
- 既存の SQL ファイルは直しません。日付つきの新しいファイルと、戻すファイルを作ります。

### 金額のチェック（入れまちがいを防ぐ）

- 合計（基本賃金＋固定残業代）を、保存の前に必ず画面に出します。
- 「基本賃金の欄に合計を入れてしまう」まちがいを防ぐため、固定残業代が基本賃金より大きいときは、確認を出します。
- 時間数から計算した金額と、入れた金額がちがうときは、差を出します（止めはしません。契約書どおりの金額が正しいので）。

## (b) 画面 5 か所の表示と入力の案

### 共通の見せ方

月給の行は、いつも 3 行で見せます。

```
月給（2026 年 12 月から）
  基本賃金            240,000 円
  固定残業代           60,000 円（30 時間分・含める: 深夜労働）
  月額固定給与合計    300,000 円
```

- 固定残業代が「なし」の人は、「固定残業代 なし」「月額固定給与合計 240,000 円」と出します。
- まだ確認していない人は、「固定残業代 未確認（スマレジと照合中）」と出します。合計は出しません（まちがった合計を見せないため）。
- この文を作る関数を 1 つ作ります（案: `wageLines(row)`）。今は 9 か所で別々に文を作っているので、先にまとめます。Slack 側は `wageLine` の 1 か所を直します。

### 入力欄（月給を選んだときだけ出す）

スマレジの「賃金設定を編集」と同じ並びにします。

1. 給与形態（時給・日給・月給）
2. 適用開始（年・月）
3. 基本賃金（円）
4. 固定残業代 □ 適用する
5. 固定残業代の金額（円）と、［時間数から計算する］ボタン
6. 対象の時間数（時間・分）← 管理システムだけの欄。雇用契約書の数字
7. 固定残業代に含めるもの: □法定内残業 □深夜労働 □所定休日労働 □法定休日労働 □月 45 時間超 時間外労働 □月 60 時間超 時間外労働（［すべてチェック］）
8. 月額固定給与合計（自動で計算して表示。入力はできない）

- ［時間数から計算する］は、スマレジと同じ式にします。
  （基本賃金＋計算に入れる手当）÷ 所定労働時間 × 対象の時間数 × 割増率。
  所定労働時間と割増率は、スマレジの設定を読んで最初から入れておきます（変えられる）。
  端数の扱いは、テスト従業員でスマレジと同じ答えになるか確かめてから決めます。

## (c) スマレジ連携の案

### API でできること（これを使う）

| すること | API | 送る・読む項目 |
|---|---|---|
| 読む | `GET /staffs/{staff_id}` の `wageApply[]` | `fixedOvertimeWageFlag`（適用する）・`fixedOvertimeWage`（金額）・`fixedWage…Flag` 6 つ |
| 新しく入れる | `POST /staffs/{staff_id}/wage_apply` | `division:2`・`effectiveDate`・`wage`・`fixedWage{ amount, rules[] }` |
| 直す | `PUT /staffs/{staff_id}/wage_apply/{id}` | 同じ |

### API でできないこと

- 計算方法・対象の時間数（スマレジに項目が無い。画面にも保存されない）。→ 管理システムだけで持つ。
- 固定残業代を「外す」送り方（仕様書に書かれていない）。→ テスト従業員で確かめる。

### Playwright で補うこと

- **書く**: 補いません。固定残業代は API で書けます。
- **読む**: 予備として、今ある「読むだけ」のジョブに、給与設定ページの隠し欄（`data[Staff][WageApply][N][fixed_…]`）を読む 1 行を足せます。API の読み取りと画面の値が同じかを、もう 1 つの目で確かめる用です。最初は作らず、API の実測で困ったときだけ作ります。

### 送る流れ（1 行ごと）

1. **送る前の見張り**
   - 月給で `fixed_ot_state` が `unknown` の行は、送りません（「確認が終わっていません」と返す）。
   - 既存社員の止め（(d)）が有効な人も、送りません。
   - 直す（PUT）ときは、先にスマレジの今の行を読みます。管理システムが知っている前回の値と違っていたら、送らずに止めます（だれかがスマレジを直接直した印。上書きしない）。
2. **送る**
   - `applied`: 基本賃金＋`fixedWage`（金額と、チェックした区分）。
   - `none`: 基本賃金だけ。スマレジ側に固定残業代があった行を「なし」に直すときの送り方は、実測の結果で決めます。
3. **読み直して照合**
   - もう一度 `GET /staffs/{id}` で読みます。
   - 比べる項目: 給与形態・適用開始・基本賃金・適用する・固定残業代の金額・含める 6 つ（全部で 11 項目）。
   - **全部同じときだけ「同期済み」にします。** 1 つでも違えば「エラー」にして、どの項目が違うかを残します。
   - 今の `wage_push` は、送って成功の返事が来たら同期済みにしています。ここを「読み直してから」に変えます。
4. **控えを更新**: 読み直した値を `wage_smaregi_snapshots` に入れます。

### 先に確かめること（テスト従業員で・スマレジへの書き込みなので別途の承認が要る）

1. 固定残業代のある月給の行を、`fixedWage` なしで直したら、固定残業代は消えるか・残るか。
2. 固定残業代を外す送り方。`rules` を空にできるか。
3. 送る側の `statutoryOvertime` が、読む側の「法定内残業」のチェックに当たるか。
4. ［時間数から計算する］の答えが、スマレジのボタンの答えと 1 円まで同じか（端数）。
5. 本番の API が、固定残業代の項目を実際に返すか（これは読むだけ）。

### 取り込みの向き（スマレジ → 管理システム）

- `staff_get`・`wage_pull`・`wage_pull_all` が、固定残業代の項目も読むようにします（読むだけ）。
- 照合の部品（`_shared/wage-reconcile.ts`）が、固定残業代も比べるようにします。違いは `wage_external_changes` に「固定残業代の違い」として残します。
- 取り込みは今までどおり、管理システムにある行を上書きしません。

## (d) 既存社員の差異の一覧と、自動同期の止め方

### 今の状態（調査 §5）

- 月給の人は 13 人（社員 7・店長 3・チーム長 2・本部 1）。月給の行は 17 行。全部「同期済み」で、送る待ちは 0 行です。
- 基本賃金は、比べられた 12 人すべてで、スマレジの 10 月の給与結果と同じでした。
- 固定残業代は、管理システムに 1 件も入っていません。スマレジの 10 月の給与結果では 4 人にありました。
- 確認が要る人が 4 人います（A さん〜D さん。調査 §5.4）。とくに A さんは、11 月の給与結果で固定残業代が 0 になっています。

### 止め方（3 段。上から順に。影響の小さい順）

**段 1（今日・変更なし）**: 本部に「社員の月給は、確認が終わるまで管理システムで保存・修正・削除・『管理システムに合わせる』・契約コピーをしない」と伝える。今は送る待ちが 0 行なので、だれも触らなければ 1 行も送られません。

**段 2（SQL 1 本・承認のあと）**: DB に「月給の止め」の見張りを足す。
- 新しい設定: `app_settings` の `employee_change.monthly_wage_sync_hold`（true で止める）。
- 新しいトリガー（表 `employee_wage_settings`）。止めが true のとき、月給の行について次を断ります。
  - 新しい行を入れる（スマレジからの取り込みは通す）
  - 金額・適用開始日を変える
  - 「同期済み」から「送る待ち」に変える
  - 行を消す
- 除くもの: 入社手続き中の人。確認が終わった人（解除の一覧に入れた人）。時給・日給の行。
- なぜ止まるか: 送る処理は「送る待ち」の行しか送りません。月給の行が送る待ちになれなければ、どの入口からも送られません。
- 断ったときの文: 「社員の月給は、スマレジとの差の確認が終わるまで、変更と同期を止めています」。
- 弱い所: 画面の「削除」は、先にスマレジ側を消す作りです。DB の見張りだけでは防げません。段 3 で防ぎます（それまでは、月給の行の削除ボタンを画面で隠す）。
- 戻し方: 設定を false にする。

**段 3（Edge Function の修正・配置のとき）**: `smaregi-sync` の `wage_push`・`wage_update`・`wage_delete` の入口でも、同じ設定を見て月給を送らないようにする。固定残業代の送信を作るときに、一緒に入れます。

使わない案: 今ある `wage_approval_required` を ON にする方法。時給の人も全員が申請制になります。承認のあとは今までどおり基本賃金だけが送られます。月給の同期は止まりません。

### 差異の一覧の作り方

**その 1（今すぐ作れる・仮の一覧）**: DB にあるデータだけで作ります。
- 比べるもの: 管理システムの月給（`employee_wage_settings`）と、スマレジの給与結果（`sf_payroll_sync` の基本給・固定残業代）。
- 分かること: 基本賃金の違い／スマレジ側に固定残業代があるか・その金額／月ごとの変化（先月あって今月ない、など）。
- 分からないこと: 含める 6 つのチェック／これから適用の行の中身／対象の時間数。

**その 2（正確な一覧・読むだけの API）**: スマレジの設定を 13 人ぶん読んで、`wage_smaregi_snapshots` に入れます。スマレジへは書きません。
- 一覧の列: 人／適用開始／管理システムの基本賃金／スマレジの基本賃金／スマレジの固定残業代（適用する・金額・含める 6 つ）／差の種類／確認の状態。
- 差の種類:
  1. 基本賃金が違う
  2. スマレジに固定残業代がある（管理システムは未登録）
  3. スマレジにだけ行がある／管理システムにだけ行がある
  4. 適用開始が違う
  5. 契約が違う（別の契約に移った人の月給）
  6. 先月の給与結果と、今の設定が合わない（消えた・増えた）
  7. 対象の時間数が未入力（雇用契約書の確認待ち）

### 確認の進め方（1 人ずつ）

1. 一覧を見て、スマレジの値を「正しい今の値」として管理システムに写します（スマレジ → 管理システムの向きだけ。逆には送りません）。
2. 本部が、雇用契約書を見て「対象の時間数」と「含めるもの」を入れます。
3. 社長が、1 人ずつ内容を見て「確認済み」にします（基本賃金・固定残業代・合計・時間数）。
4. 確認済みになった人だけ、止めを外します（解除の一覧に入れる）。その人の行は `fixed_ot_state` が `applied` か `none` になり、次の変更から、固定残業代つきで送れます。
5. 全員が終わったら、止めの設定を false に戻します。

- この確認では、だれの賃金も変えません。「今の値を正しく写す」だけです。
- スマレジの値と雇用契約書が違っていた人は、写さずに止めたままにして、社長に知らせます（直すのは賃金変更の申請で。別途の承認）。

## (e) 社長承認との関係

### 今の決まり（そのまま使う）

- 入社のとき: アルバイト・パートは承認なし。**正社員は社長の承認**。雇用区分が分からないときは確認待ち（`onboarding_wage_rule`）。承認・却下は社長だけ。マスターでは代用できない。社長本人の確定＝承認。
- 賃金の変更: **本部確認 → 社長の最終承認**（`approval_routes` の `wage`）。自分の申請は自分で承認できない。
- 承認のあとで、はじめて正式な賃金の表に入り、スマレジへ送られます。

### 固定残業代の乗せ方

- 固定残業代は「賃金の一部」として、同じ申請・同じ承認に乗せます。新しい種類の申請は作りません。
- 入社時の控え（`onboarding_wage_requests.wage_rows`）と、変更申請の中身（`profile_change_requests.payload`）に、固定残業代の項目を足します。
- 社長が見る承認の画面には、基本賃金・固定残業代・月額固定給与合計・対象の時間数・含めるものを、全部出します。
- 固定残業代だけを変えるとき（金額・時間数・含めるもの）も、賃金の変更として社長の承認が要ります。
- 判定に足す決まり（案）: アルバイト・パートの人に固定残業代を付けようとしたら「確認待ち」にする（ふつうは無いので、入れまちがいの疑い）。
- 承認のあとに送る流れは (c) のとおり。照合で違いが出たら、「同期済み」にせず、本部に知らせます。

### スイッチの今の状態（大事）

- 入社時の賃金承認（`onboarding_wage_approval.enabled`）＝ OFF。
- 賃金変更の直接登録の禁止（`wage_approval_required`）＝ OFF。
- 2 段階承認のルート（`approval_routes.wage.active`）＝ OFF。
- つまり今は、本部・社長・マスターが画面で月給を保存すると、承認なしでスマレジへ送られます。
- 「社員の賃金変更は社長承認後に反映」を本当に効かせるには、この 3 つを ON にする必要があります。ON は、これまでの決まりどおり、別途の明示の承認で行います。
- 順番の案: 先に (d) の止めを入れる → 固定残業代の機能を作る → 既存社員の確認を終える → 3 つのスイッチを ON → 止めを外す。

### 既存社員の最初の取り込みの扱い

- 賃金は変えないので、「賃金変更の申請」には当たりません。
- ただし、社長が 1 人ずつ「確認済み」にしてから正式な値にします（(d) の 3）。記録（だれが・いつ・どの値を確認したか）を残します。

## (g) 依頼主に決めてもらうこと

1. **A さんの 11 月の賃金**: 11 月から固定残業代をなくす変更でしたか。そうでなければ、スマレジの 11 月の行に固定残業代を入れ直す必要があります（スマレジの画面で、人が直す。11 月分の給与の確定の前に）。
2. **B さん・C さん（12 月開始の行）と D さん（契約が変わった人）**: スマレジの画面で、固定残業代が正しく入っているかを、だれが確かめますか。
3. **月給の止め（(d) の段 2）を入れてよいですか。** 入れる日と、止めている間に月給の変更が必要になったときの扱い（スマレジの画面で人が直す／止めを 1 人だけ外す）。
4. **対象の時間数**: 雇用契約書に、固定残業の時間数は書いてありますか。人によって違いますか。管理システムでは、時間数を必ず入れる（必須）にしますか。
5. **含める労働区分**: 契約では、固定残業代にどれを含めますか（深夜・休日・月 45 時間超・月 60 時間超）。会社で 1 つの型に決めますか。人ごとに選びますか。
6. **金額の決め方**: 契約書の金額をそのまま入れますか。時間数から計算した金額を使いますか。計算と契約書の金額が違うとき、どちらを正しいとしますか。
7. **超過分の割増**: 固定残業代を超えた残業代は、スマレジが自動で足します（「固定残業代超過分」）。この計算を、社労士にも確かめてもらいますか。月の途中の入社や欠勤のとき、固定残業代を減らすかどうかの決まりはありますか。
8. **既存社員の確認**: 社長が 1 人ずつ「確認済み」にする形でよいですか。まとめて 1 回の確認にしますか。
9. **承認のスイッチ 3 つ**（入社時の賃金承認・直接登録の禁止・2 段階承認）を ON にする時期。固定残業代の機能ができて、既存社員の確認が終わったあとでよいですか。
10. **契約のコピー（移籍・兼務）**: 月給と固定残業代を、新しい契約へ自動でコピーしますか。月給はコピーせず、毎回入れ直して社長の承認を通しますか。
11. **Slack の小窓**: 月給の固定残業代は、Slack では入れず、管理システムの画面だけにしてよいですか。
12. **テスト従業員での実測（段階 2）**: スマレジのテスト従業員に、月給と固定残業代を書いて消す確認をしてよいですか（本物の社員の賃金には触りません）。
13. **手当**: 今回は固定残業代だけです。ほかの手当（スマレジの「自動手当」）は API で書けないので、別の話として後にしてよいですか。「月額固定給与合計」に手当は入れない、でよいですか。
