# 手順書：勤怠の ○× ボタン（Slack）— 店長が確認・修正申請、中山さんが承認（2026-11-07）

> 毎朝の勤怠取込のあと、打刻がおかしい勤務が **勤怠確認チャンネル** に届きます（全店舗共通・2026-11-07 ユーザー決定）:
> ①1 時間以内の勤務 ②12 時間以上の勤務（休憩除く） ③翌朝 6 時以降の退勤 ④退勤打刻なし ⑤休憩が長すぎる（合計 2 時間超）／休憩の終了打刻なし（＋24 時間超え）。
> さらに、**スマレジ・タイムカード側で直接修正された勤務**も「✏️ 直接修正されました」として届きます（毎朝の取込で前回の値と比べて検知。「○ 確認した」で消し込み）。
> 店長が「○ 合っている」か「× 修正する」を押し、修正は中山さんの Slack（DM）に承認依頼が届きます。承認すると管理システムの勤怠実績に反映されます。

## できあがりの姿

```
⏰ 勤怠確認
⚠️ 勤怠確認
11/6（金）　鳥一代 本店
Aさん　10:00−翌10:00（24時間0分・休憩 15:00−16:00）
24時間超え（要確認）。打刻は合っていますか？
[ ○ 合っている ]  [ × 修正する ]
```
- **○ 合っている** → メッセージが「✅ 合っている（店長名・日時）」に変わる。
- **× 修正する** → 小さな入力画面が開く（正しい出勤・退勤の日時、休憩1・休憩2 の開始/終了、理由）→「承認を依頼」。
  - 休憩欄には今の休憩が入った状態で開く。直すなら時刻を変える。休憩を無しにするときは「この勤務は休憩なしにする」にチェック（日時欄は消せないため）。
  - 勤務時間は「退勤−出勤−休憩」で計算される。
  - 店長側のメッセージは「📝 修正を申請しました … 承認待ち（マスター）」に変わる。
  - 中山さんの DM に「🙋 勤怠修正の承認依頼 [✅ 承認] [❌ 却下]」が届く。
- **✅ 承認** → 管理システムの勤怠実績（人件費日次・勤怠記録）が修正後の時刻に変わり、両方のメッセージが「✅ 反映済み」に変わる。
- **❌ 却下** → 両方のメッセージが「❌ 却下」に変わる（何も変わらない）。

**押せる人**
- ○ / ×: その店舗の店長（TENCHO は担当店舗のみ）、TEAM・HQ・CEO。それ以外は本人だけに「権限がありません」と出る。
- 承認 / 却下: **マスター（中山さん）だけ**。

**反映の範囲**
- 承認すると ①管理システム（ハブ）の勤怠実績 → ②**スマレジ・タイムカードの勤務実績**（API「勤怠更新」で出勤・退勤を書き換え。休憩・遅刻/早退フラグは今の値を引き継ぐ）の順に直ります。両方のメッセージに「✅ スマレジの勤務実績にも反映済み」と出れば完了。
- スマレジ側に失敗したとき（例: 給与を締めた後の月＝409、実績が無い）は「⚠️ スマレジへの反映に失敗: 理由」と出ます。その場合だけスマレジの管理画面から手で直してください。管理システム側は反映済みのまま「手修正ロック」で守られます（翌朝の自動取込で戻らない）。
- スマレジ側に成功した行はロックを外します（以後はスマレジが正。翌朝の同期で同じ値と正しい概算人件費に置き換わる）。

## フォームから申請する（勤怠追加・勤怠修正）

URL: **https://mirai-oss.github.io/ns-portal/kintai.html**（ポータルの「申請」グループにも「⏰ 勤怠の追加・修正」として出ます。ポータルにログインしてから開く）

1. 「➕ 勤怠追加」（打刻が無かった日）か「✏️ 勤怠修正」（ある勤務を直す）を選ぶ。
2. 店舗を選ぶ → その店舗の従業員が出る。名前の一部を打つと絞り込める。
3. 勤務日・出勤・退勤（出勤より早い時刻なら翌日扱い）・休憩1/2（任意・開始と終了をセット）・理由を入れて「承認を依頼する」。
4. 中山さんの Slack DM に「🙋 勤怠追加／修正の承認依頼 [✅ 承認][❌ 却下]」が届き、勤怠確認チャンネルにも「📝 申請あり」が出る。
5. ✅ 承認 → 管理システム（人件費日次・勤怠記録）に反映 → スマレジの勤務実績へ（修正は更新、追加は新規登録）。両方のメッセージに「✅ スマレジの勤務実績にも反映済み」と出れば完了。失敗したら理由が出るので、その場合だけスマレジの管理画面から直す。
- 申請できる人: その店舗を管理できる人（店長=担当店舗・TEAM/HQ/CEO）と本人。承認はマスターだけ。
- 同じ人・同じ日の申請が承認待ちのうちは、次の申請は出せない。

- 毎朝 08:00 の勤怠取込（GitHub Actions `smaregi-attendance-sync`）の後段で自動で届く。対象は「昨日」の勤務だけ。
- 直接修正の検知は、同じ取込の「当月分の再取込（毎日）」「前月分（1〜10 日）」で比べるので、その範囲の修正なら翌朝に届く。手修正ロック中の行と、まだ退勤していなかった行は対象外。

## 仕組み（読まなくてよい）
- 表 `sf_attendance_alerts`（状態 open → confirmed / fix_requested → approved / rejected。kind=short/long/extreme/late_leave/no_clock_out/break_long・reasons[]）。
- 表 `sf_attendance_smaregi_changes`（直接修正の検知。before/after/diff_text・open → acknowledged。RPC `sf_attendance_change_ack`）。
- 表 `sf_attendance_requests`（フォーム申請。kind=add/fix・pending → approved/rejected。RPC `sf_attendance_form_staff`（店舗の従業員）・`sf_attendance_request_submit`・`sf_attendance_request_decide`（追加は labor_cost_daily に `req:<id>` を仮キーに新規行＋ロック、スマレジ POST 後に実績 ID を入れてロック解除））。EF `attendance-request`（JWT で申請者を特定 → RPC → マスター DM＋kintai.check）。状態を変えるのは RPC だけ（`sf_attendance_alert_confirm` / `sf_attendance_fix_request` / `sf_attendance_fix_decide`）。
- 承認後のスマレジ書き戻し: EF `smaregi-attendance-fix`（契約は店舗のマッピング（黒霧屋=11/1 から LiveGate）で決め、`employee_smaregi_links` のスタッフ ID → 現在の実績を GET → `PUT /timecard/shifts/{shift_result_id}` division=result。出勤・退勤・休憩1/2 は申請の値、遅刻/早退フラグは今の値）。
- 休憩: 同期が `breakStartTime1〜breakEndTime2` を `labor_cost_daily.break_start_1…` と `break_minutes` に取り込む（SQL ③）。結果は `sf_attendance_alerts.smaregi_sync_status`（synced / failed＋理由）。
- `labor_cost_daily` に `manual_fixed_at` 等の列と BEFORE UPDATE トリガ `labor_cost_daily_keep_manual_fix`（手修正済みの行は同期の upsert で打刻の値が戻らない。解除は `manual_fixed_at` を NULL にする）。元の値は `orig_*` 列に残る。概算人件費 `smaregi_estimate_cost` は時間に比例して付け替え。
- 送信は `notify-slack`（無変更）。受け取りは `slack-interact`（署名検証 → `user_slack` → RPC → `notify-slack update`）。
