# 調査レポート: D-7 diniiリアルタイム注文データ取得手段の検討

作成: 2026-08-31 ／ 担当D ／ 状態: **公開情報での調査完了・結論は「dinii社への直接問い合わせが必要」**

## 背景

店舗カメラ人流分析・5分アラート機能（`docs/設計メモ_店舗カメラ人流分析_2026-08-27.md`§6.2）の実現に必要な「diniiの注文情報をリアルタイム（数十秒以内）に取得する手段」があるかを調査した。

## 1. dinii公式のAPI・Webhookの有無

**結論: 公開されているAPI・Webhookは見当たらない。**

- 公式FAQで「他のPOSシステムとの連携は可能ですか？」に対し**「他のPOSシステムとは連携不可。ダイニーPOSレジのみ連携可能」**と明記
- BI連携の実体験記事（note）によれば、外部データ連携の実例は**HTTP APIではなくFTP経由のCSVファイル転送**（リアルタイム性なし・エラー内容も分からない不便な方式、と実装者自身が言及）
- 料金プラン別のAPI提供有無は公開情報からは確認できず

**未確認（要問い合わせ）**: 非公開の法人向けAPI・パートナー限定APIの有無、契約変更でAPIが開放されるか

## 2. 管理画面のリアルタイム注文一覧の有無

**結論: 存在する可能性は高いが、外部から自動取得しやすい形式かは未確認。**

- 公式に「注文内容がリアルタイムでキッチンディスプレイに表示。提供が遅れているメニューが一目で把握できる」という、まさにNStyleがやりたいことに近い機能が店舗内向けに存在する
- 「ダッシュボードNOW」（2020年追加）というリアルタイム業績・注文状況表示機能もある

**未確認（要実機確認）**: 更新頻度・一覧表示の形式（Playwrightでポーリングしやすい構造か）、PCブラウザで見られるか専用端末限定か

## 3. 同業他社の状況（参考）

| サービス | リアルタイムWebhook等 |
|---|---|
| スマレジ | **あり**（公式プラットフォームAPI・イベント通知） |
| Airレジ | 一部あり（2025年8月〜「データ連携API」。プッシュ型かは不明） |
| トレタ | 第三者向け公開APIは未確認（POS間の限定パートナー連携事例のみ） |

→ 業界的に「リアルタイムWebhook」自体は珍しくないが、diniiが同水準かは断定できない。

## 4. 3案の評価

| 案 | 実現性・評価 |
|---|---|
| **A. 公式API/Webhook** | 現状不明・**要問い合わせ**。公開情報ではFTPバッチ転送が中心と見られ、リアルタイムAPIは無い可能性が高い |
| **B. 管理画面をPlaywright等でポーリング** | 技術的には可能（自社の得意分野）。ただし①dini利用規約でスクレイピングが禁止されている可能性②年40回超という高頻度UI更新による保守コスト③無断実施のリスク、の3点が懸念 |
| **C. キッチンプリンター印刷データの分岐** | 技術難度が最も高い（店舗ごとの機材介入・ESC/POS解析・保守リスク）。**今回は非推奨**（設計メモの想定どおり） |

## 5. 結論・推奨アクション

**最重要の前提課題**: 店舗スタッフが「提供済み」操作をしていないため、**diniiから注文データが取れても「いつ提供されたか」の情報がそもそも無い**。これは連携方式（A〜C）とは独立した運用課題で、どの案を選んでも避けて通れない。

**推奨する次のアクション**:
1. **dinii社サポート窓口へ正式に問い合わせる**（「注文データをリアルタイム・数十秒以内で外部取得する手段=API/Webhookはあるか」を明確に確認。契約変更・パートナー契約の要否も含めて）— 問い合わせ先: https://dinii.jp/contact/
2. 契約店舗の管理画面へ実際にログインし、「ダッシュボードNOW」等の画面構成・更新頻度を目視確認（ログイン情報のあるMac miniでの実施が現実的）
3. dinii利用規約（https://info.dinii.jp/）で自動アクセス・スクレイピングに関する条項を確認（案Bを検討する場合の前提）
4. **経営判断として**: 「5分アラート」がリアルタイム必須の要件かどうかを再確認していただきたい。dinii側にAPI/Webhookが無い場合、**5分アラートは見送り、「翌朝バッチで前日の提供遅延傾向を分析するレポート」に代替する案が現実的**（diniiの手動CSVダウンロード機能だけで実現でき、規約・技術両面のリスクが大幅に下がる）
