## 1. 担当H: コックピット本体（新設レーン）

### H-1: DBを作る（Phase 1前半）

- `supabase/2026-08-31_cockpit.sql` を新規作成（**既存SQL編集禁止・冪等: create table if not exists / create or replace**）
- テーブル7つ: `ck_devices`・`ck_sessions`・`ck_tasks`・`ck_instructions`・`ck_events`・`ck_approvals`・`ck_comments`。列は `要望まとめ_AI開発コックピット_2026-08-31.md` の「主要エンティティ」どおり＋調査レポート§3の補足（`agent_name`・`changed_files jsonb`・`ck_tasks`は`bigint generated always as identity`で連番→画面表示`TK-<番号>`）
- 状態値のcheck制約: タスク=`backlog/ready/in_progress/review/waiting_human/blocked/done/cancelled`、セッション=`running/waiting/blocked/idle/stopped/stale/disconnected`、承認=`pending/approved/rejected`
- `ck_events` は `hq_task_activity`（`2026-08-10_hq_tasks.sql:251`）を雛形に（created_at desc索引も同様に）
- **RLS必須**: 全テーブルで有効化し、select/insert/update/delete すべて既存の **`portal_is_master()`** を使う（新しい判定関数を作らない）。**anonキーは公開されているためRLSが唯一の防御**（受け入れ条件）
- seed: `ck_devices` に mac-mini / macbook の2行を投入
- あわせて `2026-08-31_cockpit_seed.sql` を作成: WORKLOG冒頭「📍現在の状況」「📋 全体バックログ・統合版」から**現在の実タスクを `ck_tasks` に初期投入**（ラウンド5の即割当5件＝E-4/E-5/F-9/A-7/A優先順、設計ゲート5テーマ=waiting_human、ユーザー作業待ち（cron-job.org追加等）=assignee_name'中山'/waiting_human、D-7/D-8等）。**これで初日から「今進んでいるもの」が画面に出る**
- 完了したらSQL実行はせず**ユーザーに依頼**（§3-①）。実行確認後にH-2の実データ表示を確認

### H-2: cockpit.html（Phase 1後半・UIと手動タスク管理）

- モック `docs/mockups/NStyle_AI開発コックピット_UI_v2.html` のデザイン・画面構成をそのまま実装（左メニュー: 開発ダッシュボード／全タスク／AI・PC稼働状況／指示書作成／実行・変更履歴／担当別／接続・設定）
- 認証は `export.html:63-112` の一式（`nsportal_session_v1`・`api`/`authed`/`refresh`/`fetchMe`/`fn`・`?embed=1`対応）を**そのままコピー**（supabase-js導入禁止・キー名変更禁止）。`fetchMe()`後に `is_master` でなければ「このページはマスター管理者専用です」を出して停止
- Phase 1で動くもの:
  - KPI 6枚（進行中・残タスク・確認待ち・今日完了・稼働端末・ブロック中）= `ck_tasks`/`ck_sessions` から集計
  - LIVEカード = `ck_sessions`（heartbeatはPhase 2からなので、当面は「最終更新◯分前」表示。**last_heartbeat_atが90秒超→stale・10分超→disconnectedのバッジは最初から実装**）
  - カンバン（これから進める/進行中/あなたの確認待ち/完了）+ 全タスク画面 = `ck_tasks` のCRUD（追加・編集・状態変更・進捗%・担当変更。モーダルはモックどおり）
  - 実行・変更履歴 = `ck_events`（タスク操作時に画面からもinsert）
  - 担当別 = assignee_name別の一覧（担当A〜G・司令塔・中山）
  - 指示書作成 = モックのジェネレーターを実装し、生成した指示書を `ck_instructions` に保存＋「貼り付け文」も生成（既存ラウンド指示書§5の書式: 「あなたは担当◯です。…を実行してください」）
  - ヘッダー: WORKLOG（GitHub）への常設リンク・最終同期時刻・手動「↻同期」
  - ロードマップ/優先順位カードはPhase 1では `ck_tasks`（category='roadmap'等）で簡易表示（凝らない）
- スマホ表示（モックの@media）も確認（ユーザーは外出先スマホから見る想定）

### H-3: heartbeat受け口とCLI（Phase 2）

- Edge Function `cockpit-ingest`（新規・H専任）: POSTで `{token, device_key, session_key, agent_name, repository, branch, git_head, changed_files, status, task_no, progress_percent, message, event_type, blocker, current_file}` を受け、`app_secrets` の `cockpit_ingest_token` と照合→ `ck_devices`/`ck_sessions` upsert・`ck_events` insert・task_no指定時は `ck_tasks` の進捗/状態も更新（service role使用）
- トークン: `app_secrets` への投入SQL（新規日付入りファイル・値はプレースホルダにして**実値はユーザーがSQL Editorで直接入れる**。トークン実値をリポジトリ・文書に書かない）
- CLI `tools/ai-cockpit`（bash・実行権付き）: サブコマンド `start / progress / blocked / done / note / hb / idle`。設定は `~/.ns-cockpit/config`（URL・トークン・device_key。`.gitignore`は不要=リポジトリ外）。git情報（repo名・branch・HEAD・`git status --porcelain`の件数と先頭20ファイル）は実行時に自動採取。**20秒未満の連続送信は間引く・送信失敗は黙って捨てる**（開発を止めない）
- 動作確認は自分のセッションで実施（`ai-cockpit start --task TK-1 --agent 担当H` → 画面に出るか）
- ユーザー作業（§3-②）の手順書を作る: `手順書_コックピット_トークン設定_2026-08-31.md`（リンク必須ルール適用: Supabase SQL EditorのURL・コピペするコマンドを全部書く）
- 運用開始: 全レーンの次ラウンド指示書に「作業の節目で `ai-cockpit` を打つ」を1行追加するのは**司令塔の仕事**（Hは完了報告だけ）

## 4.5 運用ルール（2026-08-31ユーザー指示で確定）

タスク完了の反映は**2経路とも有効**:
1. **画面主導**: 中山さんがダッシュボードで完了にする → Lark通知＋unblocksの後続タスク自動着手可
2. **会話主導（代理完了）**: 中山さんが「やったよ」とスレッドで報告 → そのAIセッションが `ai-cockpit list` → `ai-cockpit done --task TK-x --message "ユーザー報告により完了"` を即実行（本人に画面操作をさせない）

二重完了は受け口側で検知し通知を1回に抑制（同一状態への再doneはLarkに流れない）。このルールは鉄則#9（`実装指示書_並行開発の担当分け_2026-08-24.md`）にも記載済み。
