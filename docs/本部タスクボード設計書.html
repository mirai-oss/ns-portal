「毎月の精算処理、いまどこで止まってる？」に3秒で答えられることをこのボードの一番の仕事にします。タスクを流れ（サブタスク）で持ち、いま誰の番か・何日止まっているかを常に表に出す設計です。

1いただいた要望 → 設計への対応

要望どう実現するか
毎日・毎週・毎月タスク「繰り返しテンプレート」から毎朝自動で今日の分を生成（毎日／毎週=曜日指定／毎月=日付指定／単発）
分解タスク（担当者・期限が別）タスクの中にサブタスク（工程）。工程ごとに担当者・期限・完了記録。親の進捗は工程の消化率
マニュアルを入れる添付リンク欄に「📘 マニュアル」タイプ。フェーズ3cのマニュアル機能とID連携（それまでは任意URL）
注意事項タスクに専用の「⚠️ 注意事項」欄（黄色枠で常に目立つ位置に表示）
添付写真タスク・工程どちらにも写真添付（スマホ撮影対応。チェックシートと同じ仕組みを流用）
URL・ID/PWの紐付け添付リンク欄に「🔗 URL」「🔐 ID/PW」タイプ。ID/PWは値を持たず社内情報管理の金庫を指すリンク（開ける人は金庫側の権限で制御）
どこで・誰で止まっているかカードに「いま: 工程名（担当者）＋停止日数」を常時表示。繰り返しタブでは月次タスクを表形式で一覧
期限前アラートタスクごとに「◯日前・前日・当日・超過」を設定 → 毎朝の自動チェックで通知
通知先を変えられるアラートごとに宛先（担当者・作成者・追加の人）と手段（アプリ内・Lark）を設定
複数法人を1箇所でタスクに法人ラベル（LiveGate／SK／N-Style／トーホー）。1つのボードに全部出して、法人チップで絞り込み

5「止まっている」の判定ルール

感覚ではなく機械的に判定して、色とバッジで出します。

● 順調期限まで余裕あり
→
● 注意いまの工程が期限2日前
／今日が期限
→
● 停滞工程の期限超過
／3日以上動きなし
  • 「いま誰の番か」＝ 最初の未完了工程の担当者。カード・一覧・通知すべてこの人を表示します。
  • 「動きなし」＝ 工程完了・コメント・写真追加のどれも無い日数。

6データ設計（ハブSupabase・7テーブル）

テーブル役割・主な列
hq_task_templates繰り返しのひな形。タイトル／法人／頻度（毎日・毎週[曜日]・毎月[日]・単発）／期限オフセット／注意事項／作成者
hq_tasks実際のタスク（毎月分など1回ごとに1行）。テンプレID／法人／期限／状態（未着手・進行中・確認待ち・完了）／注意事項
hq_task_steps工程。タスクID／名前／担当者（users.id）／期限／完了日時・完了者／並び順
hq_task_links添付リンク。種類＝url／manual（マニュアルID）／credential（社内情報管理の金庫ID。値は持たない）
hq_task_photos写真。タスクIDまたは工程ID／保存先（チェックシートと同じバケット）／撮影者
hq_task_alertsアラート設定。タイミング（-3日・-1日・0日・超過）／宛先（担当者・作成者・指定ユーザー配列）／手段（アプリ内・Lark）
hq_task_activity履歴。誰が・いつ・何をしたか（完了／コメント／写真／差し戻し）
設計判断の変更提案: 要件定義書v2では「日報の既存tasksを拡張」としていましたが、工程・繰り返し・アラートを持たせると別物になるため、本部タスクは専用テーブル群（hq_〜）で新設に変更します。日報の現場タスクはそのまま無変更（壊さない）。人は同じusers.idなので「担当者ごとの全タスク横断」は問題なくできます。承認いただければ要件定義書を更新します。

7アラートの配信のしくみ

  • 毎朝6時の自動チェック（既存のGAS時計トリガー方式を流用）が、今日作るべき繰り返しタスクの生成と、アラート条件の判定を行う。
  • 通知手段は2段階: アプリ内通知（ポータルと日報のベル。全員に届く）＋Lark（社員向け。既存の日報Webhook基盤を流用）。メール・LINEは後から同じ仕組みに追加可能。
  • 超過アラートは解消されるまで毎朝再通知（1日1回まで。うるさくしない）。

8権限

役割できること
マスター・社長・本部全部（テンプレ作成・タスク編集・完了・削除・アラート設定・全法人閲覧）
チーム長ボード閲覧＋自分が担当の工程の完了・コメント・写真（テンプレ編集は不可）
店長以下ボード自体が非表示。ただし工程の担当者に指名された場合のみ、そのタスクだけ通知が届き完了操作ができる

9確認したいこと（4点だけ）

  1. 「日報tasks拡張→専用テーブル新設」への変更（第6章の囲み）でOKですか？
