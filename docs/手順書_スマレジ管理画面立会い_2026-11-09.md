# 手順書: スマレジ管理画面の立会い（入社登録 Phase 3 の画面確認）

作成 2026-11-09。**中山さんの作業は「ログイン」と「編集ボタンを押す」だけ**（合計 10〜15 分、間を空けてよい）。画面の読み取り・設定ファイルの作成・検証は Claude Code が行います。

## 0. なにをする日か（1 分で分かる説明）

スマレジ・タイムカードの **API では書けない 4 項目**（交通費・源泉所得税・個別 Web 給与明細・メールアドレス）を、Mac mini のブラウザ自動操作（Playwright）で入力する仕組みは、もう作ってあります。
でも「画面のどこに何があるか（ボタンや入力欄の場所＝セレクタ）」は、**実際の画面を見ないと分かりません**。いまは全部「未設定」になっていて、未設定の操作は **何も書かずに止まる**ようになっています。

立会いでは、実際の管理画面を **読むだけ** で構造を調べ、`config/smaregi-ui-selectors.json`（Mac mini の `ns-daily-import` の中）を埋めます。埋めたら、使い捨ての従業員で「読むだけ → 書いて → API で読み直して一致」を確認します。

## 2. 当日の流れ（番号順。★ が中山さんの操作）

**時間帯**: 朝 06:30〜07:30（CSV 取込）と重ならない時間。目安 30 分。

1. **Claude Code**: 使い捨て従業員を 1 人作る（nippo の入社登録で「テスト 立会い」など。スマレジ側にも従業員ができる）。従業員 ID をメモ。
2. **Claude Code**: Mac mini で偵察スクリプトを実行する。
   ```bash
   cd /Users/mirai/ns-daily-import && node tasks/smaregi-ui-recon.js <従業員ID>
   ```
   ブラウザ（自動操作用。ふだんの Chrome とは別）が開き、ログイン → 従業員の詳細ページへ進みます。
3. ★ **中山さん（必要なときだけ）**: もし「2 段階認証」や「確認コード」の画面で止まったら、その画面にコードを入れてください。止まらなければ何もしなくて OK。
   - 成功の見分け方: 従業員の詳細ページ（氏名や所属が見える画面）が出る。
4. **Claude Code**: 画面構造を JSON に保存（`logs/ui-recon/…json`。値は伏せてあります）。見出し・入力欄・ボタンの一覧から、4 項目がどこにあるかを読み取ります。
5. ★ **中山さん**: 「交通費」の **編集を開くボタン** を押してください（偵察スクリプトはボタンを押さないため）。開いたら「開いた」と言ってください。
   - 成功の見分け方: 支給形態（勤務回数ごと／月額／勤務日数ごと）・金額・上限・適用開始日 の入力欄が見える。
6. **Claude Code**: 開いた状態で、もう一度構造を読み取る（同じコマンド。URL が変わっていればその URL を渡す）。**保存は押しません**。
7. ★ **中山さん**: 同じように「源泉所得税」「個別 Web 給与明細」「メールアドレス」の編集画面も順に開いてください（そのたびに Claude Code が読み取ります）。保存せずに閉じて OK。
8. **Claude Code**: 読み取った結果から `config/smaregi-ui-selectors.json` を埋める → `npm run test:ui`（モックのテスト）が通ることを確認 → 使い捨て従業員で **読むだけジョブ**（`smaregi_read`・dry_run）を 1 件流し、読めた値を Slack スレッドで確認。
9. ★ **中山さん（承認）**: 「使い捨て従業員に対して 1 回だけ書き込みテストをしてよいか」を確認します。OK なら Claude Code が `commute_rules.smaregi_write_enabled` を **一時的に** true にして 4 項目を順に書き、スマレジ GET で一致を確認したら **false に戻します**。
10. ★ **中山さん**: 最後に、スマレジ管理画面で使い捨て従業員を削除してください（API に削除が無いため）。Claude Code 側は nippo・ハブの使い捨てデータを消して 0 件を確認します。

## 4. 立会いで分かったあと（Claude Code 側）

1. JSON を埋めて ns-daily-import をコミット・push（セレクタは秘密ではありません）。
2. 読むだけジョブで確認 → 承認後に書き込みテスト（§2-9）。
3. 結果を `docs/入社登録_進捗一覧_2026-11-09.md` と WORKLOG に記録。**上限の単位**は `app_settings.commute_rules.cap_unit` に入れる（`month` か `per_shift`）。
4. その後の有効化（いずれも承認後）: `.env` に `SMAREGI_UI_JOBS=1` → `commute_rules.smaregi_write_enabled=true`。

## 5. うまくいかないとき

| 症状 | 対処 |
|---|---|
| ログイン画面で止まる（ID/パスワードが違う） | `.env` の `SMAREGI_ID`/`SMAREGI_PASSWORD` は毎朝の CSV 取込で使えているので通常は通る。通らなければ中山さんがその画面でログイン |
| 2 段階認証 | その場で中山さんがコード入力（§2-3） |
| 従業員ページが 404 | URL の形が違う → 中山さんに従業員一覧から該当者を開いてもらい、その URL を Claude Code が使う |
| 編集がポップアップ（モーダル）で開く | 開いた状態で読み取れば OK。JSON の `open` にそのボタンを入れる |
| 偵察スクリプトがブラウザを開かない | Mac mini の Playwright は `node_modules` にあり（1.61）。`npm run test:ui` が通るか確認 |
