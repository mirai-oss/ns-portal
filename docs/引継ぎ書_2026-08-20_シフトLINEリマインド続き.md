## 4. 絶対に守ること（鉄則。従来から変更なし）

1. **課金・カード登録・Vercel操作は絶対にClaude自身で実行しない**
2. **`info`スキーマへの書き込み・RLS変更、および既存テーブルへのALTERは全般的にClaude自身では実行できない**（安全ガードでブロックされる）。SQLを提示してユーザーのSupabase SQL Editorで実行してもらう。**1回のRunで1文でもエラーになると全体がロールバックされる**ので、大きなSQLは慎重に
3. **git fetch/pull してからpush**。nippoは並行編集が起きやすいので**必ず`git fetch`で他セッションの先行コミットを確認**してから作業する（今回42コミット分の衝突が発生し手動修復した実績あり。詳細はWORKLOG参照）
4. **SQL実行はManagement API＋curl経由のみ**（`POST https://api.supabase.com/v1/projects/{ref}/database/query`）
5. **既存の本番Edge Function（`line-webhook`・`smaregi-sync`・`hq_generate_today`等）を書き換えるときは、必ずバイナリから完全なソースをUTF-8で復元し、diffで「既存部分が一切変わっていないこと」を確認してからデプロイする**。今回`line-webhook`の改修はこの手順で安全に行った（`WORKLOG.md`参照）。実在の応募者・従業員に影響する本番関数なので、雑な再構築は絶対にしないこと
6. **書き込み禁止**: `manual_items`／`checklist_*`／`hq_*`（法人切替を除く）／日報系のテーブル／`info.*`（読み取りは自由）
7. **WORKLOG.md（ns-portal側）を作業のたびに更新する**
8. **本番データを直接テストに使わない**。テストは使い捨てユーザー（Auth Admin APIで作成→削除）で行い、作業後は関連データを完全に削除して0件を確認する。**LINEの実機テストは特に注意**（実際にLINEでメッセージを送受信するテストになるため、使い捨てユーザーでもLINE公式アカウントとの実際のやりとりが発生する。テスト用の合言葉・連携も必ず後始末する）
