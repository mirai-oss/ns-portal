# 手順書: インフォマート受発注API 利用申込み（D-9）

作成: 2026-08-31 ／ 担当D ／ 対象: ユーザー（インフォマート社への申込み作業）

## 目的

発注明細（今は店舗別・日別の合計金額だけ）を、品目・数量単位まで自動でBigQueryへ取り込めるようにするため、インフォマートの「受発注API」を使えるようにする。これが今回の会計自動化（インフォマート発注明細→BQ・MF証憑添付・振込CSV自動生成）の最初の一歩。

## 前提条件（すでに満たしています）

- インフォマートの「BtoBプラットフォーム受発注」で**「買い手」として既に利用中**（現在`ns-daily-import`の`infomart-siire`タスクが仕入データを取得している、まさにその契約）
- 有料プランに加入済み・API利用が可能なことは確認済み（2026-08-31ユーザー回答より）

## 申込み手順（インフォマート公式FAQ「API連携の申込手続きについて【受発注】」より・2026-08-31時点で確認済み）

### ①インフォマートの担当者へ連絡する

オプション機能「API連携」の申込みが必要です。まだ申し込んでいなければ、**普段やり取りしているインフォマートの営業・サポート担当者へ連絡**し、「受発注のAPI連携を利用したい」と伝えてください。担当者から「API利用申込書」が送られてきます。

- 担当者の連絡先が分からない場合は、インフォマート公式の問い合わせ窓口から: https://www.infomart.co.jp/corporate/contact_im.asp

### ②「API利用申込書」を提出する

①で送られてきた申込書に記入し、指示された方法で提出してください（提出方法は担当者から案内があります）。

### ③「API連携設定申込み」フォームに入力する

②の提出後、以下のGoogleフォームから技術的な接続設定を申し込みます。

**フォームURL**: https://docs.google.com/forms/d/e/1FAIpQLSdjLS-IP-qHyWFqtmnAefI9imm4ZTcVsfZzniBnTl5_RMZiAA/viewform

- **検証環境・本番環境どちらも申込み可能**です（開発時は検証環境、実運用開始時に本番環境、と2回申し込む形になる見込み）
- 申込み完了後に届く「受付メール」に**申込番号**が記載されます。**このメールは必ず担当D（Claude）が見られる場所（このリポジトリのdocsフォルダや、共有しているクラウドストレージ等）に保存しておいてください**。後続の接続作業（APIキー・認証情報の設定）で必要になります

### ④インフォマートの担当者へ完了連絡する

③のフォーム送信後、①の担当者へ「申込みが完了した」旨を連絡してください。ここでAPIの接続情報（クライアントID・シークレット等の認証情報）が発行される見込みです。

## ⑤ここまで完了したら教えてください

上記①〜④が完了し、認証情報（APIキー等）が発行されたら、担当Dへ共有してください。共有いただき次第、発注明細取込（BigQuery `stg_infomart_order`）の実装に着手します。

## （参考・担当D作業メモ）申込み完了までの先行作業

設計書どおり、申込み・認証情報の発行を待つ間に以下を並行で進めます:

- **受発注APIリファレンス**（上記リンク）を確認し、実際に取得できるエンドポイント・項目を把握済み。主なエンドポイントは以下の3段構成（非同期バッチ方式）:
  1. `POST /ordApi/order/trade/download/request`（ダウンロード依頼。`batch_id`を受け取る）
  2. `POST /ordApi/order/trade/download/check`（処理状況確認。`batch_flg`・`record_count`）
  3. `POST /ordApi/order/trade/download/get`（実データ取得。`trade_id`・`order_day`・`member_code_self`・`member_name_partner`・`delivery_date`・`prod_lot_qty`・`trade_total`・明細行=`item_name`・`prod_unit_code`・`prod_lot_total`）
  - マスタ取得用に`POST /ordApi/order/master/download/buy/get`（`item_id`・`item_name`・`catalog_id`）もあり、品目マスタの正規化に使えそう
- 上記を踏まえた**BigQuery`stg_infomart_order`スキーマ案**（認証情報受領後、実際のレスポンスで確定させる前提の暫定案）:
  | 列名 | 型 | 由来 |
  |---|---|---|
  | trade_id | STRING | 取引ID（主キー） |
  | order_day | DATE | 発注日 |
  | delivery_date | DATE | 納品日 |
  | member_code_self | STRING | 自社コード（店舗特定に使えるか要確認） |
  | member_name_partner | STRING | 取引先名 |
  | item_id / item_name | STRING | 品目（マスタAPIと突合） |
  | prod_unit_code | STRING | 単位 |
  | prod_lot_qty / prod_lot_total | NUMERIC | 数量／明細金額 |
  | trade_total | NUMERIC | 取引合計金額 |
  | synced_at | TIMESTAMP | 取込日時 |
  - ⚠`member_code_self`だけでは店舗（NStyleの各店）を直接特定できない可能性がある。認証情報受領後、実データで店舗の識別方法（自社コードが店舗単位で発行されているか、他の項目で店舗が分かるか）を確認する
- `ns-daily-import`（Node/Playwright基盤）か GitHub Actions のどちらから日次投入するかは、認証方式（APIキー/OAuth等）が判明してから決定（RESTのバッチ方式なのでPlaywright不要・単純なfetchで済む可能性が高い）
