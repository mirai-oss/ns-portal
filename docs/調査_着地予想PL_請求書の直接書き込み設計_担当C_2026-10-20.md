# 調査: 請求書 → pl_entries 直接書き込みの設計（担当C・2026-10-20）

設計書 v2 §10 (C)。読み取り調査と設計案のみ（本番は変更していない）。

## ① 今の流れ（現状）と問題
- 請求書の承認画面（invoices.html）→ Edge `pl-fee-reflect` の `confirm`（科目×補助×月×店舗の割り振り）→ 記録 `invoice_pl_reflections`（正）→ GAS `writePlFee`（tori-dashboard）が DB_PL とPL管理システムに追記 → BQ stg_pl → Edge `keiei-kd-refresh` の `autoSyncFromStgPl` が `pl_entries` に取り込み。
- 問題: GAS側は「全行読む→全消し→書き戻し」で排他が無く、10/8朝以降に補助科目(G列)・請求書ID・勘定科目がずれた（9月は自動行の41/55行が不一致）。10/20に LockService(DocumentLock) と、`invoice_pl_reflections` からの作り直し(`rebuild_pl_rows`)を実施済み。
- 追加の事実: 補助科目セルが『補助　外部連携:<請求書ID>』という“補助科目＋冪等キー”の複合文字列で、ずれると両方が壊れる。

## ② 直接書き込みの設計案
- 書き先: `pl_entries`（列: year_month / store_id / item / category / amount / memo / sub_item / source / source_key / deleted_at ...）。
- 関数: 既存 `pl_entries_bulk_upsert(p_rows, p_mode='upsert', p_actor)`。service_role は `_pl_scope` で kind='service' になるため Edge から呼べる。
- 行の形（1反映行=1店舗×科目×補助×月）:
  - `source` = `自動｜請求書`（固定）／`memo` = `自動｜請求書`
  - `source_key` = `inv:<請求書ID>:<反映ID(invoice_pl_reflections.id)>:<store_id>`（冪等キー。同じキーなら upsert で更新）
  - `item` = MFの勘定科目名のまま／`sub_item` = MFの補助科目（外部連携タグは持たせない）／`category` = PL_ITEM_CAT（plSeisanGuessCat_と同じ。未登録科目は O）
  - `store_id` = 店舗マスタID（『本部』= 7750652c-… も可）
- **modeは `upsert` を使う**（`replace_source` は source×年月 単位で全削除するため、請求書行を月ごと丸ごと消してしまう。再生成のときだけ使う）。
- 取り消し（unconfirm・請求書削除・差し戻し）: `pl_entries_delete(ids)`（deleted_at）。履歴は `pl_entries_history` に残る。
- 二重防止: source_key が一意。confirm の再実行・retry は同じ source_key で更新になる。

## ③ autoSyncFromStgPl との境界（二重計上防止）
- 現状 `autoSyncFromStgPl` は source が `自動｜スポット人件費` / `店舗間移動` / `自動｜仕入高差額調整` を無視している。ここに **請求書由来の `自動｜<科目>`（GASが書く memo）と `自動｜請求書`** の扱いを足す。
- 切替手順（案）: (1) pl-fee-reflect に“直接書き”を追加（旧GAS書き込みと並走せず、フラグ `pl_direct_write` で切替）(2) 切替日に、GASの writePlFee を止める（pl-fee-reflect からの呼び出しをやめる）(3) DB_PL上の請求書由来行（memo『自動｜<科目>』＋UUIDタグ）を repairPlAutoRows 系で除去 → autoSync が差分を検出して pl_entries 側の旧 source 行を削除 (4) 『自動｜請求書』を autoSync の無視リストに追加 (5) 過去月は `invoice_pl_reflections` から `自動｜請求書` として一括生成（rebuild_pl_rows の移植）。
- 精算書ルート（『自動｜精算書』・運営委託費）は別ルートのまま（GAS同期）。今回は対象外。

## ④ 追加で必要なもの / 注意
- pl-fee-reflect の `confirm` / `unconfirm` / `retry_sheet_sync` / `rebuild_pl_rows` を pl_entries 書き込みに置き換える（担当C）。
- 『本部』の経費（例: 支払手数料/Mostfun ¥165,000）は store_id = 本部 で書く。
- 切替前にバックアップ（pl_entries_export）を取る。
- 広告媒体（食べログ等）の行は、広告管理DB側の内訳（別資料『広告費パネル→広告DB』）と二重にならないよう、実績の正本はここ（A2確定）。
