# 設計書: 事業所別の賃金・交通費の取り込み（案・未実装）2026-11-18

## 0. 現状（調査結果）
- 管理システムは、事業所別の賃金を持てる（employee_wage_settings.store_id。賃金カードで「◯◯だけ」を選んで登録できる）。
- 交通費も、店舗ごとの金額を持てる（employee_commute_settings.scope='per_store'・store_amounts）。
- 食い違いの原因は、**スマレジにだけある事業所別の行が、承認ルールで「未承認」として保留されている**こと。
  管理システムの賃金・交通費の入力欄がないことではない。
- 交通費は、スマレジから**読み取って取り込む処理がない**（書く側は ui_job 経由）。そのため、管理システムに記録が無い人がいる。
- 表示（2026-11-18 適用済み）: 「同期・承認の状況」に給与形態と事業所名を出すようにした（金額は出さない）。

## 1. 賃金: 保留中の事業所別の行を、承認で正式に取り込む（案2）
### ルール（変えない）
- 賃金の追加は、本部が確認 → 社長が最終承認（自己承認禁止）。スマレジの値を、勝手に正式な賃金にしない。
### 動き
1. 「同期・承認の状況」の「未承認の賃金変更」の行に、**［取り込む申請を作る］**ボタンを足す（本部・社長・マスターだけ）。
2. 押すと、賃金の変更申請（既存の payWageRequest／承認の流れ）を1件作る。内容はスマレジの値（給与形態・事業所・金額・適用開始日）。
   - 申請を作った時点では、スマレジにも管理システムにも書かない（正式な賃金は変わらない）。
3. 本部の確認 → 社長の最終承認で、employee_wage_settings に store_id つきで登録する。
   - スマレジに同じ行が既にあるので、**スマレジへは再送しない**（反映済みの印だけ付ける。smaregi_wage_apply_id を控えから引き継ぐ）。
4. wage_external_changes は status='approved'・request_id を記録して閉じる。
5. 金額違い（amount_changed）は、「スマレジに合わせる（管理システムを直す）」と「管理システムに合わせる（スマレジを戻す）」の2択を、承認の画面で選ぶ。削除（deleted）も同様。
### 変更箇所
- SQL（新規・日付つき）: wage_external_changes から申請を作る関数 hr_wage_external_request(p_id)。承認後の反映は、既存の承認処理に「反映済みの印」だけ足す。
- 画面（nippo）: 「同期・承認の状況」のボタン。賃金カードの申請表示に事業所名。
- Edge Function: 変更なし（再送しない作りにするため）。
### 検証
- ロールバック付きテスト: 申請作成 → 承認 → store_id つきの行ができる／再送されない／控えが approved になる。
- 本番は、1人（寺岡）だけで試し、金額が一致することを確認してから、残りに広げる。

## 2. 交通費: スマレジの交通費を読み取って取り込む（案3）
### 前提の確認が必要（実装前に1つ調べる）
- スマレジ・タイムカードのAPIで、交通費の設定（適用時期・支給形態・事業所別の金額・上限）を**読めるか**。
  読めない場合は、既存の ui_job（画面操作）の読み取り版を作る（読み取りだけ・書き込まない）。
### 動き
1. 読み取り専用の処理（smaregi-sync の commute_pull。賃金の wage_pull と同じ形）。値は employee_commute_settings に**直接書かず**、控え表 commute_external_changes に「未承認」で記録する（賃金と同じ保留の考え方）。
2. 「同期・承認の状況」に、「未承認の交通費変更（事業所・支給形態・適用開始）」を出す。
3. 賃金と同じ［取り込む申請を作る］→ 承認 → employee_commute_settings（scope='per_store'・store_amounts）に登録。スマレジへは再送しない。
4. 交通費は金額が変わると給与に直結するため、**取り込みの承認は社長**（賃金と同じ扱い）。
### 変更箇所
- SQL（新規）: commute_external_changes（控え）・記録関数・申請作成関数。
- Edge Function: smaregi-sync に commute_pull（読み取りのみ）を追加（デプロイは本番取得 → 差分確認 → 承認後）。
- 画面: 「同期・承認の状況」の交通費の行。通勤カードに「スマレジの設定を確認」ボタン。

## 3. 対象外（確認）
- スマレジの「営業時間帯別」の賃金（画面の「すべての営業時間帯」）。管理システムでは持たない。使っている人がいる場合は、別途設計する。

## 4. 順番と費用
1. 賃金（案2）→ 2. 交通費の読み取り可否の確認 → 3. 交通費（案3）。
各段階で、本番適用の前に確認をもらう。最短で進める場合は、1 を先に実装し、2・3 は並行して調べる。
