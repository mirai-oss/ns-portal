# 実装指示書: 担当B — スマレジ登録スタッフの一括招待機能（2026-09-02）

作成: 2026-09-02 ／ 担当D実行スレッドが、ユーザーからの直接依頼を受けて作成。**あなたが担当B（`nippo/index.html`専任）であればこの指示書に従って着手してください。**

## 背景

ユーザーから「鳥一代本店の昨日のアルバイト人件費がおかしい」との報告を受け担当Dが調査した結果、**PL人件費のAPI連携（`labor_cost_daily`）が実際にはポータルアカウントを持つ人しか対象にできておらず、スマレジに登録されている在籍中の実従業員141人のうち、ポータル連携済みはわずか25人（未連携121人・約86%）**という重大なギャップが判明した（担当Aへは`API_LABOR_COST_FROM_YM_`を一旦無効化する緊急対応を別途依頼済み・対応完了）。

ユーザーへ状況を報告したところ、**「121人分のポータル連携を、一括招待の仕組みを新規で作って進めたい」**との明確な依頼を受けた。全員の連携が完了次第、PL人件費のAPI切替を再度有効化する予定。

## 現状の実装（`nippo/index.html`・壊さないこと）

- **`adminSmaregiView()`**（該当行を`grep -n "async function adminSmaregiView"`で確認）: スマレジに登録されている全スタッフの一覧を表示する画面。既に「スマレジ登録スタッフ」画面として存在し、各行に未連携なら「連携する」ボタン、連携済みなら「アプリ連携済」バッジが出る
- **`smaregiInviteDo(sendEmail)`**: 1人ずつ、役職チップ・所属店舗チップ（複数選択可）・有効期限を選んで、`smaregi-sync` Edge Functionの`action:"invite"`を呼ぶ（`staff_id`・`role`・`store_ids`・`days`・`send_email`を渡す）。成功すると招待URL（メール送信 or リンクコピー）が返る
- **バックエンド（`ns-portal/supabase/functions/smaregi-sync/index.ts`）は変更不要**: `action:"invite"`は既に1回の呼び出しで1人分の招待を発行できる仕組みなので、フロント側から複数回呼び出せば一括処理が実現できる（新しいEdge Functionアクションを追加する必要はない）

## 今回作ってほしいもの: 一括招待UI

`adminSmaregiView()`（スマレジ登録スタッフ画面）に、以下を追加する:

1. **未連携スタッフの行にチェックボックスを追加**（連携済みの行にはチェックボックス不要）。画面上部に「すべて選択」「選択解除」ボタン
2. **選択中の人数を表示する固定バー**（例: 「12人選択中」）＋「まとめて招待する」ボタン。1人も選ばれていない間は非表示 or 無効化
3. **「まとめて招待する」を押すと、既存の役職チップ・所属店舗チップ・有効期限（`smSel`の1人版と同じUI）を出す**。ただし今回は「選択した全員に同じ役職・同じ所属店舗を一括で適用する」という設計でよい（元々同じ店舗・同じ役職の人をまとめて選ぶ運用を想定）。役職や店舗が人によって違う場合は、ユーザーが選択をグループ分けして複数回に分けて実行すればよい（1回の一括操作＝1つの役職×1つ以上の店舗、という制約で十分。無理に人ごとに個別設定できるUIまでは今回作らなくてよい）
4. **送信実行**: 選択された`staff_id`ごとに、既存の`action:"invite"`を順番に（もしくは少数ずつ並行）呼び出す。**送信は`send_email:false`（リンク発行のみ）をデフォルト推奨**——121人分をいきなり一斉メール送信すると、Resend側のレート制限やメールアドレス未登録者の扱いで失敗が混ざりやすいため。発行された招待リンクの一覧をその場で確認・コピーできるようにし、実際に本人へどう渡すか（LINE配布・現場貼り出し等）は運用側に委ねる設計が安全
   - 「メールでも送りたい」という要望が出た場合は、`send_email:true`にしてスマレジにメール登録済みの人だけ対象にする、といった拡張は次フェーズで検討でよい
5. **結果表示**: 成功・失敗を人ごとに一覧表示する（既に連携済みだった＝409エラーになるケース、スマレジ側にメール未登録のケース等、失敗理由も分かるように。**無言で一部だけ失敗させない**という既存の全社ルールに沿う）
6. 招待リンクの一覧は、CSV/コピー等でまとめて持ち出せるとなお良い（必須ではない。時間があれば）

## 注意・ゲート

- 既存の1人ずつの招待フロー（`smaregiInviteDo`）は変更・削除しない。新しいUIは追加のみ
- 121人という規模のため、Edge Functionへの呼び出しを一気に並列実行しすぎるとスマレジAPI側のレート制限に当たる可能性がある。**逐次実行、または少数（5件程度）ずつの並行実行**を推奨
- 本番反映前にユーザーへ動作確認（使い捨てデータでのテストが難しい機能のため、実際に数名分でテストしてから全体展開するなど、慎重に進めてよい）
