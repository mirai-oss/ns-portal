# 引継ぎ書: マネーフォワードAPI連携（2026-08-27・担当C）

請求書メール管理（`docs/引継ぎ書_2026-08-24_請求書メール管理Phase1完了.md`）の延長として、マネーフォワード クラウド会計との実際のAPI連携を実装した。**この文書だけ読めば全体像・使い方・次にやることが分かる**。

---

## 1. できるようになったこと

- 請求書メール（入金メールも）から、AIの提案や過去の仕訳履歴をもとに**マネーフォワードへ仕訳登録**できる
- 複合仕訳（振替伝票・1仕訳に複数の借方/貸方セット）にも対応
- 仕訳登録と同時に、**メールの添付ファイルをマネーフォワードの証憑としてそのまま添付**できる
- 本部タスクの工程と請求書を紐付けておくと、仕訳登録と同時に**その工程が自動で完了**になる
- **複数の事業者（有限会社トーホーエージェンシー・株式会社N-Style）**を切り替えて登録できる
- 一覧・メール詳細に「💰会計処理済み」バッジが出る

## 3. マネーフォワードAPIの正体（ハマりどころ込み）

- **APIホストが2つに分かれている**: OAuth（`/authorize`・`/token`）は`api.biz.moneyforward.com`。会計リソース本体（勘定科目・仕訳・証憑）は**別ホストの`api-accounting.moneyforward.com`**。ここを間違えると`NOT_FOUND`が出続ける（実際に一度混同して不具合になった）
- **OAuth登録は`developers.biz.moneyforward.com`ではない**: ドキュメントサイトにログイン機能は無い。実際の登録は、ログイン済みの「[アプリポータル](https://portal.biz.moneyforward.com/)」内「アプリ開発」→「新規登録」から行う
- **技術サポートは原則やっていない**が、**OpenAPI仕様書（YAML）は正確・完全**。仕様が分からなくなったら`https://developers.api-accounting.moneyforward.com/v3/openapi.yaml`を取得して`grep`するのが一番早い（サポート問い合わせより速い）
- **主要エンドポイント**（すべて`api-accounting.moneyforward.com`）:
  - `GET /api/v3/accounts` — 勘定科目一覧（補助科目込み）
  - `GET /api/v3/journals?start_date=...&end_date=...&per_page=...&page=...` — 仕訳一覧（**日付は登録済みの会計期間内でないとエラー**。当期は`4/1〜`、前期`4/1〜3/31`と確認済み）
  - `POST /api/v3/journals` — 仕訳登録。body: `{journal:{transaction_date, journal_type:"journal_entry", branches:[{debitor:{account_id,value,...}, creditor:{...}, remark}, ...]}}`。**branchesは複数渡せる＝複合仕訳が組める**（例:「買掛金1000/手数料500(部門A)+手数料500(部門B)」は「買掛金500/手数料500(A)」「買掛金500/手数料500(B)」の2branchesとして表現）
  - `POST /api/v3/vouchers` — 証憑添付。body: `{journal_id, voucher_files:[{file_name, file_data(base64)}]}`。スコープ`mfc/accounting/voucher.write`が必要（後から追加したので既存連携先は再認可が必要だった）
  - `GET /api/v3/departments`は**今回付与したスコープでは403**（別スコープが必要）。部門一覧は代わりに仕訳履歴から実際に使われている部門をユニーク抽出して代用している
- **会計期間をまたぐ日付の自動判定**: 実登録はせず検証エラーのみで確認したところ、期間外の日付を指定してもエラーにならなかった＝**`transaction_date`から自動でその期に振り分けられている可能性が高い**（100%の確証は実登録でしか取れていない）
- **refresh_tokenはローテート式（使い捨て）**: 同時に2つのAPI呼び出しがどちらもリフレッシュを試みると片方が失敗する。`_shared/mf.ts`は失敗時に少し待ってDBを再読み込みし、もう一方が更新した最新トークンを使うフォールバックを持つ。**呼び出しは可能な限り直列にする**のが安全（`invoices.html`側もsuggest→accountsを直列にしている）

## 4. 複数事業者（テナント）対応の仕組み

- `mf_oauth_tokens`は1事業者=1行（`id`が事業者キー、`label`が表示名）。現在: `default`＝有限会社トーホーエージェンシー、`nstyle`＝株式会社N-Style
- 新しい事業者を追加するとき: 認可URLの`state`パラメータに`tenant|<新id>|<表示名（URLエンコード）>`を入れて発行する。ユーザーがその事業者を選んで許可すれば、`mf-oauth-callback`がその`id`で行を作る
- `mf-journal`の全アクションは`tenant_id`をbodyで受け付ける（省略時`default`）。`list_tenants`アクションで連携済み事業者一覧が取れる
- `invoices.html`は連携済み事業者が2つ以上あれば、仕訳作成の最初に選択画面を出す

## 5. mf-journal のアクション一覧（API仕様）

呼び出し方は共通: `POST https://uuvsxzhpxtghojoubjcc.supabase.co/functions/v1/mf-journal`、`Authorization: Bearer <ユーザーのアクセストークン>`、`invoice_can_access()`（CEO/HQ/master）を満たす必要あり。

| action | 用途 | 主なbody |
|---|---|---|
| `list_tenants` | 連携済み事業者一覧 | なし |
| `accounts` | 勘定科目一覧 | `{tenant_id}` |
| `suggest` | 過去仕訳からvendor_nameに一致する最有力候補1件 | `{vendor_name, tenant_id}` |
| `list_journals` | 過去仕訳をキーワード検索（複数件） | `{keyword, tenant_id}` |
| `search_hq_steps` | 本部タスクの工程を検索（紐付け用・未着手/進行中のみ） | `{keyword}` |
| `linked_invoices` | 工程ID配列→紐付いた請求書の状態を一括取得 | `{step_ids:[...]}` |
| `create` | メールに紐付く請求書の仕訳登録 | `{invoice_id, tenant_id, branches, transaction_date, remark, linked_hq_step_id, attach_files}` |
| `create_standalone` | メールに紐付かない請求書の仕訳登録（新規invoices行を作成） | `{tenant_id, linked_hq_step_id(必須), vendor_name, branches, transaction_date, remark, voucher_files}` |
