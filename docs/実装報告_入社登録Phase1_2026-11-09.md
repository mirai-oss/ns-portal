## 6. 未対応事項・リスク

- **スマレジ日給 API の実挙動は未確認**（仕様書は開発者サイトのログインが必要）。body は月給と同形 `{division:1, effectiveDate, wage}` と推定。初回の日給反映は使い捨てアカウントで確認し、400 ならスレッドに理由が出る（管理システム側は反映待ちで残り、二重登録なし）。
- 店舗別の時給・休日賃金は Slack モーダルの対象外（nippo の賃金カードで従来どおり）。
- 入社手続き中止（Phase 4）・停滞アラート（Phase 5）・交通費/税/Web明細/メールの自動化（Phase 2〜3）は未実装。該当項目は親メッセージに「今は手作業」と表示。
- Playwright 用のジョブ表（`ui_automation_jobs`）は Phase 3 で追加。Phase 1 の `onboarding_items` に attempts/next_retry_at/last_error を持たせ、ジョブの永続管理・再実行・二重防止（unique）に接続できる形にしてある（③の条件）。
- Slack 側の前提: Bot が #本部-人事 に参加済み（11/8 に送信実績あり）。`views.open`・`chat.update` は勤怠ボタンで実績あり。`number_input` 要素は Slack 標準（未使用だったので初回は実機で確認）。
- `onboarding_start` の本部タスク紐づけは related_user_id → 題名一致の順。同姓同名が同時期に入社した場合は題名一致で取り違える可能性があるため、nippo の `p_user_id` 渡し（公開後）が前提。
