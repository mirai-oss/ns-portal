# 調査: 広告費パネル（invoice_lines からの割り振り）を広告管理DBへの書き込みまで通す設計（担当C・2026-10-20）

設計書 v2 §14 A2 の追加項目。読み取り調査と設計案のみ。担当Aの管轄部分は“案”であり、担当Aとの合意が必要。

## ① 現状
- 請求書の承認画面で、広告宣伝費（媒体補助科目＝食べログ/ぐるなび/ホットペッパー/Retty）の行は、`plReflectInvoice_` が Edge `ad-cost-reflect`（action=confirm）を呼ぶ。
- `ad-cost-reflect` は ①媒体名を `tpl_media_alias` で正規化 ②`invoices.ad_cost_*` に確定内容を保存（`ad_cost_reflected_at` があれば重複拒否）③tori-dashboard GAS `writeAdCost` を呼び、広告管理DB（スプレッドシート「💾広告費DB」＋BQ `stg_ad_cost`）へ書く。
- 店舗への割り振りの元は、承認画面の行の店舗（`invoice-resolve-lines` が `invoice_lines` の店舗表記から確定。10/19に旧店名・部分一致の確定を改善、確定した店舗を `invoice_stores` にも反映）。食べログの試験では 18/18 行が正しい店舗に確定。
- 同じ請求書は PL へも `pl-fee-reflect` で（広告宣伝費/媒体）として反映される。→ 広告DBとPL（A区分）の**2系統**（設計書 A2）。

## ② 設計案（広告DBへの書き込みまで通す）
- 書き先（案）: 担当A管轄の広告管理DBの“内訳”を **Supabase 側の新表**（例 `ad_cost_entries`: year_month / store_id / media / plan(固定・予約従量・その他) / amount / source='請求書' / source_key / deleted_at）に置く。GASの 💾広告費DB は当面ミラー（または入力UIのみ）。担当A・レーンPが `kd_ad` 系に取り込む想定。
- 内訳の自動登録: `invoice_lines` の明細（食べログなら『PRプレミアム5（定額）』『ネット予約（従量ディナー/ランチ）』『レスラク（月額利用料）』）を **plan に分類**して媒体×店舗×plan で集計（分類は明細名のキーワード。分類表は `ad_plan_rules` として持つ）。
- 冪等キー: `inv:<請求書ID>:<media>:<store_id>:<plan>`。同じキーは upsert。
- 取り消し: 請求書削除・差し戻し・unconfirm で deleted_at。
- 実績との関係: 実績PL（pl_entries）への書き込みは別資料のとおり請求書→pl_entries 直接。広告DB内訳は“見込みの元”であり、実績PLには足さない（二重計上防止）。

## ③ 担当Aとの境界
- 担当C: 請求書の読み取り・店舗確定・明細→媒体×plan への分類・Supabase新表への書き込み（Edge）。
- 担当A: 広告管理DB（見込み・実消化・予約）の側の取り込み（kd_ad）、媒体手数料設定の正本化、PL側の突合（24%行の除外・A3）。
- 決めること: 新表のスキーマと所有（A or P）／plan分類の初期表／過去分（8〜10月）の一括登録の要否。

## ④ 追加で必要なもの / 注意
- 明細名→plan 分類は媒体ごとに違う（食べログ以外は未確認）。ぐるなび・ホットペッパー・Retty の実請求書で分類表を作る必要がある。
- `ad_cost_reflected_at`（請求書単位のフラグ）は1請求書=1媒体前提。複数媒体を含む請求書への対応を決める。
- 旧GAS `writeAdCost` との並走期間は二重にならないよう、切替フラグで一方だけ有効にする。
