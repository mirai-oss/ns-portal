## 3. DB設計案（ハブSupabase・接頭辞 `ck_`＝新規予約）

原本の主要エンティティをそのまま `ck_` 接頭辞で作る（日付入り新規SQLファイル・冪等）:

- `ck_devices` — 端末（device_key='mac-mini'等, name, hostname, os, last_seen_at, status）
- `ck_sessions` — Claude Code等のセッション（session_key, device_id, agent_type, **agent_name='担当A'〜'担当G'/'司令塔'**, repository, branch, current_task_id, status, progress_percent, started_at, last_heartbeat_at, current_file, blocker, git_head, changed_files_count, changed_files jsonb）
- `ck_tasks` — 開発タスク（連番→画面表示は`TK-<番号>`。title, description, priority, project, category, assignee_type(ai/human), **assignee_name(担当A〜G/中山)**, repository, branch, instruction_id, status, progress_percent, blocker, due_at, created_by, timestamps）
- `ck_instructions` — 指示書（task_id, title, markdown, target_agent, target_device, …）
- `ck_events` — 実行・変更履歴（session_id, task_id, device_id, event_type, message, metadata jsonb, created_at。`hq_task_activity`と同型＋索引）
- `ck_approvals` — 承認キュー（kind, title, detail, status=pending/approved/rejected, decided_by/at）
- `ck_comments` — コメント

状態値は原本どおり（タスク=backlog/ready/in_progress/review/waiting_human/blocked/done/cancelled、セッション=running/waiting/blocked/idle/stopped/stale/disconnected）。

**RLS**: 全テーブル `portal_is_master()` で読み書きともマスター限定。anonキーはHTMLに公開されているので、**画面側で隠すだけでは制御にならない＝RLSが本体**。マシンからの書き込み（heartbeat）はEdge Function経由（service roleでRLS通過）。

## 4. Heartbeat方式

- 各セッションは共通CLI `ai-cockpit`（bashスクリプト・ns-portal/tools/ に置く）で送信 → Edge Function **`cockpit-ingest`** が受けて `ck_devices`/`ck_sessions` をupsert・`ck_events` をinsert。
- 認証: `app_secrets` の `cockpit_ingest_token`。トークンは各PCの `~/.ns-cockpit/config` に置く（**リポジトリにはコミットしない**）。
- 送信間隔: フックから呼ばれても**20秒未満は間引く**（CLI側でthrottle）。
- stale判定は**画面側で計算**（last_heartbeat_atが90秒超→stale、10分超→disconnected）。サーバ側cronは最初は作らない（シンプル優先）。ローカルの状態ではなくSupabase上の値が正本。

## 5. Claude Code側の状態取得方式

2段構え:
1. **手動CLI（Phase 2）**: `ai-cockpit start|progress|blocked|done --task TK-xx --message "…"`。各レーンの指示書に「作業の節目で打つ」を追記。
2. **フック自動化（Phase 4）**: 各リポジトリの `.claude/settings.json` に SessionStart / PostToolUse(Edit・Write・Bash) / Stop フックを追加し `ai-cockpit hb` を自動発火。git情報（branch・HEAD・変更ファイル）はCLIが実行時に `git` から自動採取して同送。

## 6. Git競合検知方式

サーバ側では検知せず、**cockpit.html が ck_sessions を読んで表示時に計算**（実装が一番簡単で十分機能する）:
- 同じ repository+branch を複数端末が同時編集 → ⚠️
- changed_files（jsonb）が複数セッションで重なる → ⚠️
- branch=main で changed_files_count>0 → ⚠️
- 同じ current_task_id を複数セッションが実行 → ⚠️
- migration（supabase/*.sql）の同時変更 → ⚠️

## 10. リスク

1. **anonキーは公開情報** → 対策: RLSをマスター限定で必ず有効化（画面側の出し分けは飾り）。指示書に受け入れ条件として明記。
2. **トークンの扱い** → `~/.ns-cockpit/config` のみ・コミット禁止・`.gitignore` 追加。指示書・手順書にも「トークンを文書に書かない」を明記。
3. **正本の二重化**（WORKLOGとコックピットで「今」が食い違う） → 役割分担を固定: **コックピット=「今この瞬間」の正本／WORKLOG=「経緯・詳細」の正本**。コックピットのヘッダーからWORKLOGへ常設リンク。移行期は司令塔が両方を更新。
4. **フックの打ちすぎ**（毎ツール実行でPOST） → CLI側20秒throttle＋失敗時は黙って捨てる（開発作業を止めない）。
5. **GitHub Pages反映の1〜2分ラグ** → 画面の話だけ。データはSupabase直読みなのでリアルタイム性に影響なし。
6. **Edge Functionデプロイ事故** → `cockpit-*` はH専任（鉄則#4）。他レーンの関数には触らない。
7. **画面が「動いてる風」で実は止まっている** → stale/disconnected 表示（§4）とヘッダーの最終同期時刻で防ぐ。
