# 手順書: I-1 予約取込「当月＋翌月＋月初は前月」対応 — Mac miniでの実機確認・仕上げ

作成: 2026-08-30 ／ 担当D ／ 対象: `~/ns-daily-import`（Mac mini。ログイン情報・Chromeプロファイルがあるマシンで作業すること）

## 背景

ユーザー要望「予約の取り込みを当月分だけでなく翌月分も。月初は前月分も取り込んでほしい（当日予約・当日来店＝ウォークインの実績が、月をまたいでも予約帳に反映され続けるため）」に対応中。

MacBook側（ログイン情報を持たないマシン）で、**コードの構造部分（対象月をどう決めるか・どうループするか）はすでに実装・push済み**。残っているのは「食べログノート・ダイニー予約台帳それぞれの実サイトで、当月以外のCSVをどう出力するか」という、実機でログインしないと分からない部分だけ。これをMac miniで確認・実装してほしい。

## 前提として押さえておくこと

- 対象ファイルは2本: `tasks/tabelog-note-reservation.js`と`tasks/dinii-reservation.js`
- どちらも**当月分は今までどおり正常に動く**（今回の変更で壊していない）。翌月・前月分だけが「未実装としてスキップ」される安全な状態になっている（黙って誤動作せず、ログにはっきり「未実装スキップ」と出る）
- 対象月の決め方はもう実装済み・テスト済み（`lib/dates.js`の`targetReservationMonths()`）。**この部分は触らなくてよい**。今回やることは「その対象月を実際にサイトへ伝えてCSVを出す」部分の実装だけ

## 作業手順

### 手順0: 最新化

```bash
cd ~/ns-daily-import
git pull --rebase
```

`f6d5934`より新しい`ea750a5`・`42390e9`のコミット（今回の対象月ループ化）が入っていることを確認する。

### 手順1: 食べログノート側の実機調査

まずHEADLESS=0で1店舗だけ動かし、「分析」タブの画面を目視で確認する。

```bash
HEADLESS=0 node run.js tabelog-note-reservation
```

- `tasks/tabelog-note-reservation.js`の`gotoAnalysisTab()`（70行目）まで動いたら、分析タブの画面で以下を確認:
  1. 「当月の予約情報CSV出力」ボタンの近くに、「翌月の予約情報CSV出力」のような別ボタンが並んでいないか
  2. 無ければ、月を選ぶプルダウン・カレンダー・矢印のようなUIが画面のどこかに無いか（スクロールして探す）
  3. 見つかった場合、そのボタン/UIをクリックしてCSVがダウンロードできるか試す（ダウンロードされたCSVの中身が本当にその月のデータか、来店日列を見て確認する）

見つかったセレクタで、`downloadCsvForMonth()`（100行目）のNOT_IMPLEMENTED分岐を、`downloadCurrentMonthCsv()`と同じ「ボタン押下→`page.waitForEvent('download')`で待ち受け」の形に書き換える。

### 手順2: ダイニー予約台帳側の実機調査（食べログノートよりヒントが多い）

こちらは2026-08-28に別セッションが過去月バックフィルを調査した際、**日付ピッカーの仕組みがすでに実機確認済み**（`ns-daily-import/WORKLOG.md`のcommit`c0f61d4`「dinii-reservation バックフィル調査結果」参照）。分かっていること:

- 日付ピッカーはAnt Design RangePicker。2パネル連動・前月/次月ボタンあり
- 各日セルの`title`属性がISO形式`YYYY-MM-DD`（例: `.ant-picker-cell[title="2026-09-01"]`のようなセレクタで直接指定できる見込み）
- **既知の落とし穴**: 開始日をクリックすると、パネルの表示月が意図せず戻ることがある。終了日をクリックする前に、もう一度対象月へパネルを再ナビゲートする必要がある

これを踏まえてHEADLESS=0で確認する:

```bash
HEADLESS=0 node run.js dinii-reservation
```

- `downloadCsvForMonth()`（`tasks/dinii-reservation.js`132行目）のTODOコメントに沿って、`.ant-picker`を開いた状態で前月/次月ボタン（`.ant-picker-header-prev-btn`・`.ant-picker-header-next-btn`が典型的だが実機で確認すること）を対象月まで押し、`monthRangeDash(targetMonth)`（125行目）で作れる月初(`from`)・月末(`to`)の日付を、それぞれ`.ant-picker-cell[title="..."]`で指定してクリックする
- 開始日クリック後にパネルが戻る現象が実際に起きるか確認し、起きるなら終了日クリック前に対象月への再ナビゲートを挟む
- ダウンロードしたCSVの来店日列が対象月のものになっているか確認する

見つかった実装で、NOT_IMPLEMENTED分岐を置き換える。

### 手順3: 翌月・前月の実データでテスト

`TARGET_MONTH`環境変数で、翌月分・前月分を単独テストできる（`run()`内で`TARGET_MONTH`指定時はその月1本だけに絞る仕様のまま）。

```bash
# 翌月分だけテスト（今日が8月なら9月）
TARGET_MONTH=2026-09 HEADLESS=0 node run.js tabelog-note-reservation
TARGET_MONTH=2026-09 HEADLESS=0 node run.js dinii-reservation

# 月初のみ意味がある前月分のテスト（今日が9月1〜3日ならこれで前月=8月がテストできる。
# それ以外の日はTARGET_DATE相当の日付偽装の仕組みが無いため、月初になるまで待つか
# 手動でtargetReservationMonths()の呼び出し元を一時的に書き換えてテストする）
TARGET_MONTH=2026-08 HEADLESS=0 node run.js tabelog-note-reservation
```

### 手順4: `source_month`列の確認

Supabaseの`rsv_reservations`テーブルで、`source_month`列が実際にテストした対象月と一致しているか確認する（`washAndReplace()`が`sourceMonth`引数どおりに書き込んでいるはずだが、念のため）。

```bash
# .config/ns-portal/hub_service_role にあるサービスロールキーを使う想定
curl -s "https://uuvsxzhpxtghojoubjcc.supabase.co/rest/v1/rsv_reservations?select=source_month&limit=5&order=source_month.desc" \
  -H "apikey: $(cat ~/.config/ns-portal/hub_service_role)" \
  -H "Authorization: Bearer $(cat ~/.config/ns-portal/hub_service_role)"
```

## 注意点

- ログイン・店舗切替のセレクタ自体（`login()`・`switchStore()`）は今回変更していない。もし手順1・2の途中でこれらが動かない場合は、サイト側のUI変更の可能性があるので別問題として切り分けること
- どうしても月指定CSVの出し方が見つからない場合は、無理に実装せず「見つからなかった」とWORKLOGに記録して終えてよい（NOT_IMPLEMENTEDのままでも当月分の取込は正常に続くため、実害は無い）
- ダイニー側は現状「うお蔵 新横浜」1店舗のみが対象（`config.js`の`DINII_RESERVATION_ACCOUNTS`）。食べログノート側はテストしやすい店舗として「鳥一代 本店」（`config.js`の`TABELOG_NOTE_ACCOUNTS`先頭）を使うとよい
