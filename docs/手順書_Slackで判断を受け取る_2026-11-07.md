# 手順書：Claude からの「判断してください」を Slack のボタンで答える（2026-11-07）

> Claude（作業セッション）が「A か B か」「進めてよいか」を聞きたいとき、`#本部-開発システム` に **質問＋ボタン** が届きます。
> ボタンを押すと管理システム（ハブ）に記録され、Claude がそれを読んで作業を続けます。
> 本番に入れるには、下の「① 本番に入れる（1 回だけ・5 分）」が必要です。

## できあがりの姿

```
🤖 Claude（判断依頼）
❓ 判断をお願いします
   請求書の二重取込 3 件、どうしますか？
   [ 片方を削除 ]  [ 両方残す ]
   依頼 a1b2c3d4・期限 24 時間・ボタンを押すと管理システムに記録されます
```
押したあと、同じメッセージが **「✅ 中山 俊士 が「片方を削除」を選択しました（日時）」** に変わり、ボタンは消えます。

- 押せる人: **マスター（中山さんだけ）**。それ以外の人が押すと本人だけに「権限がありません」と出て、何も記録されない。
- 先に誰かが押したあとに別の人が押すと、本人だけに「○○さんが先に「…」を選んでいます」と出る（記録は上書きされない）。
- 24 時間（依頼ごとに変えられる）過ぎると「期限切れ」で押せない。

## ② ふだんの使い方（Claude 側）

Claude のセッションが次のように使います（ユーザーが打つ必要はありません）。

```bash
# 質問を送る（1 行目の request_id を控える）
python3 scripts/decision_ask.py "質問文" a=選択肢A b=選択肢B [c=見送り] [--hours 24] [--by claude:セッション名]
# 答えを読む（終了コード 0=答えあり / 2=まだ / 3=期限切れ・取消 / 4=無い）。待つのは呼び出し側（/loop など）
python3 scripts/decision_wait.py <request_id>
# 答え待ち一覧
python3 scripts/decision_wait.py --list
# 取り消す（Slack の本文も「取り消されました」に変わる）
python3 scripts/decision_ask.py --cancel <request_id>
```

- 選択肢は 2〜5 個。`key=表示名` の形（key は英小文字・数字・_、表示名は 75 字まで）。最初の選択肢が緑（primary）になる。
- 宛先は既定 `hq.dev_system`（`#本部-開発システム`）。`--channel` で `slack_channels` の他のキーに変えられる。
- 文章で答える（スレッド返信を拾う）のは Phase 2。今はボタンだけ。

## 仕組み（読まなくてよい）

- 表 `decision_requests`（ハブ）: 質問・選択肢・状態（pending → answered / expired / cancelled）・答えた人（`users.id`）・送った Slack メッセージ（`notification_deliveries.id`）。
- 送信は既存の `notify-slack`（変更なし）。ボタンの `action_id` は `decision.request.<key>`、`value` に request_id。
- 受け取りは `slack-interact`: 署名検証 → `user_slack` で社内ユーザーに解決 → RPC `decision_request_answer`（権限・状態・期限・選択肢の検査と更新はすべてここ。Slack から表を直接更新しない）→ `notify-slack update` で元メッセージ差し替え。
- 秘密はリポジトリに書かない。鍵は `~/.config/ns-portal/`（`supabase_pat`・`notify_slack_secret`）と Edge Function の secrets（`SLACK_SIGNING_SECRET`・`NOTIFY_SLACK_SECRET`）。
