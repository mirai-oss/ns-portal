# 実装指示書: 並行開発の担当分け（ワーカーA〜E）

作成: 2026-08-24 ／ 目的: 未実装の設計書を**複数のClaude Codeスレッド（別PC含む）で同時に進めても衝突・上書き・破壊が起きない**よう、担当・ファイル所有権・順番を固定する。

**使い方**: 各スレッドに「あなたは担当◯です。`ns-portal/docs/実装指示書_並行開発の担当分け_2026-08-24.md` を読み、担当◯のセクションだけを実行してください」と1行伝える。

---

## 0. 全員共通の鉄則（各担当セクションより優先）

1. **自分の担当ファイル以外は編集禁止**（下の所有権マトリクスが絶対。読むのは自由）。担当外の修正が必要になったら、実装せずWORKLOGに「◯◯担当への依頼」として書き残す
2. 作業前に必ず全リポジトリ`git fetch`→`git pull --rebase`（CLAUDE.mdのルールどおり）。**pushが弾かれたら必ずrebaseで取り込み、WORKLOG.mdの競合は「両方のエントリを残す」で解消**（他人の記録を消さない）
3. SupabaseのSQLは**日付入り新規ファイルの追加のみ**（既存SQL編集禁止）。テーブル・RPCは自分の接頭辞のみ（B=`sf_`、C=`invoice_`、D=`attendance`/`labor_`系）。共有テーブル（users/stores等）は列追加もWORKLOGで宣言してから
4. **Edge Functionは自分の担当分だけデプロイ**。他人の関数は`supabase functions deploy`しない
5. **GASのデプロイ権限は担当Aだけ**（ダッシュボードGAS・PL管理システムGASとも）。他の担当はGASを一切触らない（読み取りcurlは可）
6. ユーザー確認ゲート（本番SQL実行・GASデプロイ・メッセージ送信・課金・本番切替）は従来どおり都度確認
7. 作業の区切りごとにWORKLOG 4ステップ（push→追記→📍更新→再push）。📍は自分の担当の行だけ書き換え、他担当の行は触らない
8. テストは使い捨てデータで行い削除まで確認（実データを使わない・LINEやLarkの本番送信テストは範囲を絞る）

**参照**: `実装指示書_勤怠月またぎ再取込と新規要望4件_2026-08-24.md`タスク0／`実装指示書_BQ表示改善と社員給与按分_2026-08-24.md`タスク3

2. **D-2 社員給与の勤務日ベース按分**: BQに按分ビュー（従業員×店舗×月の労働時間シェア・打刻ゼロ月は暦日フォールバック）→現行手入力値との**比較レポートを週次出力**→ユーザー承認まで（**切替はやらない**。承認後の表示切替は担当Aへ引き継ぎ）
3. **D-3 朝の見張り番**: 毎朝「昨日分の売上・勤怠がBQに入っているか」をチェックし、無い時だけLark警告。**tori-dashboardに新規ワークフローファイル1個を追加するだけ**（既存ファイル・GAS変更禁止。既存のreportDataBQ/bq-diagパターンを流用）
4. **D-4 Anthropic API費用の自動レポート（2026-08-24追加・ユーザー要望）**:
   - データ取得: Anthropicの公式**Usage & Cost Admin API**（`GET https://api.anthropic.com/v1/organizations/cost_report?starting_at=...&ending_at=...`、認証は`x-api-key: <Admin APIキー>`。金額はUSDセント単位の文字列・日次粒度。ページングは`has_more`/`next_page`）
   - 毎日1回GitHub Actionsで取得→ハブSupabaseの新テーブル`api_cost_daily`（date・amount_cents・description等。D名前空間に`api_`を追加）へupsert
   - **Lark配信**: ①毎月1日に「先月のAPI利用料合計（円換算の目安つき）」②毎週月曜に「今月の累計」③しきい値超過アラート（金額はユーザーに確認。例: 月$100）。配信は見張り番（D-3）と同じLark Webhookを使う
   - **ユーザー作業（依頼して待つ）**: Anthropic ConsoleでAdmin APIキー（`sk-ant-admin01-...`で始まる・通常のAPIキーとは別物）を発行→GitHub Secretへ登録。**注意**: Admin APIは個人アカウントでは使えない（Console→Settings→Organizationで組織設定が必要）。キー発行時はスコープを利用状況の読み取りに限定
   - 表示側（ポータルのウィジェット）はF-1.5（担当F）が担当。Dはデータを`api_cost_daily`に置くところまで
