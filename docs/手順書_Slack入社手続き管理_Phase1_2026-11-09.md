# 手順書: Slack で入社手続きを管理する（Phase 1・賃金まで）

作成 2026-11-09。だれが読んでも同じ操作ができるように、1 動作ずつ書いています。

## 0. これは何？

- 新しい人が **入社フォームを送る** と、Slack の **#本部-人事**（人事チャンネル）に「🧑‍💼 入社登録：○○さん」という **親メッセージ** が 1 つ届きます。
- その親メッセージの **スレッド（返信欄）** に、進み具合・結果・エラーが自動で届きます。
- 親メッセージの **「💴 賃金を設定」ボタン** を押すと、小さな入力画面（モーダル）が出て、時給・日給・月給をその場で登録できます。登録した値は **スマレジ・タイムカードに自動で反映** され、反映後にスマレジから読み直して **一致を確認** します。
- 本部タスク「入社登録（○○さん）」の工程②「時給」のチェックは、反映が成功すると **自動で ✓** が付きます。人が付け直す必要はありません。

用語:
- **親メッセージ** … 1 人につき 1 つの、まとめのメッセージ。
- **スレッド** … 親メッセージの下の返信欄。履歴がここに積み上がります。
- **モーダル** … ボタンを押すと出る小さな入力画面。

### 1-3. nippo を公開する（日給の選択肢・本部タスクの重複防止）

nippo の変更は、私（Claude）が `git push` してよいと言っていただいてから公開します。SQL より先に公開しても壊れないように作ってあります（SQL が入る前は従来どおりの呼び方に自動で戻ります）。

### 1-4. 切替スイッチを ON にする（ここから通知が変わります）

`supabase/2026-11-09_onboarding_switch.sql` を開き、**ステップ A** の行だけ先頭の `-- ` を消して保存し、次を実行します。
```bash
python3 scripts/apply_sql.py supabase/2026-11-09_onboarding_switch.sql
```
- ステップ A の間は、人事チャンネルに **新しい親メッセージ** と **従来の「賃金登録をお願いします」** の **2 通** が届きます（動作確認期間）。
- 新しい方で問題なく賃金が入れられるのを 1〜2 人分確認したら、**ステップ B**（従来文面を止める）→ **ステップ C**（Chatwork の入社通知を止める）→ **ステップ D**（LINE の賃金返信の残りを閉じる）の順に、同じやり方で 1 行ずつ実行します。
- **戻したいとき**: 同じファイルの「戻し方」の行を実行すれば、通知は元に戻ります。

## 2. ふだんの使い方（本部の人）

### 2-1. 入社フォームが届いたとき

1. #本部-人事 に「🧑‍💼 入社登録：○○さん」が届きます。区分・所属・入社日・スマレジの登録状況・10 項目の状態が見えます。
2. スレッドに「📝 入社フォーム 送信済み」「✅ スマレジ従業員 作成済み（ID …）」などの 1 通目が届きます。

### 2-2. 賃金を入れる

1. 親メッセージの **「💴 賃金を設定」** を押します（押せるのは 本部・社長・マスター だけ。ほかの人が押すと「本部・社長・マスターのみです」と本人にだけ表示されます）。
2. 出てきた画面で次を選びます。
   - **スマレジの契約（法人）** … 2 つの法人に登録されている人だけ出ます。
   - **給与形態** … 時給 / 日給 / 月給。
   - **適用開始日** … 最初から **入社日** が入っています。変えるときはカレンダーで選びます。月給は 1 日にしてください（違う日だと赤字で教えてくれます）。
   - **賃金（円）** … 半角の数字だけ。例 `1200`。
3. **「登録してスマレジに反映」** を押します。画面が閉じれば受付完了です。
4. 数秒〜10 秒ほどで、スレッドに結果が届きます。
   - **成功**: `✅ 賃金をスマレジに反映しました … 🔍 反映後にスマレジから読み直して一致を確認しました`。親メッセージの「賃金」も ✅ になり、本部タスクの「時給」にも ✓ が付きます。
   - **失敗**: `⚠️ 賃金のスマレジ反映に失敗しました …理由…` と、**「🔁 もう一度反映」「💴 賃金を直す」** のボタンが届きます。理由を読んで、直してからもう一度押してください。管理システム側には保存済み（反映待ち）のまま残っているので、二重に登録されることはありません。
5. **店舗別の時給や休日賃金** を入れたいときは、親メッセージの「従業員ページ」ボタンから nippo の「💴 賃金設定」で入れてください（Slack の画面は基本の 1 行だけです）。

### 2-3. それ以外の項目（交通費・源泉所得税・Web 給与明細・メール）

- Phase 1 では **今までどおり本部タスクで手作業** です。本部タスクで ✓ を付けると、親メッセージの項目も自動で ✅ になります（「🔄 表示を更新」を押すと最新になります）。
- ✓ を外すと、項目も「未」に戻ります。

### 2-4. 表示が古いと感じたら

- 親メッセージの **「🔄 表示を更新」** を押します。

## 3. うまくいかないとき

| 症状 | 見るところ・直し方 |
|---|---|
| ボタンを押しても何も起きない | 自分の Slack が管理システムに紐づいているか（紐づいていないと「本部に連絡してください」と出ます）。本部・社長・マスターか。 |
| 「スマレジにまだ登録されていない」と出る | nippo の従業員ページで先にスマレジ登録（従業員作成）をしてください。終わったら「🔄 表示を更新」。 |
| 反映に失敗（400 重複など） | スレッドの理由を読む → 「💴 賃金を直す」で適用開始日や金額を直す → 「🔁 もう一度反映」。 |
| 親メッセージが届かない | `app_settings.onboarding_slack` の enabled が true か／Bot が #本部-人事 に参加しているか（11/8 に送れているので参加済み）。 |
| 状態を SQL で見たい | `select * from onboarding_workflow_v order by created_at desc limit 20;`／履歴は `onboarding_events`。 |

## 4. 仕組み（技術メモ・短く）

- 表: `onboarding_workflows`（1 人 1 行）→ `onboarding_items`（10 項目）→ `onboarding_events`（誰が・いつ・何を・前後の値）。
- 入口 RPC: `onboarding_start`（行を作る・冪等）、`onboarding_set_item`（状態を変える唯一の入口。本部タスクの ✓ と連動）、`hr_save_wage`（賃金の保存。日給 OK・Slack からは p_actor）。
- EF: `onboarding-notify`（親メッセージ・スレッド・賃金の反映と照合）、`slack-interact`（ボタン・モーダルの受付だけ）、`hr-wage-notify`（入社フォーム完了→スイッチを見て新旧を呼ぶ）、`smaregi-sync`（wage_push に日給・wage_pull を内部から呼べる）。
- Slack 送信はすべて `notify-slack` 経由（台帳 `notification_deliveries`）。DB 更新はすべて RPC 経由（Slack から直接は書かない）。
