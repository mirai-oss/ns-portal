作成 2026-11-12（ファイル名の日付は 2026-11-21）。**下書きだけ。本番の SQL 適用・関数の入れ替え・設定の変更・Slack への投稿はしていない。**
土台: リポジトリの HEAD（`onboarding-notify`・`slack-interact`・`onboarding-blocks.ts` は `7ff70e2` の中身。賃金の承認・交通費の 1 回承認を含む）。
関連: `docs/設計書_Slack通知の共通フォーマット_2026-11-11.md` §16・§17／`docs/計画書_Slack通知の統一_2026-11-11.md` §3／お手本 `_shared/attendance-alert-notice.ts`。

## 1. 親メッセージの決まり（1 行だけ）

| 状態 | 親メッセージ | ボタン |
|---|---|---|
| 進行中 | `🟢 入社登録｜氏名｜入社 11/20` | ［詳細を確認］ |
| 進行中（入社日が無い） | `🟢 入社登録｜氏名` | ［詳細を確認］ |
| 止まっている（人の対応が要る） | `🛑 入社登録｜氏名｜要対応` | ［詳細を確認］ |
| 完了 | `✅ 入社登録｜氏名｜完了` | なし |
| 中止 | `⛔ 入社登録｜氏名｜中止` | なし |

- 区分・所属・項目の一覧・操作ボタン・金額は、親には出さない。
- 「要対応」になるのは、項目が「失敗」か「手動対応が必要」（社長の承認待ち・却下を含む）のとき。自動のやり直し待ち・処理中は「要対応」にしない。
- ［詳細を確認］は、スレッドの先頭（状況カード）を開くリンク。リンクが取れなかったときはボタンなし（Slack の「○件の返信」から開ける）。
- 状態が変わるたびに、同じ親を書き換える（親は 1 人に 1 つ。増やさない）。

## 2. 状況カード（スレッドの 1 通目。1 件だけ・変化のたびに書き換える）

```
【入社登録】
氏名：（氏名）（アルバイト）
所属：（店舗名）
入社日：2026/11/20
スマレジ：（契約名）／従業員ID 000
状況：🟢 進行中（5/10 完了）　▶ 次: 源泉所得税の設定

【登録状況】
✅ 入社フォーム：完了
✅ スマレジ従業員の作成：完了
✅ 賃金（時給・日給・月給）：賃金設定済み（スマレジ照合済み）
✅ 交通費の経路確認：交通費確認済み
⚠️ 交通費の設定：交通費設定待ち（失敗の理由）
⬜ 源泉所得税の設定：未
…（10 項目）

【入社後の提出】（入社登録の完了とは別）
⬜ 年末調整 2026 年度：必須・社内期限 11/30・未提出
📝 扶養家族：必須・社内期限 11/23・提出済み（本部の承認待ち）

［🚌 交通費を設定］［🧾 源泉所得税］            ← いま必要な設定だけ
［📨 本人へ連絡］［🔎 スマレジ照合］［🔄 表示を更新］［⛔ 中止］
従業員ページ・本部タスク（リンク）　ワークフロー番号・更新時刻
```

- 金額は出さない（賃金・交通費は「設定待ち／設定済み」の言葉だけ。金額を出す設定になっていても、このカードには出ない）。
- メール・税の区分・扶養の人数と続柄も出さない。
- 失敗の理由は出す。ただし理由の文に金額らしいものが混ざっていたら「理由は管理システムで確認」に置き換える（出口の金額検査で送信が止まらないようにするため）。
- ボタンは「いま押せるもの」だけ。
  - 賃金: まだ済んでいないとき。社長の承認待ち・反映中は出さない（却下されたら出す）。
  - 交通費の設定: 経路と片道額の承認が済んだあとで、設定がまだのとき。設定済みのあとは「その他」の行に［交通費を入れ直す］。
  - 源泉所得税: まだ済んでいないとき。
  - **承認のボタンはカードに無い**（承認は、申請があったときのスレッドの返信に付く。今までと同じ）。
  - **完了・中止のあとは操作ボタンなし**（リンクと一覧だけ）。
- ボタンの名前（action_id）と value（`workflow_id`・`notification_id`＝親の台帳の番号）は今までと同じ。`slack-interact` は変更なし。

## 3. スレッドに足すもの・足さないもの（新しい形のときだけ。今までの形は全部今までどおり）

決まり: 足すのは **人の対応が要るもの** と **人が行った操作の記録（だれが・いつ）** だけ。自動処理の成功・途中経過は、状況カードの書き換えだけ。

| op | 場面 | 今まで | 新しい形 |

| refresh | 表示の更新 | 投稿なし | 投稿なし（親とカードを書き換え） |
| thread | slack-interact からの知らせ（保存の失敗・再実行の記録など） | 投稿 | **残す**（失敗か、人の操作の記録） |
| wage_sync | 反映に失敗／適用開始日が変わった（確認待ち）／一部未反映 | 投稿（ボタンつき） | **残す** |
| wage_sync | 反映できた（照合一致） | 投稿 | 人が操作したとき＝**1 行の記録**（金額なし）／自動の続き＝**カードだけ** |
| wage_sync | 反映できたが照合できない・一致しない | 成功の投稿に注記 | **残す**（確認のお願い・金額なし） |

## 4. 切り替えと、進行中の入社登録の扱い

- 切り替えは設定 `app_settings.onboarding_slack.format`。**無い・`"v1"`＝今までと同じ。`"v2"`＝これから親メッセージを作る入社登録だけ新しい形。**
- どちらの形で作ったかは、入社登録ごとに控える（`onboarding_workflows.slack_notice_format`。`null`＝今までの形）。**作ったときの形のまま最後まで動く。**途中で設定を変えても、進行中の入社登録の形は変わらない。
- 列が無い（SQL をまだ適用していない）ときは、設定が `"v2"` でも必ず今までの形で動く。関数と SQL の順番を間違えても壊れない。
- テスト用の入社登録 1 件だけ新しい形で試せる: `op=open`（または `refresh`）に `format:"v2"` を付ける（親メッセージをこれから作る入社登録だけに効く）。
- 分けている場所（`onboarding-notify/index.ts`）: `ensureParent`（作るとき）・`refreshParent`（書き換え）・`thread`（言い換え）と、各 op の「足すかどうか」。今までの形の行は、今までのコードをそのまま通る。
- 追加する列（`2026-11-21_onboarding_notice_v2.sql`）: `slack_notice_format`・`slack_card_notification_id`（状況カードの台帳の番号）・`slack_parent_permalink`（［詳細を確認］のリンク）。既存の行は変えない。

入れる順番（案。どれも承認をもらってから）

1. SQL を適用する（列を足すだけ。通知は変わらない）。
2. `onboarding-notify` を入れ替える（設定が無いので、通知は今までと同じ）。
3. テスト用の入社登録 1 件を `format:"v2"` で作り、通しで確かめる（賃金・交通費の実書き込みはしない・既存のテスト手順）。
4. 設定に `"format":"v2"` を入れる（これから作る入社登録から新しい形）。

## 8. 決めてほしいこと・迷ったこと

1. 「要対応」のときの親に、入社日も残すか（いまは見本どおり `🛑 入社登録｜氏名｜要対応`。残すなら `…｜入社 11/20｜要対応`）。
2. 完了・中止のあとの親から［詳細を確認］を外してよいか（勤怠確認と同じにした。完了のあとも年末調整・扶養の提出はスレッドに届く）。
3. 人が操作したあとの「1 行の記録」を残す形でよいか（賃金・交通費・源泉・スマレジ照合）。もっと減らすなら、記録をカードの中の「最近の操作」にまとめる方法がある。
4. 設定済みの交通費の［入れ直す］を「その他」に残した（入れ直せる画面が Slack にしか無いため）。賃金の入れ直しは従業員ページから。
5. 新しい形の入社登録では、設定に関係なく金額を出さない表示にした（「新しい文面でも金額を出さない」を確実にするため）。
6. 年末調整・扶養の提出と比較の投稿は、今までの文面のまま（配偶者の有無・勤労学生・続柄・人数が入っている）。税まわりの内容をここからも外すかは別途。
7. 自動再試行の待ち（retry_wait）は「要対応」にしなかった（今までの親では「止まっています」に数えていた）。
8. 初回出勤日: 入社フォームにまだ項目が無いので、日付は入社日（`hire_date`）を使った。項目が足されたら、ここを差し替える。
9. まだ入れていないもの: 同じ失敗を繰り返さないしくみ／停滞のお知らせのメンション／スマレジ事業所の作成結果を入社のスレッドに入れること／完了・中止のあとに古い返信のボタンを消すこと／共通の控え `notice_cases` への記録（今回は入社登録の行に控えた）。
